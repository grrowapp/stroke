## Original Goal
肥大化した OpenSpec change create-module-markdown（残37タスク／全74）を、依存関係の整った複数の spec へ分解する。feature としての切り口が大きすぎて着手判断ができない状態を解消し、どこから並行して進められるかを示す。

## Completed

## Learnings

### Triage - 分解の決定と根拠

- **軸は関心別4分割**（承認済みブリーフのとおり）。① 位置の口の公開 / ② 検知の整備 / ③ 正規化と座標の決め / ④ 資料
- **① が唯一の Wave 0。** 根拠は tasks.md に項目が無い穴 — `spec.md` の Requirement が「外から引ける形で公開しなければならない（SHALL）」と定めるのに、`MarkdownView.vue` が口を出していない（grep で確認）。`createPreviewPositionPort`（`position/preview.ts:366`）の呼び出し元は単体テスト3本のみ。`design.md:200` が同じ穴を明記している
- **change-id は動詞始まりの5語（ADR-0015）に従う**。① `add`（モジュールの口が1つ増える）/ ② `add`（検知を足す。利用者のできることは増えないが、5語のうち他に当てはまるものが無い）/ ③ `fix`（tasks.md 自身が「潜在の不具合」と書いている）/ ④ `create`（`mdc-observations.md` は新規）
- **tasks.md の未割り当て2件を単位へ配った。** 5.1（記帳漏れ。実装は `MarkdownView.vue:118` で済んでいる）→ ①。3.7（テスト2本の移設）→ ④。これで親自身に開いた作業が無くなり、親の archive 条件が「子が全部終わる」だけになる

### Interface contracts

- **`PositionPort`**（`modules/markdown/runtime/position/types.ts`）— `toSourceRange(Range): SourceRange | null` / `toDomRange(SourceRange): Range | null`。① が形を確定、② が検知、`adr0017-sub-create-module-annotation` が唯一の実利用者
- **口へ渡す生テキストの基準** — ここが ① と ③ の接点。① が「正規化後（CRLF → LF、front matter 除去後）を受け取る」と**明記**することで、③ の決め（誰が正規化するか）が ① の型を動かさなくなる。これを入れないと ③ が ① をやり直すことになる
- `SOURCE_START_ATTR` / `SOURCE_END_ATTR`（`position/source-span.ts`）と `SOURCE_SHOWN_KEY`（`render/source-shown.ts`）は既定。この epic では変えない
- **注釈のオフセットの保存座標**は ③ が決める。本家へ送られて保存されるため、正規化後で保存すると生ファイルとずれた値が残る

### Risks

- **R1** 親を残すため 1〜5章が子の完了まで archive されず開いたまま（承認済みのトレードオフ）
- **R2** ② が `@nuxt/icon` の 404 という環境整備に引きずられる（承認済みのトレードオフ）。6.14.2 を二択にして着手時に選ぶ
- **R3（triage で発見）** 3.7 が既存の委譲先と重複。ADR-0017 は `adr0017-sub-update-docs-structure` の触るファイルに `test/app/components/workspace/markdown-*.test.ts` を挙げている。④ が引き取るなら、あちらの行を落とす必要がある
- **R4** ③ の 6.11.1 は「本家に保存された注釈を誰が読むか」の調査結果待ち。決め手が出ないと止まる
- **R5** ② の 6.10 が塞ぐ層は `@nuxtjs/mdc@0.23.1` が最新で上げ先が無く、実地で測れない。6.6.1 と同じくパーサを直接変異させて測る
- **R6** ① が `MarkdownView.vue` を触る。`<MDC>` のスロットだけを差し替える形から外れるとアプリ全体のアイコンが消える（実測。本文には症状が出ない）。① では解析の段に触らない
