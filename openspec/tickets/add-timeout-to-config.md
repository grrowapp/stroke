# add-timeout-to-config

`claude -p` の子プロセスタイムアウトがコードのハードコード定数で、`claude.maxRetries` と置き場が揃っていない。同じ式を作る2つの値が、片方は承認の要る設定、片方は無手続きの定数になっている。

## 事実

`server/utils/stroke/claude.ts:18`:

```
export const CLAUDE_TIMEOUT_MS = 600000
```

`nuxt.config.ts:287`（`runtimeConfig.claude`）:

```
maxRetries: 2,
```

`docs/specs/core/settings-reference.md:84` は総待ち時間を1つの式で定義している。

```
総待ち時間 = (maxRetries + 1) × タイムアウト
```

同 `:86`:

```
タイムアウトは10分（設定ではない。server/utils/stroke/claude.ts）なので、
既定の 2 では最大30分で error に達する。
```

置き場と変更手続きの対応:

| 因子 | 置き場 | 変更手続き |
| --- | --- | --- |
| `maxRetries` | `nuxt.config.ts` の `runtimeConfig` | change 起票 → ユーザー承認 → 資料編集 → コード追随（ADR-0004） |
| タイムアウト | `claude.ts` のハードコード定数 | 定数を書き換えるだけ |

## 害

- **同じ式の因子が別の手続きに属する。** 総待ち時間を変えるのに、片方は承認が要り、片方は要らない
- **設定でないと宣言した値に、設定の説明が依存している。** `settings-reference.md` は「設定ではない」と書いた上で、その値を使って `maxRetries` の既定を説明している
- 運用中に総待ち時間を調整したいとき、`maxRetries` しか動かせない

## 判断の根拠が記録されていない

`settings-reference.md:140` の「設定ではないもの」に、タイムアウトが載っている。

```
| 子プロセスのタイムアウトと打ち切りシグナル | server/utils/stroke/claude.ts |
```

この節の説明は「外から変えられないようにしているもの」の一文だけで、**なぜ各項目がそこに入るのかの基準が書かれていない。** 同じ表には、置き場の外へ出られる形を防ぐもの（プロジェクト名として許す文字、対象の id の形）と、運用上の閾値（巡回の間隔、タイムアウト）が区別なく並んでいる。

したがって「タイムアウトは設定にしない」という判断について、**この資料にも ADR にも根拠は残っていない。**

`claude.ts:13` のコメントが残しているのは値の実測経緯だけで、なぜ設定にしないかは書かれていない。

```
**10分。** 180秒では初回が必ず時間切れになった（実測 2026-08-25）。
```

## この change を扱うときの前提

**ADR-0003 を判断の根拠に使わない。** 同 ADR は 0004 に取って代わられており、冒頭に「判断の根拠に使わない」と明記されている。設定と設定でないものの線引きについて、ADR-0003 に書かれた内容を現行の基準として引かないこと。

**ADR-0004 からは是非が導けない。** 同 ADR は手続きだけを定める。「この ADR は資料の**扱い**を定めるものであり、資料に何を載せるかの構成は資料自身が持つ」と明記されている。

**判断は資料の内部矛盾から行う。** `settings-reference.md` が同じ資料の中で、タイムアウトを「設定ではないもの」に載せながら（`:148`）、設定の説明にその値を使っている（`:84` の式、`:86` の「既定の 2 では最大30分」）。既存の判断に引っ張られず、この矛盾をどう解くかを一次の論点にすること。

## 経緯

2つの記述は別々のコミットで入っている。どちらも「タイムアウトを設定にするか」を主題にした変更ではなく、判断だけが本文に書き込まれた。

```
ccfb65b  feat: ポータルとストロークの入口と出口を繋ぐ
         → claude.ts に「設定ではない」を記述
         → settings-reference.md の「設定ではないもの」の表にタイムアウトの行を追加

494c156  chore: base2 の作業中の変更を統合ブランチへ取り込む
         → settings-reference.md に「タイムアウトは10分（設定ではない）」を記述
```

ADR-0004 は `settings-reference.md` の編集に change の起票とユーザー承認を要求している。上の2件はいずれも feat / chore のコミットで、その手続きを経ていない。

## 方針の候補

1. タイムアウトを `claude.timeoutMs` として `runtimeConfig` に昇格させ、`maxRetries` と同じ場所に揃える
2. `maxRetries` も定数に降格させ、両方をコード側に置く

`settings-reference.md` の編集を伴うため、ADR-0004 によりユーザー承認が要る。
