# fix-overview-file-import

概要入力画面のファイル読み込みが、**同じファイルを選び直したときに反映されない**。読み込んだファイル名も画面に出ないため、反映されたかどうかを確かめる手段が無い。

対象は `app/components/stroke/OverviewForm.vue`。機能そのものは change `add-overview-file-import`（archive 済み、2026-08-18）で入った。

## 事実

実測 2026-08-30。pre6 の `yarn dev`（3399）で `/strokes` を開き、`.md` / `.txt` / `.json` を順に選んで挙動を見た。

**動いているもの。**

```
.md を選ぶ              → 概要欄が中身で置き換わる          ✅
.json を選ぶ            → 「.txt または .md のファイルのみ読み込めます。」が出て
                          概要欄は変わらない                 ✅
.json の直後に .md      → 概要欄が中身で置き換わる          ✅
```

**動いていないもの。**

```
.md を選ぶ → 概要欄を手で書き換える → もう一度 同じ .md を選ぶ
  期待  概要欄がファイルの中身に戻る
  実際  「手で書き換えた内容」のまま。何も起きない
```

`watch(selectedFile, onFileChange)` が発火していない。同じファイルを選んでも `<input type="file">` の値が変わらず、`change` が飛ばないためである。**間に別のファイルを挟めば動く**ので、連続して同じファイルを選んだときだけ落ちる。

**読み込んだファイル名がどこにも出ない。**

選択後の `UFileUpload` は汎用のファイルアイコンと ✕ ボタンだけを出し、ファイル名を表示しない。`label` と `description` に渡している文言も、選択後は preview に置き換わって消える。**何を読み込んだのかが画面から分からない。**

## なぜ効くか

ファイルを直しながら概要を詰める使い方が通らない。エディタでファイルを書き換えて選び直しても画面が変わらず、ユーザーからは「読み込みが壊れている」ようにしか見えない。間に別のファイルを挟むという回避策は、気づけるものではない。

## 求めるもの

- **同じファイルを選び直しても読み込み直す。** 読み終えた後に入力の値を空に戻すのが定石。`UFileUpload` の `reset` が使えるかを先に確かめる（`@nuxt/ui` 4.11.0 の `FileUpload.vue` が `reset` を `toRefs` で受けている）
- **読み込んだファイル名を画面に出す。** 反映されたことと、何が反映されたかが分かるようにする
- 拒否時のエラー文言は今のままでよい。実測で出ている

## 前提

- 画面の場所は `/strokes` である。`/` は上層の通知画面で、概要入力欄は無い（`relocate-stroke-routes` 以降）
- ブラウザ内で完結する処理で、サーバ API の契約には関わらない（`add-overview-file-import` の proposal）
- `.txt` / `.md` 以外を拒否する判定は拡張子で行っている。この ticket では変えない
