# separate-composable-responsibilities

app/composables/ の責務分離リファクタ。仕様書 `file-composables`（spec-workflow、2026-08-24 承認）の**条件付き承認の条件**として起票。「責務分離が全くできていない」が条件の内容。

症状（実測 2026-08-28）:
- `useProposalReview`（417行・return 39プロパティ）が画面2の表示・注釈編集・差し戻し・承認・問い返しを全部1本で持つ。39 のうち13がモーダルの状態
- `Modals.vue` が useProposalReview の戻り値を丸ごと受ける（他の部品と結合の仕方が違う）
- HTTP エラー解体が `useProposalReview`（27-60行）と `useAgentQuestion`（8-27行）で**完全に一致**（`interface HttpError` + `statusOf` + `messageOf`）。`pages/strokes/[sessionId]/index.vue:14` にも `statusOf` の3つ目のコピーがある
- `reasonOf` は `useProposalReview`（409 の `data.data.reason` を取る）と `useProjectApi`（`statusMessage` を画面文言へ写す）で**同名だが別物**。名前で括ると壊れる
- 色定数を `CommentModal.vue` が composable から逆向き import（色は CSS へ寄せる方向が別途ある）

切り口の設計は本 change の design で決める。
