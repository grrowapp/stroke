# adr0016-sub-add-timeout-to-config

`claude -p` のタイムアウトを設定へ出し、**リトライごとに伸ばせる**ようにする。いまは定数で固定されており、同じ式を作る `maxRetries` と置き場も手続きも揃っていない。

触るファイル:
- 更新 `server/utils/stroke/claude.ts`（`CLAUDE_TIMEOUT_MS` の廃止。渡された値で打ち切る）
- 更新 `server/utils/stroke/ai.ts`（リトライ回数から今回の長さを決めて渡す）
- 更新 `nuxt.config.ts`（`runtimeConfig.claude` へ2件追加）
- 更新 `docs/specs/core/settings-reference.md`（式の改訂・「設定ではないもの」の表から削除・新設定の記述。**ADR-0004 によりユーザー承認が要る**）

## 事実

置き場と手続きが割れている。

| 因子 | 置き場 | 変更手続き |
| --- | --- | --- |
| `maxRetries` | `nuxt.config.ts` の `runtimeConfig` | change 起票 → ユーザー承認 → 資料編集 → コード追随（ADR-0004） |
| タイムアウト | `claude.ts:21` のハードコード定数 | 定数を書き換えるだけ |

`settings-reference.md` は総待ち時間を1つの式で定義している（`:84`）。

```
総待ち時間 = (maxRetries + 1) × タイムアウト
```

**同じ式の因子が別の手続きに属している。** 総待ち時間を変えるのに、片方は承認が要り、片方は要らない。

さらに同じ資料が二枚舌になっている。タイムアウトを「設定ではないもの」の表（`:149`）に載せながら、設定の説明にその値を使っている（`:86`「既定の `2` では最大30分」）。

## なぜ設定にするか

**この値は運用の実測で調整されてきた。**

- 180 秒では初回が必ず時間切れになり10分へ延ばした（実測 2026-08-25）。当時は claude がスキルをロードし `!` フェンスで curl を往復させていた
- 操作が MCP ツールへ移って所要が減ったので3分へ戻した（実測 2026-08-28: 8回の呼び出しで 28.5〜64.7 秒、turns は 4〜15）

調整のたびに定数を書き換えており、その判断はどこにも記録されない。設定の性質そのものである。

## なぜ刻みが要るか

**固定のタイムアウトは初回とリトライで要る長さの違いを解けない。** 短くすれば重い初回が落ち、長くすれば失敗の検知が遅れる。上の「180秒 → 10分 → 3分」の往復は、1つの値で両方を賄おうとして起きている。

初回は短く保って早く見切り、起こし直すたびに伸ばせば、両方が立つ。

## 求めるもの

**設定を2件増やす。**

| 設定 | 意味 |
|---|---|
| `claude.timeoutMs` | 打ち切るまでの時間。1つのターンの `retries` が 0 のときの値 |
| `claude.timeoutStepMs` | 同じターンでリトライを重ねる間、`retries` 1つにつきタイムアウトへ足す刻み |

**伸びるのは1つのターンの中だけである。**

```
今回のタイムアウト = timeoutMs + timeoutStepMs × retries
```

`retries` は `state.json` が持つ「そのターンでこれまでに起こし直した回数」で、`maxRetries` の上限に達すればそこで終わる。**次のターンでは `retries` が 0 に戻り、タイムアウトも `timeoutMs` へ巻き戻る。** 上限に達して `error` で終わったターンの後でも同じである。ターンをまたいで積み上がらない。

- タイムアウトを `runtimeConfig.claude.timeoutMs` として `maxRetries` と同じ場所に置く。`CLAUDE_TIMEOUT_MS` の定数は廃す
- 刻みを `runtimeConfig.claude.timeoutStepMs` として持つ。`0` を入れれば現在と同じ固定の振る舞いになる
- `settings-reference.md` の式を刻みを含む形へ改め、「設定ではないもの」の表からタイムアウトの行を落とす

刻みを加算にするか倍率にするかは design で確定する。加算を軸に置くのは、`0` が「伸ばさない」を素直に表せて現在の振る舞いと地続きになるためである。

## 前提

- **ADR-0003 を判断の根拠に使わない。** 同 ADR は 0004 に取って代わられており、冒頭に「判断の根拠に使わない」と明記されている
- **ADR-0004 からは是非が導けない。** 同 ADR は手続きだけを定める。「この ADR は資料の**扱い**を定めるものであり、資料に何を載せるかの構成は資料自身が持つ」
- **判断は資料の内部矛盾から行う。** 上記の二枚舌をどう解くかが一次の論点である
- 打ち切りシグナル（`SIGKILL`）は設定にしない。`maxRetries` の意味も変えない
- 現在の2つの記述（`claude.ts` の「設定ではない」、`settings-reference.md:86`）は `ccfb65b` / `494c156` の feat / chore コミットで入っており、**ADR-0004 の手続きを経ていない**。この change で手続きに載せ直す
