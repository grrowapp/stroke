# adr0017-sub-add-detection-assumptions

`create-module-markdown` の実装で前提が7件崩れた。うち3件は**黙って壊れる** — 症状が出ないまま誤った位置を返す、あるいは別の場所が壊れる。資料に書くだけでは、読まなかった人が同じ穴に落ちる。踏んだら止まる状態にするまでを範囲とする。

黙って壊れる3件。

- 解析を自前で組み直すとハイドレーションが壊れ、**アプリ全体のアイコンが消える**。markdown 本文には症状が出ず、全画面のピクセル差分だけが捕まえた
- offset 0 と `undefined` の取り違え。`parser/compiler.js` が `node.position?.start?.offset && …` と真偽判定するため、文書の冒頭から始まるノードは `position` を持たない。そこに 0 を書くと冒頭が `[0,0)` を指す
- 記法によって `position` が記号を含むかが違う。`**強調**` は含まず、`` `インラインコード` `` は含む。長さを按分すると1〜2文字ずれた位置を黙って返す

検知力の測定で、さらに穴が見つかった。テストはフェンスの幾何と text ノードの位置をよく固めているが、**AST の構造を何も固めていない**。出力が実際に変わったのに143本すべてが通過した変異が3件あった。

ハイドレーションの検知にも拾えない範囲がある。属性だけのずれは Vue が本番ビルドで直さないため素通りし、アイコン消失そのものはこの環境で再現しない（`@nuxt/icon` のカスタムコレクションが 404 で、SSR も客側も空の `<svg>` を出す）。再現環境を用意するか、再現しない前提で検知の設計を見直すかを着手時に選ぶ。

`create-module-markdown` から分けた。あちらは markdown を扱う実体をモジュールに閉じ、位置の口を実装するところまでを持つ。`adr0017-sub-add-position-port-preview` の後続で、口の形が確定してから検知を書く。
