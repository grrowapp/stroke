# adopt-upstream-design-tokens

統合で見た目が割れないよう、ストローク側の画面を本家再現の design token（CSS 変数・ダークテーマ）に揃える

## Triage Notes

> *This was generated by AI during triage.*

**目的の前提が動いている（2026-08-25 の確認）。**

この change の目的は「本家 spec-workflow-mcp と地続きに見えること」で、値も本家の CSS バンドルから取り、そこに無い色を足さないと決めている。つまり**本家の見た目を正としている**。

ところが、本家そのものを段階的に自作していく前提が別にある。本家を置き換えるなら、「本家の色に合わせる」という目的は過渡的なものになり、何を正とするかが変わる。

**決めてもらう必要があること:**

- **何を正とするか。** 本家の design token を引き続き正とするのか、自作を見据えて独自の token 体系を定めるのか。前者なら本家のバンドルから取り続け、後者なら「本家に無い色を足さない」という制約は外れる。
- **合わせる方向。** 現状は2つの見た目が同居している（一方は本家再現の CSS 変数とダークテーマ、他方は UI ライブラリの既定にタイポグラフィ拡張を足したもの）。どちらに寄せるかは、上の判断で決まる。

**急ぐ理由はある。** 統合済みなので、プロジェクト一覧から概要入力へ移った瞬間に見た目が割れる状態が現に起きている。ユーザーには「別のところへ飛ばされた」と映る。ただし正が決まらないまま片側へ寄せると、自作の段階でやり直しになる。

**この change を待っているもの:** `fold-stroke-css`（セッション画面だけに効くスタイルを畳む）は token の採用が先だと明記している。
