## MODIFIED Requirements

### Requirement: 一覧は4つの列を持つ

システムは、プロジェクト一覧の各行に次の4つを示さなければならない（SHALL）。

- **プロジェクト** — 走査で見つかったディレクトリ名。生成中のものは、承認で確定した名前
- **状態** — **アクティブ / 未接続 / 生成中** のいずれか。**プロセス ID は示さない（MUST NOT）**——一覧で下す判断は「その行に入るかどうか」だけで、プロセス ID はその判断に使われない。**「作成に失敗」の状態は持たない（MUST NOT）**——失敗は決着のモーダルで片付き、行として居座らない（`project/generation`）
- **未処理の通知** — そのプロジェクトで発生していて一覧に残っている通知の件数。0件のときは件数を出さず、無いことが分かる表示にする。生成中のものは通知を持ちようがないため、同じく無いことが分かる表示にする
- **最終更新** — そのプロジェクトの `.spec-workflow` がいつ更新されたか。取れないときは、取れないことが分かる表示にする

「最終更新」は未接続のプロジェクトについても示さなければならない（SHALL）。未接続では本家 API から何も取れないため、ここが唯一の手がかりになる。

生成中のプロジェクトは `.spec-workflow` を持たないため、「最終更新」は取れないことが分かる表示にする（SHALL）。取れない事実を、承認した時刻など別の値で埋めてはならない（MUST NOT）。

システムは、3つの状態を **同じ形・同じ幅** で示さなければならない（SHALL）。状態によって形や大きさを変えてはならない（MUST NOT）。幅を揃えるのは、状態の列が行をまたいで縦に揃い、一覧を上から下へ流し読みできるようにするためである。

システムは、**アクティブだけを際立たせ**なければならない（SHALL）。未接続と生成中は際立たせない。3つの違いは、形の違いではなく、際立っているかどうかと文言で示す。ここで「際立つ」とは、同じ形のまま色と明るさだけが変わることを指す。

#### Scenario: アクティブなプロジェクトの行

- **WHEN** アクティブなプロジェクトの行を見る
- **THEN** 状態に「アクティブ」が出ており、プロセス ID は出ていない

#### Scenario: 未接続のプロジェクトの行

- **WHEN** 未接続のプロジェクトの行を見る
- **THEN** 状態は「未接続」で、アクティブと区別できる

#### Scenario: 生成中のプロジェクトの行

- **WHEN** 生成中のプロジェクトの行を見る
- **THEN** 名前は承認で確定した名前が出ており、状態は「生成中」、未処理の通知と最終更新はいずれも無いことが分かる表示になっている

#### Scenario: 3つの状態を並べて見る

- **WHEN** アクティブ・未接続・生成中の行が同じ一覧に並んでいる
- **THEN** 3つの状態は同じ形と同じ幅で示されており、状態の列は縦に揃っている

#### Scenario: 際立っているものを見分ける

- **WHEN** 一覧の状態の列を見る
- **THEN** 際立っているのはアクティブの行だけであり、未接続と生成中は際立っていない

#### Scenario: 通知が発生していないプロジェクト

- **WHEN** そのプロジェクトの通知が1件も無い
- **THEN** 未処理の通知の列は件数ではなく、無いことが分かる表示になる

#### Scenario: 通知が発生したプロジェクト

- **WHEN** そのプロジェクトで通知が2件発生している
- **THEN** 未処理の通知の列に 2 が出ている

#### Scenario: 未接続のプロジェクトの最終更新

- **WHEN** 未接続のプロジェクトの行を見る
- **THEN** 最終更新が出ている

### Requirement: 未接続のプロジェクトは選択できない

システムは、未接続のプロジェクトの行を選択不可としなければならない（SHALL）。押せないことが見て分かる表示にし、キーボード操作のフォーカス対象にしてはならない（MUST NOT）。

システムは、**生成中のプロジェクトの行も、同じく選択不可としなければならない（SHALL）**。まだ下層に入れる中身を持たないためである。

システムは、押せないことを示すために行を弱めるとき、**状態の列を弱めてはならない（MUST NOT）**。弱めるのは名前・未処理の通知・最終更新であり、状態はアクティブの行と同じ読みやすさを保たなければならない（SHALL）。

行を弱めるのは「その行に入れない」ことを示すためである。状態はその理由そのものを名指しているため、理由まで一緒に弱めると、押せない行を前にして原因が読み取れなくなる。行全体に一律の弱め方を掛ける実装は、この要件を満たさない。

#### Scenario: 未接続の行をポインタで押す

- **WHEN** 未接続のプロジェクトの行を押す
- **THEN** 何も起きず、下層に入らない

#### Scenario: 生成中の行をポインタで押す

- **WHEN** 生成中のプロジェクトの行を押す
- **THEN** 何も起きず、下層に入らない

#### Scenario: キーボードで一覧を辿る

- **WHEN** キーボードでプロジェクト一覧のフォーカスを順に送る
- **THEN** フォーカスはアクティブな行だけを通り、未接続・生成中の行では止まらない

#### Scenario: 未接続の行の状態を読む

- **WHEN** 未接続のプロジェクトの行を見る
- **THEN** 名前・未処理の通知・最終更新は弱く示されるが、状態はアクティブの行と同じ読みやすさで読める

#### Scenario: 未接続の行とアクティブの行を並べて見る

- **WHEN** 未接続の行とアクティブの行が同じ一覧に並んでいる
- **THEN** 状態の列だけは、どちらの行でも同じ読みやすさで示されている
