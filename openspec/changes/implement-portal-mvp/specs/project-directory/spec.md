## Purpose

監視対象のプロジェクトがどれで、そのうちどれが今つながっているかを1つの一覧で示し、つながっているプロジェクトの下層へ入場させる。プロジェクトを増やす操作の入口もここに置く。

## ADDED Requirements

### Requirement: プロジェクトの母集合を親パスの走査で作る

システムは、設定された親パスの配下を走査し、`.spec-workflow` ディレクトリを持つディレクトリをプロジェクトとして扱わなければならない（SHALL）。本家 API はプロジェクト一覧の母集合として使ってはならない（MUST NOT）。本家 API は停止中のプロジェクトを返さないためである。

システムは、走査対象を読み取りのみで扱わなければならない（MUST）。プロジェクトのディレクトリにも `.spec-workflow/` にも書き込んではならない（MUST NOT）。

#### Scenario: 親パスの配下にプロジェクトがある

- **WHEN** 設定された親パスの配下に `.spec-workflow` を持つディレクトリが複数ある
- **THEN** それらすべてがプロジェクトとして一覧に並ぶ

#### Scenario: `.spec-workflow` を持たないディレクトリは拾わない

- **WHEN** 親パスの配下に `.spec-workflow` を持たないディレクトリがある
- **THEN** そのディレクトリは一覧に現れない

#### Scenario: 親パスが未設定

- **WHEN** 親パスが設定されていない状態でプロジェクト一覧を開く
- **THEN** 「親パスが未設定である」と分かる表示になり、「プロジェクトが0件である」状態とは区別できる

#### Scenario: 親パスの配下にプロジェクトが1件も無い

- **WHEN** 親パスは設定されているが、配下に `.spec-workflow` を持つディレクトリが1つも無い
- **THEN** 「プロジェクトが0件である」と分かる表示になり、「親パスが未設定である」状態とは区別できる

#### Scenario: 親パスが読み取れない

- **WHEN** 設定された親パスが存在しない、または読み取り権限が無い
- **THEN** 走査の失敗が画面に出て、0件の状態と区別できる

### Requirement: アクティブと未接続を判定して示す

システムは、各プロジェクトが **アクティブ**（本家の MCP サーバーが繋がっている）か **未接続**（繋がっていない）かを判定し、一覧に示さなければならない（SHALL）。判定は本家のグローバル状態（`activeProjects.json`）または本家 API を母集合に重ねて行う。

システムは、アクティブ判定が本家ダッシュボードの起動時に1回しか更新されないという本家の制約を、そのまま受け入れなければならない（SHALL）。本家プロセスの生存を stroke-board が独自に確認してはならない（MUST NOT）。

#### Scenario: 本家に繋がっているプロジェクト

- **WHEN** 本家のグローバル状態に、そのプロジェクトの生きたインスタンスが登録されている
- **THEN** 一覧のその行は「アクティブ」として表示され、選択できる

#### Scenario: 本家に繋がっていないプロジェクト

- **WHEN** 走査では見つかるが、本家のグローバル状態に生きたインスタンスが無い
- **THEN** 一覧のその行は「未接続」として表示され、選択できない

#### Scenario: アクティブなプロジェクトが1件も無い

- **WHEN** 走査で見つかったすべてのプロジェクトが未接続である
- **THEN** 一覧には行が並ぶが、どの行も選択できない状態になる

### Requirement: 一覧は4つの列を持つ

システムは、プロジェクト一覧の各行に次の4つを示さなければならない（SHALL）。

- **プロジェクト** — 走査で見つかったディレクトリ名
- **状態** — アクティブ か 未接続 か。アクティブのときは、その判定の実体である本家の MCP サーバーのプロセス ID も示す
- **未処理の通知** — そのプロジェクトで発生していて一覧に残っている通知の件数。0件のときは件数を出さず、無いことが分かる表示にする
- **最終更新** — そのプロジェクトの `.spec-workflow` がいつ更新されたか。取れないときは、取れないことが分かる表示にする

「最終更新」は未接続のプロジェクトについても示さなければならない（SHALL）。未接続では本家 API から何も取れないため、ここが唯一の手がかりになる。

#### Scenario: アクティブなプロジェクトの行

- **WHEN** アクティブなプロジェクトの行を見る
- **THEN** 状態に「アクティブ」と本家の MCP サーバーのプロセス ID が出ている

#### Scenario: 未接続のプロジェクトの行

- **WHEN** 未接続のプロジェクトの行を見る
- **THEN** 状態は「未接続」で、プロセス ID は出ていない

#### Scenario: 通知が発生していないプロジェクト

- **WHEN** そのプロジェクトの通知が1件も無い
- **THEN** 未処理の通知の列は件数ではなく、無いことが分かる表示になる

#### Scenario: 通知が発生したプロジェクト

- **WHEN** そのプロジェクトで通知が2件発生している
- **THEN** 未処理の通知の列に 2 が出ている

#### Scenario: 未接続のプロジェクトの最終更新

- **WHEN** 未接続のプロジェクトの行を見る
- **THEN** 最終更新が出ている

### Requirement: アクティブを上、未接続を下に並べる

システムは、プロジェクト一覧をアクティブなものが上、未接続のものが下になるよう並べなければならない（SHALL）。

#### Scenario: アクティブと未接続が混在する

- **WHEN** アクティブなプロジェクトと未接続のプロジェクトが両方ある
- **THEN** アクティブなプロジェクトがすべて未接続のプロジェクトより上に並ぶ

### Requirement: 未接続のプロジェクトは選択できない

システムは、未接続のプロジェクトの行を選択不可としなければならない（SHALL）。押せないことが見て分かる表示にし、キーボード操作のフォーカス対象にしてはならない（MUST NOT）。

#### Scenario: 未接続の行をポインタで押す

- **WHEN** 未接続のプロジェクトの行を押す
- **THEN** 何も起きず、下層に入らない

#### Scenario: キーボードで一覧を辿る

- **WHEN** キーボードでプロジェクト一覧のフォーカスを順に送る
- **THEN** フォーカスはアクティブな行だけを通り、未接続の行では止まらない

### Requirement: アクティブなプロジェクトの下層へ入場する

システムは、アクティブなプロジェクトの行を選んだとき、そのプロジェクトの下層へ入場させなければならない（SHALL）。入場先は下層のサイドバーの先頭画面とする。

#### Scenario: アクティブな行を選ぶ

- **WHEN** アクティブなプロジェクトの行を選ぶ
- **THEN** そのプロジェクトの下層に入り、サイドバーの先頭画面が開いている

### Requirement: プロジェクトの登録と作成は非活性の入口として持つ

システムは、プロジェクト一覧画面に「登録」と「作成」の入口を置かなければならない（SHALL）。本 change の時点では実処理を持たないため、どちらも非活性としなければならない（MUST）。押しても何も起きない状態にしてはならない（MUST NOT）— 押せないことが見て分かる表示にする。

システムは、独立したメニュー項目として登録・作成を持ってはならない（MUST NOT）。一覧画面の操作として持つ。

#### Scenario: 登録の入口を見る

- **WHEN** プロジェクト一覧画面を開く
- **THEN** 「登録」の入口が非活性で表示されている

#### Scenario: 作成の入口を見る

- **WHEN** プロジェクト一覧画面を開く
- **THEN** 「作成」の入口が非活性で表示されている

### Requirement: プロジェクトの一覧を永続化しない

システムは、プロジェクトの登録簿を自前で持ってはならない（MUST NOT）。一覧は走査と本家のグローバル状態から毎回導出する。

#### Scenario: プロジェクトが親パスから消える

- **WHEN** 親パスの配下からプロジェクトのディレクトリが削除され、その後に一覧を取得する
- **THEN** そのプロジェクトは一覧に現れない
