## Purpose

画面へ出来事を届ける WebSocket 配信の規約を1箇所に定める。出来事が増えるたびに新しい配信口と束ね方が生えていくのを止め、届け方を用途の数だけに保つ。

## ADDED Requirements

### Requirement: WS 配信はサーバから画面への一方向とする

システムは、WS 配信をサーバから画面への一方向としなければならない（SHALL）。画面から配信の口へ送られたものを、状態を変える入力として受け付けてはならない（MUST NOT）。状態を変える操作は HTTP の口で受ける。

#### Scenario: 画面が配信の口へ送る

- **WHEN** 画面が WS の口へ何かを送る
- **THEN** システムはそれを受け付けず、サーバの状態は何も変わらない

#### Scenario: サーバが出来事を配信する

- **WHEN** サーバ側で配信対象の出来事が起きる
- **THEN** その接続を張っている画面へ配信が届く

### Requirement: 接続した瞬間に現在分を配信する

システムは、画面が接続した瞬間に、その接続が運ぶものの**現在分**を配信しなければならない（SHALL）。画面が接続より前に起きた出来事を取りこぼしたまま、次の出来事が起きるまで何も知らない状態にしてはならない（MUST NOT）。

現在分の配信は、接続後に起きた出来事の配信と区別できなければならない（SHALL）。画面はこの区別によって、既に起きていたものを新たに起きたものとして扱わずに済む。

#### Scenario: 何も起きていない状態で接続する

- **WHEN** 配信対象の出来事がまだ何も起きていない状態で画面が接続する
- **THEN** 現在分として「何も無い」ことが配信され、画面は取得の途中で止まらない

#### Scenario: 既に起きている状態で接続する

- **WHEN** 配信対象の出来事が既に起きている状態で画面が接続する
- **THEN** その現在分が接続の瞬間に配信される

#### Scenario: 接続の後に出来事が起きる

- **WHEN** 接続した後に配信対象の出来事が起きる
- **THEN** それが配信され、画面は接続時に受け取った現在分とは区別できる

### Requirement: 新しい種類の出来事のために配信の口を増やさない

システムは、配信する出来事の種類が増えたときに、そのために新しい WS の endpoint を追加してはならない（MUST NOT）。既にある接続の上で、**メッセージの種別**によって区別しなければならない（SHALL）。

配信の口を分けてよいのは、**運ぶ相手が違うとき**だけとする（SHALL）。すなわち、全体に向けた配信と、ある1つのセッションに向けた配信は別の口でよいが、同じ相手に向かう出来事が2種類あることを理由に口を2本にしてはならない（MUST NOT）。

#### Scenario: 同じ相手へ届ける出来事が増える

- **WHEN** 既にある配信と同じ相手へ届く、新しい種類の出来事が加わる
- **THEN** WS の endpoint は増えず、既にある接続にメッセージの種別が1つ加わる

#### Scenario: 届ける相手が異なる配信

- **WHEN** 全体に向けた配信と、特定のセッションに向けた配信の両方がある
- **THEN** それらは別の口であってよい

### Requirement: 画面は同じ相手向けの接続を1本だけ張る

システムは、1つのブラウザが同じ相手向けの WS 接続を複数本張らないようにしなければならない（SHALL）。画面の遷移によって接続を張り替えてはならない（MUST NOT）。張り替えると、その間に起きた出来事を取りこぼす。

#### Scenario: 画面を移動する

- **WHEN** 同じブラウザで画面を移動する
- **THEN** WS 接続は張り直されず、移動の前後で同じ1本が続いている

#### Scenario: 同じ配信を複数の場所が使う

- **WHEN** 1つの画面の中の複数の箇所が同じ配信を必要とする
- **THEN** 接続は1本のまま、それぞれがその1本から受け取る

### Requirement: 接続が切れたら張り直し、切れている間を偽らない

システムは、WS 接続が切れたときに自動で張り直さなければならない（SHALL）。張り直した時点で現在分が配信されるため、切れている間に起きた出来事はそこで揃う。

システムは、接続が切れている間、最後に受け取った内容を最新であるかのように見せてはならない（MUST NOT）。

#### Scenario: サーバが再起動する

- **WHEN** 画面を開いたままサーバが再起動する
- **THEN** 接続が張り直され、その時点の現在分が配信される

#### Scenario: 切れている間に出来事が起きる

- **WHEN** 接続が切れている間に配信対象の出来事が起きる
- **THEN** 張り直した時点の現在分にそれが含まれている
