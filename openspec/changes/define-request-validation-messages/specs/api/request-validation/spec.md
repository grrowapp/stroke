# api/request-validation Delta

## Purpose

受け口が入力を受けるときの検証と、受け付けられなかったときの伝え方を定める。

送り手（エージェント・画面）は、返ってきた内容だけを頼りに値を直して送り直す。何が悪いか分からなければ、当たるまで送り続けるしかない。

## ADDED Requirements

### Requirement: 送られた値は検証の定義を通す

システムは、送り手が組み立てて送るすべての入力を、定義された検証を通して受ける SHALL。検証を経ずに受ける経路を持ってはならない（MUST NOT）。

#### Scenario: 定義に無い形は受け付けない

- **GIVEN** ある受け口が入力の形を定義している
- **WHEN** 送り手がその形に合わない値を送る
- **THEN** 受け付けられず、受け付けなかったことが送り手に伝わる

### Requirement: 制約ごとに、その制約のためのメッセージを定める

システムは、入力の各制約に対し、その制約に反したときのメッセージを定める SHALL。検証の仕組みが持つ既定のメッセージに委ねてはならない（MUST NOT）。

メッセージは、**何の項目が、どの決まりに反したか**をそのまま読める文とする SHALL。

#### Scenario: 何を直せばよいか読み取れる

- **GIVEN** 送り手が、ある項目の決まりに反した値を送った
- **WHEN** 受け口がそれを受け付けない
- **THEN** 返る内容から、どの項目の、どういう決まりに反したかが読み取れ、送り手は値を直せる

#### Scenario: 検証の仕組みの言葉が漏れない

- **GIVEN** 送り手が制約に反した値を送った
- **WHEN** 送り手が返ってきた内容を読む
- **THEN** 内容はその受け口の言葉で書かれており、検証の実装が生成した文言がそのまま出ることはない

### Requirement: 違反はすべて返す

システムは、複数の制約に反している場合、そのすべてを返す SHALL。最初の1つだけを返してはならない（MUST NOT）。

1つずつ返すと、送り手は直しては送り直すことを繰り返す。往復のたびに時間と実行が費やされる。

#### Scenario: 複数の違反が一度に返る

- **GIVEN** 送り手が、複数の項目でそれぞれ決まりに反した値を送った
- **WHEN** 受け口がそれを受け付けない
- **THEN** 反した項目がすべて返り、送り手は一度に直せる

### Requirement: 量の違反には現在の値を添える

システムは、長さ・件数の上限や下限に反した場合、**いま幾つなのか**を添える SHALL。

上限だけを伝えても、送り手は自分の値が幾つかを数え直すことになる。どれだけ超えているかが分かれば、削る量が決まる。

#### Scenario: あと幾つ削ればよいか分かる

- **GIVEN** ある項目に長さの上限がある
- **WHEN** 送り手が上限を 1 だけ超えた値を送る
- **THEN** 返る内容から、上限と現在の長さの両方が読み取れ、1 だけ削ればよいと分かる

#### Scenario: 件数の違反も同じ形で伝わる

- **GIVEN** ある項目に件数の上限がある
- **WHEN** 送り手が上限を超える件数を送る
- **THEN** 返る内容から、上限と現在の件数の両方が読み取れる
