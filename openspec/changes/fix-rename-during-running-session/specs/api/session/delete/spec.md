## REMOVED Requirements

### Requirement: 実行中の呼び出しを持つセッションの削除は受理しない

**Reason**: 「実行中だから受理しない（busy）」という応答を契約から無くす。実行中は断る理由ではなく、順番を待つ理由である（`api/session/invoke-agent`「同一対象の多重起動を受け付けない」）。

**Migration**: 実行中のセッションへの削除は予約として受理され、実行の終わりに行われる（下の ADDED）。呼び手は削除を出し直さない。

## ADDED Requirements

### Requirement: 実行中の呼び出しを持つセッションの削除は、実行の終わりに行う

システムは、実行中の呼び出しを持つセッションへの `DELETE /api/sessions/:id` を、**断らずに予約として受理する SHALL。** 予約の時点では何も消さない。今の実行が終わった時点で、セッションに属するものを残らず消す SHALL。

実行中かの判定の単位は、起動の endpoint（`api/session/invoke-agent`）が定める「同一対象」と同じものとする SHALL。削除が予約された対象に起動の予約があれば捨てる SHALL——消える対象に次の実行は無い。

画面は実行中のセッションに削除の操作を出さない（`stroke/frontier`「承認の操作は、対象の実行が平常のときにだけ存在する」）ので、予約に落ちるのは別々の画面が同時に操作したときだけである。

#### Scenario: 実行中に消そうとする

- **WHEN** 実行中の呼び出しを持つセッションの削除が要求される
- **THEN** システムは予約として受理し、その時点ではセッションに属するものは何も消えない

#### Scenario: 予約された削除が実行の終わりに行われる

- **WHEN** 削除が予約されたセッションの実行が終わる
- **THEN** セッションに属するものは残らず消え、次の実行は始まらない

#### Scenario: 呼び出しが終わった後に消す

- **WHEN** 実行中だった呼び出しが終わったセッションに削除が要求される
- **THEN** システムは受理し、セッションに属するものはすぐに残らず消える
