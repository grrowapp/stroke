## MODIFIED Requirements

### Requirement: 同一対象の多重起動を受け付けない

システムは、実行中の呼び出しを持つ対象への起動要求を受理しない SHALL。呼び出しが終わった後は、同じ対象に再び起動を要求できる。

**「同一対象」は、要求に使われた id ではなく、その実行の作業場所（cwd が指す物理ディレクトリ）を単位とする SHALL。** 同じ物理ディレクトリを作業場所とする呼び出しどうしは、異なる id で要求されても同一対象とみなす SHALL。id が異なることを理由に、同じ物理ディレクトリで2つの呼び出しを同時に走らせてはならない（MUST NOT）。

承認による昇格は対象の id を uuid からプロジェクト名へ変えるが、ディレクトリの実体は改名の前後で同じものである。したがって昇格前の id で始まった呼び出しと、昇格後の id で起こす呼び出しは同一対象であり、同時に走ってはならない（MUST NOT）。

作業場所が異なる呼び出しどうしは別の対象とし、同時に走ることを妨げてはならない（MUST NOT）。

実行中かどうかを見る他の口——セッションの削除・プロジェクトの削除・承認——は、この同じ単位で判定する SHALL。口ごとに別の単位で数え直してはならない（MUST NOT）。同じ物理ディレクトリが口によって別々の対象に見える状態を作ってはならない（MUST NOT）。

#### Scenario: 実行中に起動を要求する

- **WHEN** 実行中の呼び出しを持つ対象に起動が要求される
- **THEN** システムは受理せず busy であることを伝え、AI は二重に起動されない

#### Scenario: 呼び出しが終わった後に再び起動を要求する

- **WHEN** 実行中だった呼び出しが終わった対象に、再び起動が要求される
- **THEN** システムは受理し、AI の呼び出しを開始する

#### Scenario: 昇格の前後で同じディレクトリに起動が要求される

- **WHEN** 昇格前の id で始まった呼び出しが実行中のまま、同じ物理ディレクトリを作業場所として昇格後の id で起動が要求される
- **THEN** システムは受理せず busy であることを伝え、そのディレクトリで2つ目の呼び出しは始まらない

#### Scenario: 別のディレクトリなら同時に走る

- **WHEN** 実行中の呼び出しを持つ対象とは別のディレクトリを作業場所として起動が要求される
- **THEN** システムは受理し、AI の呼び出しを開始する

#### Scenario: 削除と起動が同じ単位で実行中を見る

- **WHEN** ある物理ディレクトリで呼び出しが実行中の状態で、その対象の削除が要求される
- **THEN** 削除は受理されず busy であることを伝える。起動を止めた実行中と、削除を止めた実行中は同じ1つの事実である
