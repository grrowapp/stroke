## MODIFIED Requirements

### Requirement: U10 POST /api/sessions/:id/approve — 承認を受理して昇格を実行する

システムは `POST /api/sessions/:id/approve` を公開する SHALL。確定された名前を受け取り、昇格（`project/generation` が規定する rename）を実行する。

昇格が成功したら次の実行を起こし、その完了を待たずに受理を返す SHALL。昇格が失敗したときは失敗を返し、次の実行を起こしてはならない（MUST NOT）。

昇格が失敗したとき、phase は `proposed` のままとし、同じセッションでユーザーが再度承認できる状態を保つ SHALL。**phase が `approved` なのに昇格していない**宙吊りの状態を作ってはならない（MUST NOT）。

存在しないセッション id への承認は受理しない SHALL。

**対象に実行中の呼び出しがある間は、昇格を実行してはならない（MUST NOT）。** システムは昇格の前に対象が実行中かを確認し、実行中であれば何も変えずに busy であることを伝える SHALL。判定の単位は起動（U13）が定める「同一対象」と同じものとする SHALL——別の単位で数え直してはならない（MUST NOT）。呼び出しが終わった後は、同じセッションで再度承認できる SHALL。

**確認から昇格の完了までの間に、対象への新しい呼び出しの起動が始まってはならない（MUST NOT）。** 実行中かを確認した後に起動が入り込めると、確認をすり抜けた呼び出しが改名の最中に走り出す。システムはこの区間を、起動が割り込めない1つの区間として扱う SHALL。区間を抜けた後は、承認が起こす次の実行を含め、通常どおり起動できる SHALL。

理由は、昇格が**セッションディレクトリの改名**だからである（`project/generation`）。改名はディレクトリの実体を移さないため、走っている呼び出しは改名先で生き続ける一方、その呼び出しが自分を名乗る id は改名前のものである。改名の後はその id で参照できるものが無く、以後その呼び出しが行う操作——問いの送信・文書の提出・実行の記録——はすべて対象を見つけられずに落ちる。走らせたまま改名すると、その呼び出しの成果はどこにも残らない。

#### Scenario: 承認が成功する

- **WHEN** 確定された名前を伴う承認が `POST /api/sessions/:id/approve` に届き、昇格が成功する
- **THEN** 受理が返る。応答は次の実行の完了を待たない

#### Scenario: 昇格が失敗する

- **WHEN** 承認が届いたが昇格が失敗する
- **THEN** 失敗が返り、次の実行は起こされない。phase は `proposed` のまま、セッションは元の名前で残り、ユーザーは再度承認できる

#### Scenario: 存在しない id で承認が届く

- **WHEN** 存在しないセッション id に承認が届く
- **THEN** システムは受理せず、存在しないことを伝え、何も変えない

#### Scenario: 実行中に承認が届く

- **WHEN** 対象に実行中の呼び出しがある状態で承認が届く
- **THEN** システムは受理せず busy であることを伝える。ディレクトリは改名されず、phase は `proposed` のままで、次の実行も起こされない

#### Scenario: 呼び出しが終わった後に承認する

- **WHEN** 実行中だった呼び出しが終わった後に、同じセッションへ再び承認が届く
- **THEN** システムは受理し、昇格を実行する

#### Scenario: 確認の後に起動が割り込もうとする

- **WHEN** 承認が実行中でないことを確認した後、昇格が終わる前に、同じ対象への起動が要求される
- **THEN** その起動は昇格の完了までは始まらず、改名の最中に走る呼び出しは生まれない

#### Scenario: 改名が走っている呼び出しを置き去りにしない

- **WHEN** 承認が受理されて昇格が成立した
- **THEN** 改名の時点で対象に走っていた呼び出しは無く、改名前の id を名乗ったまま生き残る呼び出しは存在しない

#### Scenario: 昇格の後に次の実行が起こる

- **WHEN** 昇格が成功し、承認が次の実行を起こす
- **THEN** その起動は同じディレクトリを作業場所として受理される。承認が取った実行中の確認は、この起動を妨げない
