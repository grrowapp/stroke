## REMOVED Requirements

### Requirement: 実行中の呼び出しを持つプロジェクトの削除は受理しない

**Reason**: 「実行中だから受理しない（busy）」という応答を契約から無くす。実行中は断る理由ではなく、順番を待つ理由である（`api/session/invoke-agent`「同一対象の多重起動を受け付けない」）。

**Migration**: 実行中のプロジェクトへの削除は予約として受理され、実行の終わりに行われる（下の ADDED）。呼び手は削除を出し直さない。

## ADDED Requirements

### Requirement: 実行中の呼び出しを持つプロジェクトの削除は、実行の終わりに行う

システムは、実行中の呼び出しを持つプロジェクトへの削除を、**断らずに予約として受理する SHALL。** 予約の時点では何も消さない。今の実行が終わった時点で、そのディレクトリ配下を残らず消す SHALL。セッションの削除と同じ扱いとする。

実行中かの判定の単位は、起動の endpoint（`api/session/invoke-agent`）が定める「同一対象」と同じものとする SHALL。削除が予約された対象に起動の予約があれば捨てる SHALL。巡回（`portal/batch`）が実行の終わりを retry の対象として拾う前に削除が行われるので、消えた対象が再び起動されることはない。

#### Scenario: steering が走っている最中に消そうとする

- **WHEN** 実行中の呼び出しを持つプロジェクトの削除が要求される
- **THEN** システムは予約として受理し、その時点では何も消えない

#### Scenario: 予約された削除が実行の終わりに行われる

- **WHEN** 削除が予約されたプロジェクトの steering の実行が終わる
- **THEN** そのディレクトリ配下は残らず消え、巡回はそれを起動しない
