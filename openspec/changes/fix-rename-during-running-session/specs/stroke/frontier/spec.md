## MODIFIED Requirements

### Requirement: 承認の成功で画面2を離れてプロジェクト一覧へ戻る

システムは、承認が成功したときにモーダルを閉じ、プロジェクト一覧へ戻す SHALL。承認の応答は、承認後に始まる次の実行の完了を待ってはならない（MUST NOT）。

承認が成功したセッションは、そのセッション id では開けなくなる SHALL。セッションはプロジェクトへ昇格して同じ id のセッションとしては存在しなくなるためである（`project/generation`）。承認後に承認・差し戻しの操作が現れる余地は無い。

承認が成功しなかったときは画面2に留まり、ユーザーが同じセッションで承認し直せる状態を保つ SHALL。

**成功しなかった理由は、ユーザーの次の手が分かる形で示す SHALL。** 理由を捨てて汎用の失敗として示してはならない（MUST NOT）。理由によって次の手が違う。

- **名前の衝突** — 別の名前で承認し直す
- **AI が実行中**（昇格が busy で断られた） — 走っている AI の応答が終わるのを待ち、**同じ名前のまま**承認し直す。名前の変更を求めてはならない（MUST NOT）。実行の終わりは画面が示す実行中の表示で分かる
- **昇格の失敗**（改名や phase の書き込みの失敗） — 判断は残っているので、昇格だけをやり直すか破棄するかを選ぶ

#### Scenario: 承認が成功する

- **WHEN** ユーザーがプロジェクト名を確定して承認し、昇格が成功する
- **THEN** モーダルが閉じてプロジェクト一覧が表示される。次の実行の完了は待たない

#### Scenario: 承認したセッションを開こうとする

- **WHEN** 承認が成功した後、そのセッション id の画面2を開こうとする
- **THEN** そのセッションは存在せず画面2は開かない。承認・差し戻しの操作は現れない

#### Scenario: 承認が失敗する

- **WHEN** 名前の衝突や昇格の失敗で承認が成立しない
- **THEN** 画面2に留まり、phase は `proposed` のままで、別の名前で承認し直せる

#### Scenario: AI が実行中に承認する

- **WHEN** 対象で AI が走っている最中にユーザーが承認し、昇格が busy で断られる
- **THEN** 画面2に留まり、AI が実行中で終わるのを待てば通ることが示される。名前の変更は求められず、phase は `proposed` のまま、確定した名前も保たれている

#### Scenario: AI の応答が終わってから承認し直す

- **WHEN** busy で断られた後、AI の応答が終わり、ユーザーが同じ名前で再び承認する
- **THEN** 昇格が成功し、モーダルが閉じてプロジェクト一覧へ戻る
