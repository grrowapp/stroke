## ADDED Requirements

### Requirement: U15 POST /api/sessions/:id/activate — 昇格した対象を完成した状態にする

システムは `POST /api/sessions/:id/activate` を公開する SHALL。昇格した対象を、**steering が成果物を出し終えた状態**にする受け口である。承認の判断（`api/session/approve`）・昇格（`api/session/promote`）・起動（`api/session/invoke-agent`）に続く4段目にあたる。

**この受け口は本文を取らない SHALL。** 書く値は1つに決まっており、引数で受ける余地を残してはならない（MUST NOT）——受ければ、この受け口を通して任意の状態を書けることになる。昇格の受け口が名前を引数に取らないのと同じ形である。

**昇格した対象以外の要求を受理してはならない（MUST NOT）。** 完成は昇格の後にしか起こらない。これは分岐ではなく責務の不成立である——「昇格した対象を完成した状態にする」が責務であり、昇格していなければそれが成立しない。

**この受け口は次の実行を起こしてはならない（MUST NOT）**し、**成果物の有無を自分で判定してはならない（MUST NOT）**。判定は要求する側が済ませており、この受け口は記録するだけである。

既に完成した対象への重ねての要求は受理しない SHALL。存在しない id への要求は受理しない SHALL。

#### Scenario: 昇格した対象を完成した状態にする

- **WHEN** 昇格した対象へ `POST /api/sessions/:id/activate` が届く
- **THEN** その対象は完成した状態として記録され、受理が返る。次の実行は起こされない

#### Scenario: 昇格していない対象に要求が届く

- **WHEN** まだ昇格していないセッションへ要求が届く
- **THEN** システムは受理せず、何も変えない

#### Scenario: 既に完成した対象に要求が届く

- **WHEN** 既に完成した状態の対象へ要求が届く
- **THEN** システムは受理せず、何も変えない

#### Scenario: 存在しない id に要求が届く

- **WHEN** 存在しない id へ要求が届く
- **THEN** システムは受理せず、存在しないことを伝え、何も変えない

### Requirement: 完成の記録を要求できるのは、実行を握っている側だけである

システムは、完成の記録を要求する主体を、**AI の呼び出しを終端まで握っている側**に限る SHALL。画面とエージェントはこの受け口を叩かない（MUST NOT）。

エージェント自身に完成を告知させてはならない（MUST NOT）。完成の検知に AI の協力を要らなくすることは既に定めがあり（`agent/invocation`）、その形をここでも保つ。

要求する側は、**成果物が在ることを確かめてから**要求する SHALL。確かめられなかったとき——読めない、または1件も無いとき——は要求してはならない（MUST NOT）。黙って成功へ倒してはならない（MUST NOT）。

#### Scenario: 実行が終わり、成果物が在る

- **WHEN** 昇格した対象の実行が終わり、成果物が在ることを確かめられた
- **THEN** 完成の記録が要求され、その対象は完成した状態になる

#### Scenario: 実行が終わったが、成果物が無い

- **WHEN** 昇格した対象の実行が終わったが、成果物が1つも無い
- **THEN** 完成の記録は要求されず、その対象は昇格したままの状態で残る

#### Scenario: 成果物の有無を確かめられない

- **WHEN** 成果物の有無を確かめようとして、確かめられなかった
- **THEN** 完成の記録は要求されない

#### Scenario: エージェントが完成を告げようとする

- **WHEN** エージェントが自ら完成を告げる手段を探す
- **THEN** そのような口は無い。完成は実行を握っている側が判定して記録する

### Requirement: 完成しなかった対象は、昇格したままの状態で残る

システムは、完成の記録に至らなかった対象を、**昇格したままの状態**で残す SHALL。失敗を表す別の状態を作ってはならない（MUST NOT）。

昇格したままの対象は生成中として扱われる（`project/generation`）。ユーザーはそこから、やり直すか破棄するかを選べる SHALL。

#### Scenario: 完成しないまま残る

- **WHEN** 昇格した対象が、成果物を出せないまま実行を終えた
- **THEN** その対象は昇格したままの状態で残り、一覧には生成中として並ぶ

#### Scenario: 完成しなかった対象をやり直す

- **WHEN** 完成しなかった対象について、ユーザーがやり直しを選ぶ
- **THEN** 昇格はやり直されず、実行だけが起こし直される
