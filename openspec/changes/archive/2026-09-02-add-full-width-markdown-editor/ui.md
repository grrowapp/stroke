## Question

承認画面で、右の指摘の一覧（コメント欄）をしまって本文を広く読めるようにするとき、どう見せ、どう操作するか。

## Variants

prototype は2段階ある。

1. **元の prototype**（ブランチ `proto/full-width-markdown-editor`、develop へ merge `34b58428`）— 稼働中の承認画面の上に `?variant=` と浮きバーで載せた。ユーザーが実機で見た（保存ページ `stroke-board.html`）
2. **ペラ1の写し**（`prototype/index.html`。Nuxt 非依存）— 1 の保存ページをそのまま土台にし、ユーザー指示で直した分を上乗せした。2026-09-01 にユーザーが見て「fix」

3案が変えるのは**しまったときに帯へ何を残すか**だけ:

- **a** 縦書きの帯を残す — 件数バッジと縦書き「コメント」
- **b** 同じ場所で開閉するつまみ — 開いているときの見出し帯のボタンと同じ位置（右上）に、chevron の丸だけ
- **c** 見出しを細くして残す — 見出し帯の絵（吹き出し）と件数バッジだけが細い帯として残る

## Chosen

**挙動は fix（2026-09-01）。** 実機で見て決まったもの:

- 対象は承認画面だけ
- コメント欄をしまえる。しまうと 44px の帯だけ残り、押すと戻る
- 開閉の口は4つ: コメント欄そのものを掴んで左右へ引く／見出し帯のボタン／しまった帯のクリック／右辺の全高レール
- **レールは不可視**。押せるが、hover / 押下で光らせない。中の線も出さない（元 prototype は光っていた → 訂正）
- **左のナビとコメント欄は連動しない**（元 prototype は左を閉じると右もしまっていた → 訂正）
- **コメント欄の幅は固定**。左のナビを畳んで空いた幅は本文だけが取る（元 prototype の `w-1/3` は行幅に比例して広がっていた → 訂正）
- 本文に固定幅は与えない。ビューポートに追従。左右の余白は残ってよい
- **承認画面に編集ボタンは無い**（本家どおり。承認画面は編集できない。仕様書・ステアリングの編集は変えない）
- しまった状態は保存しない

**a / b / c のどれを採るかは未記録。** 3案とも `prototype/index.html` の `?variant=` で見られる。採用が決まるまで design 決定4 と tasks 3.7 は空欄。
