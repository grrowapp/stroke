# mcp/tools/guide Delta

## Purpose

セッション工程の進め方をエージェントへ渡すツール（`get-guide`）の契約を定める。本家 `spec-workflow-mcp` の `spec-workflow-guide` / `steering-guide` と同じ役割で、手順そのものを本文として返す。

操作系のツール（概要の取得・問いの提出など）は「何ができるか」しか伝えられない。どの順で何をするか、いつ問いを立て、いつ把握完了とみなし、いつ proposal を出すかは、この手順を読まないと決まらない。

## ADDED Requirements

### Requirement: 工程の手順を引数なしで取得する

ツールは引数を取らない SHALL。成功の結果は `status` と `guide`（工程の手順の本文）を持つ SHALL。

手順の本文はセッションの状態に依存しない SHALL。状態（概要・これまでの往復・差し戻し）は既存の取得ツールが返すものであり、このツールは手順だけを返す。

#### Scenario: 手順を読む

- **GIVEN** エージェントがセッション工程で起動している
- **WHEN** このツールを実行する
- **THEN** 結果に `status: 200` と、工程の手順の本文（`guide`）が入っている

### Requirement: 手順は工程の全体と終わり方を含む

手順の本文は、次を含む SHALL。

- 状態の確認から提出までの順序
- 問いを立てる単位（一度に1問）と、**各項目の上限がどこに書いてあるか**（上限の数値そのものは書かない SHALL——正は `send-question` の `inputSchema` の説明で、本文へ書き写すと2箇所になり片方だけが古くなる）
- 把握完了の判定（どうなったら問いを止めるか）
- proposal を提出する条件と形式
- 差し戻しを受けたときの進め方

#### Scenario: 把握完了まで到達できる

- **GIVEN** エージェントが手順を読んでいる
- **WHEN** 往復を重ねて問うべきことが無くなる
- **THEN** エージェントは把握完了と判定し、問いの提出をやめて proposal の提出へ移る

### Requirement: 最初に読ませる

ツールの説明（description）は、他のツールより先に呼ぶべきことを述べる SHALL。

#### Scenario: 起動直後に手順を読む

- **GIVEN** エージェントがセッション工程で起動した直後である
- **WHEN** エージェントがツールの一覧を見る
- **THEN** 説明から、まずこのツールを呼ぶべきだと判断できる
