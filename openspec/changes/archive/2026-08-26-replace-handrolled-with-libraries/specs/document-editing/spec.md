## MODIFIED Requirements

### Requirement: 編集できる文書は6本に限る

システムは、次の6本の文書だけを編集できるようにしなければならない（SHALL）。

- 仕様書 — `requirements` / `design` / `tasks`
- ステアリング — `product` / `tech` / `structure`

上記以外の文書を編集させてはならない（MUST NOT）。

編集できるかどうかは**文書の実体で決まり、どの画面から開いたかによって変わってはならない**（MUST NOT）。承認依頼の対象文書が上記6本のいずれかを指している場合、承認画面からも直せなければならない（SHALL）。

まだ作られていない文書は編集させてはならない（MUST NOT）。

**承認画面は読んで判断する場なので、対象文書は整形した本文で開く SHALL。** 直すときは編集へ入る操作を挟む SHALL。承認画面では対象文書に指摘を付けられ（`project-workspace`）、指摘を付けられるのは生テキストの面だけであるため、開いた瞬間に生テキストの入力欄にすると「読む」「指摘する」「直す」の3つが同じ面に重なる。

#### Scenario: 仕様書の文書を開く

- **WHEN** 仕様書の `requirements` / `design` / `tasks` のいずれかを開く
- **THEN** その本文を直せる

#### Scenario: ステアリングの文書を開く

- **WHEN** ステアリングの `product` / `tech` / `structure` のいずれかを開く
- **THEN** その本文を直せる

#### Scenario: 未作成の文書を開く

- **WHEN** まだ作られていない文書の URL を開く
- **THEN** 未作成である旨が出て、編集の口は現れない

#### Scenario: 承認依頼から対象文書を開く

- **WHEN** 承認依頼のカードから対象文書を開く
- **THEN** 本文が整形して出る。生テキストの入力欄は出ず、編集へ入るための操作が置かれる

#### Scenario: 承認画面で対象文書を直す

- **WHEN** 承認画面で編集へ入り、本文を直して保存する
- **THEN** その文書の URL を開いても、直した内容が出る

#### Scenario: 承認依頼が編集できない文書を指している

- **WHEN** 承認依頼の対象が編集を許す6本のいずれでもない
- **THEN** 本文は読めるが、編集の口は現れない
