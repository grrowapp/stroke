# api/session Delta

## Purpose

endpoint 経由でセッションそのものを管理する場を規定する。ストロークの進行は stroke-session の管轄であり、ここではセッションの存廃——消すこと、残っているものを一覧すること——を扱う。

## ADDED Requirements

### Requirement: セッションを消す endpoint を1つ公開する

システムはセッションの削除を受け付ける endpoint を1つ公開する SHALL。削除が成立したとき、そのセッションに属するもの——セッションディレクトリ配下の状態・生成物・openspec の change——は残らない SHALL。片方だけ消えて片方が残る状態を作らない。

#### Scenario: 消す

- **WHEN** 実行中の呼び出しを持たないセッションの削除が要求される
- **THEN** そのセッションに属するものは残らず消え、以後そのセッションは存在しないものとして扱われる

#### Scenario: 存在しないセッションを消そうとする

- **WHEN** 存在しないセッション id の削除が要求される
- **THEN** システムは存在しないことを伝え、何も消さない

### Requirement: 実行中の呼び出しを持つセッションの削除は受理しない

システムは、実行中の呼び出しを持つセッションの削除を受理しない SHALL。既存の busy と同じ扱いとし、呼び出しが終わってから消せる。

#### Scenario: 実行中に消そうとする

- **WHEN** 実行中の呼び出しを持つセッションの削除が要求される
- **THEN** システムは受理せず busy であることを伝え、セッションに属するものは何も消えない

### Requirement: 残っているセッションを一覧する endpoint を1つ公開する

システムは残っているセッションの一覧を返す endpoint を1つ公開する SHALL。一覧の各件には、セッション id・phase・いつのものかが分かる時点情報が載る SHALL。

#### Scenario: 一覧する

- **WHEN** 一覧が要求される
- **THEN** 残っている全セッションについて、id・phase・時点情報が返る

#### Scenario: 何も残っていない

- **WHEN** セッションが1件も残っていない状態で一覧が要求される
- **THEN** 空の一覧が返る
