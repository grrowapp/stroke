## MODIFIED Requirements

### Requirement: 同一対象の多重起動を受け付けない

システムは、同じ対象で2つの呼び出しを同時に走らせてはならない（MUST NOT）。**起動の要求は冪等である SHALL。** 対象が既に実行中なら、その要求は満たされているものとして受理し、新しい呼び出しを開始しない。呼び手は要求を出し直さない。

**「同一対象」は、要求に使われた id ではなく、その実行の作業場所（cwd が指す物理ディレクトリ）を単位とする SHALL。** 同じ物理ディレクトリを作業場所とする呼び出しどうしは、異なる id で要求されても同一対象とみなす SHALL。昇格（`api/session/promote`）は対象の id を uuid からプロジェクト名へ変えるが、ディレクトリの実体は改名の前後で同じものである。作業場所が異なる呼び出しどうしは別の対象とし、同時に走ることを妨げてはならない（MUST NOT）。

**「実行中だから受理しない」という応答を持ってはならない（MUST NOT）。** 画面が次の起動を要求できる状態（問いへの回答・差し戻し・承認後の起動）は、いずれも前の実行の決着の後にしか立たない（`agent/invocation`）ので、実行中の対象に新しい実行を求める要求は存在しない。届くのは同じ意図の要求（画面と巡回の両方が同じ対象を起動しようとした等）だけであり、それは満たされている。

#### Scenario: 実行中に起動を要求する

- **WHEN** 実行中の呼び出しを持つ対象に起動が要求される
- **THEN** システムは受理し、新しい呼び出しは開始しない。AI は二重に起動されない

#### Scenario: 呼び出しが終わった後に再び起動を要求する

- **WHEN** 実行中だった呼び出しが終わった対象に、起動が要求される
- **THEN** システムは受理し、AI の呼び出しを開始する

#### Scenario: 画面と巡回が同じ対象を起動する

- **WHEN** 昇格の直後に画面が起動を要求し、巡回も同じ対象を起動しようとする
- **THEN** 先に届いた方が呼び出しを開始し、後の方は受理されるが新しい呼び出しは開始しない。実行は1回である

#### Scenario: 昇格の前後で同じディレクトリに起動が要求される

- **WHEN** 昇格前の id で始まった呼び出しが実行中のまま、同じ物理ディレクトリを作業場所として昇格後の id で起動が要求される
- **THEN** そのディレクトリで2つ目の呼び出しは始まらない

#### Scenario: 別のディレクトリなら同時に走る

- **WHEN** 実行中の呼び出しを持つ対象とは別のディレクトリを作業場所として起動が要求される
- **THEN** システムは受理し、AI の呼び出しを開始する
