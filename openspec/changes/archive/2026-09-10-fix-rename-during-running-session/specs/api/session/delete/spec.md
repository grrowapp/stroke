## REMOVED Requirements

### Requirement: 実行中の呼び出しを持つセッションの削除は受理しない

**Reason**: 「実行中だから受理しない（busy）」という応答を契約から無くす（`api/session/invoke-agent`「同一対象の多重起動を受け付けない」）。画面が削除の操作を出す局面は実行の決着の後であり、実行中に削除の要求が届く経路は無い。

**Migration**: 呼び手は busy を受けて出し直す処理を持たない。実行中に削除が届いたときの扱いは下の ADDED による。

## ADDED Requirements

### Requirement: 削除は実行の決着の後にしか要求されない

画面がセッションの削除の操作を出す局面——`error` に達した実行からの回復、初回起動の失敗からの回復——は、いずれも実行が終わった後である（`stroke/frontier`）。したがって削除が要求される時点で、対象に走っている呼び出しは無い SHALL。

「実行中だから受理しない」という応答を持ってはならない（MUST NOT）。実行中に削除の要求が届いたなら、それは欠陥である。システムはそれを握りつぶさず失敗として返す SHALL（ADR 0022）。リロード・複数タブ・再起動に由来する状態は後始末の問題として別に扱う。

#### Scenario: 削除の時点で実行が無い

- **WHEN** ユーザーが画面から削除を要求する
- **THEN** 対象で走っている呼び出しは無く、セッションに属するものは残らず消える
