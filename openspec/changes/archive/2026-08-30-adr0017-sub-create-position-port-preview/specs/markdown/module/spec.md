## Purpose

markdown を読める形にする働きを1つの場所に閉じ、外へ公開するものを絞る。markdown へ触る作業がどこを触ればよいのかを、参照元を辿らずに置き場だけで判別できる状態にする。

## ADDED Requirements

### Requirement: 整形された本文を描く面も位置の対応を提供する

モジュールが本文を整形して描く面は、生テキストを描く面と同じ形で位置の対応を提供しなければならない（SHALL）。

対応を使う側は、どちらの面を扱っているかによって手続きを分けてはならない（MUST NOT）。

面は対応を提供するにあたり、描画に使っている要素そのものを外へ渡してはならない（MUST NOT）。渡すと、使う側が面の内部の作りに依存できてしまう。

#### Scenario: 整形された本文の面から対応を得る

- **WHEN** 整形して描かれた本文の面に、位置の対応を求める
- **THEN** 生テキストの面と同じ2つの操作（描かれた範囲から生テキストの位置を得る／生テキストの位置から描かれた範囲を得る）が得られる

#### Scenario: 面を入れ替える

- **WHEN** 使う側が、整形された本文の面と生テキストの面を入れ替える
- **THEN** 位置の対応を得る手続きは変わらない。面の違いによる分岐が要らない

#### Scenario: 面の内部を見に行けない

- **WHEN** 対応を使う側のコードを読む
- **THEN** 面が描画に使っている要素への参照は現れない

#### Scenario: 本文が描かれていない

- **WHEN** 描く対象の本文が無い状態で、位置の対応を求める
- **THEN** 対応が得られないことが呼ぶ側に分かる。誤った範囲を返してはならない

### Requirement: 位置は面に渡された文字列の先頭を基準とする

位置の対応が返す数値は、**面に渡された文字列**の先頭から数えた文字数でなければならない（SHALL）。

ファイルに保存されている元の文字列を基準にしてはならない（MUST NOT）。両者は改行の表現や front matter の有無で食い違いうる。

改行の表現や front matter を正規化する責務がどこにあるかは、この要件では定めない。定めるのは基準がどちらであるかだけである。

#### Scenario: 渡した文字列がそのまま基準になる

- **WHEN** 面に文字列を渡し、描かれた本文の上である範囲を選ぶ
- **THEN** 返る位置は、渡したその文字列の先頭から数えた文字数である

#### Scenario: 呼ぶ側が文字列を揃えてから渡す

- **WHEN** 呼ぶ側が改行の表現を揃えた文字列を面に渡す
- **THEN** 返る位置は、揃えた後の文字列を基準とする。揃える前の文字列を基準にはしない

#### Scenario: 基準が食い違う文字列を渡す

- **WHEN** 面に渡した文字列と、位置を突き合わせたい相手の文字列が食い違っている
- **THEN** 面はそれを知らないまま、渡された文字列を基準に答える。食い違いを吸収する責務は面の外にある
