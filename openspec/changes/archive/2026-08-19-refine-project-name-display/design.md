# design — refine-project-name-display

## Context

候補の初期値は AI の提案がそのまま入り、既存プロジェクトとの突合は承認（確定）時にしか行われない。承認後の画面と承認確認には `projectPath`（`/opt/projects/<name>`）が表示されている。動機は proposal.md の Why を参照。

本 change は migrate-claude-p-to-api-endpoint と独立して成立する。候補が `PROJECT_NAME:` 行から来ても endpoint の `projectName` から来ても、画面2へ当てる際の突合は同じ場所（SessionView の組み立て）で行うため。

## Goals / Non-Goals

**Goals:**

- 画面2に出る名前候補を常に衝突しない状態にする
- 画面からパスの観念を消す

**Non-Goals:**

- 確定時の衝突確認の変更（既存規定のまま。最後の砦として残る）
- 生成の実体（`/opt/projects/<name>/` に作られること）の変更

## Decisions

### 1. 突合は SessionView を組み立てるたびに行う

候補と `/opt/projects/` の既存ディレクトリ名の突合は、画面2に出す SessionView を組み立てるたびに行う。保存済みの候補を書き換えるのではなく、表示に当てる値を毎回計算する。ストローク中に同名プロジェクトが作られても、次に画面2を開いた時点で候補は衝突していない。

- 対抗案「proposal 受領時に一度だけ突合」は、受領後に名前が取られるケース（本 change の動機）を拾えないので採らない

### 2. 衝突時は連番サフィックスで回避する

衝突した候補は `-2`, `-3`, … の連番サフィックスを付けて最初に空く名前にする。サフィックスは `-<数字>` のみなので kebab-case は保たれる。

- 対抗案「AI へ再提案させる」は、呼び出しが1回増えるだけなので採らない

### 3. 差し替えは黙って行う

候補が衝突で変わったことを知らせる表示は置かない。ユーザーにとって候補は編集して確定するだけの初期値であり、由来の説明は決定の材料にならない。

### 4. パスは画面に出さない

承認の確認は「後戻りできないこと」とプロジェクト名で示す。承認後の表示は「承認済み」と確定名で示す。`projectPath` は画面の表示に使わず、`ApproveResult` / `SessionView` から外す方向で整理する（生成の実体は project-generation の規定どおり）。

## Risks / Trade-offs

- [ユーザーが手で衝突する名前に書き換えて承認する] → 確定時の衝突確認（既存規定）が弾く。候補の突合はあくまで初期値の品質の話
- [表示のたびの突合でディレクトリ一覧を読む] → `/opt/projects/` 直下の一覧のみで浅い。MVP の規模では問題にならない

## Migration Plan

1. SessionView の組み立てに候補の突合・サフィックス回避を入れる
2. 画面2の承認確認・承認後表示からパスを除き、名前表示に変える
3. 同名ディレクトリを用意して候補の回避と確定時の衝突確認を実機で確認する

ロールバックは表示の変更を戻すだけ。保存データの形式は変えない。
