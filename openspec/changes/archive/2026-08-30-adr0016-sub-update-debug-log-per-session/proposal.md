# adr0016-sub-update-debug-log-per-session

## Why

デバッグログが呼び出しごとに1ファイルになっており、1つのセッションを追うのに複数のファイルを開くことになる。

実測 2026-08-28: 3往復のセッション1本で4ファイル（`20260828-012223-153-744aa80a-….json` 〜 `20260828-012430-777-744aa80a-….json`）。往復が増えるほどファイルが増え、時系列に読むにはファイル名の時刻で並べ直す手間がかかる。並走したセッションのファイルも同じディレクトリに混ざる。

調べる単位はセッションである。`claude-debug-logging` は「呼び出しごとに1ファイル」を Requirement に置いたが、この単位が調査の単位と合っていない。

## What Changes

- **変更**: デバッグログをセッションごとに1ファイルにし、呼び出しのたびに追記する。ファイル名からセッションを特定でき、1つ開けばそのセッションの全呼び出しを時系列で読める
- **変更**: `claude-debug-logging` の Requirement「ログは呼び出しごとに1ファイルで、上書きされない」を、記録を失わないという意図はそのままに、単位をセッションへ改める

上書き禁止の意図（前の呼び出しの記録を失わない）は追記で満たす。呼び出しの区切りが読み取れる形にする。

## Capabilities

### Modified Capabilities

- `debug/logging`: ログの単位を呼び出しからセッションへ改める。1ファイルにそのセッションの全呼び出しが時系列で入り、過去の呼び出しの記録は失われない。

## Impact

- **影響コード**: `server/utils/stroke/claude.ts`（`writeDebugLog` / `debugLogStamp`）
- **影響するテスト**: `test/server/utils/stroke/claude.test.ts`（ファイル数と名前を見ている）
- **影響しないもの**: 呼び出しの成否判定・セッションの状態・画面への応答。ログは調査用の複製であり、書き出しの失敗が呼び出しへ影響しない点も変わらない
