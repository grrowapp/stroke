# debug/logging Delta

## MODIFIED Requirements

### Requirement: デバッグログは出力先の設定があるときだけ書かれる

システムは、デバッグログの出力先が設定されているときに限り、AI 呼び出しの生出力を書き残す SHALL。出力先が未設定なら、ログの書き出しは行われない（MUST NOT）。有効/無効のフラグは出力先の設定と別に持たない。

出力先が設定されているとき、システムは**ツールの呼び出しとその結果まで残る形式**で呼び出しを行う SHALL。最終結果だけを出す形式では、失敗したツール呼び出しがどこにも残らない。形式の選択は出力先の設定の有無から導き、別の設定として外に出してはならない（MUST NOT）。

#### Scenario: 出力先が未設定なら何も書かれない

- **GIVEN** デバッグログの出力先が設定されていない
- **WHEN** ストロークの往復で AI 呼び出しが完了する
- **THEN** ログファイルはどこにも作られない（セッションディレクトリ・サーバーの作業ディレクトリを見ても呼び出しの生出力を含むファイルは増えていない）

#### Scenario: 出力先が設定されていれば書かれる

- **GIVEN** デバッグログの出力先が設定されている
- **WHEN** ストロークの往復で AI 呼び出しが完了する
- **THEN** そのセッションのログに、その呼び出しの生出力が区切り付きで残る

#### Scenario: ツールの呼び出しと結果が残る

- **GIVEN** デバッグログの出力先が設定されている
- **WHEN** AI が呼び出しの中でツールを使い、その結果を受け取る
- **THEN** ログからツールの呼び出しと結果を読み取れる。**失敗したツール呼び出しも残る**

## REMOVED Requirements

### Requirement: ログは呼び出しごとに1ファイルで、上書きされない

**Reason**: 調査の単位はセッションであって呼び出しではない。呼び出しごとに分けると、1本の往復を追うのに何枚も開くことになる（実測 2026-08-28: 3往復のセッション1本で4ファイル）。「呼び出し1回につき1ファイル」と「ファイル名は `<呼び出し時刻>-<セッション uuid>.json`」は、その目的に対して逆に働く。

**Migration**: 下の ADDED「ログはセッションごとに1ファイルで、過去の呼び出しを失わない」が置き換える。上書き禁止（`writeFile` の `wx`）が担っていた「前の記録を失わせない」は、追記（`appendFile`）が担う。既に溜まっている `<時刻>-<uuid>.json` は残したままでよい。読み替えの手当ては要らず、新しい呼び出しから `<uuid>.json` へ追記される。

## ADDED Requirements

### Requirement: ログはセッションごとに1ファイルで、過去の呼び出しを失わない

システムは、セッション1つにつきログファイルを1つ作り、そのセッションで呼び出しが完了するたびに追記する SHALL。既に書かれた呼び出しの記録を失わせてはならない（MUST NOT）。

ファイル名だけで「どのセッションのログか」が判別できる SHALL。ファイルの中では、呼び出しの区切りと順序が読み取れる SHALL。

#### Scenario: 2回の呼び出しが1ファイルに時系列で入る

- **GIVEN** デバッグログの出力先が設定されている
- **GIVEN** あるセッションで AI 呼び出しが既に1回完了し、そのセッションのログがある
- **WHEN** 同じセッションで2回目の AI 呼び出しが完了する
- **THEN** そのセッションのログファイルは1つのままで、1回目の記録は残っており、2回目がその後ろに続いている

#### Scenario: セッションで絞り込める

- **GIVEN** 複数セッションの呼び出しログが同じ出力先に溜まっている
- **WHEN** 調査者が特定セッションのログを探す
- **THEN** ファイル名からそのセッションのファイルを1つ特定でき、開けばそのセッションの全呼び出しが順に読める

#### Scenario: 呼び出しの区切りが分かる

- **GIVEN** あるセッションのログに複数回の呼び出しが入っている
- **WHEN** 調査者がそのファイルを読む
- **THEN** どこからどこまでが1回の呼び出しかを判別でき、何回目の呼び出しかが分かる
