# stroke-session Delta

## MODIFIED Requirements

### Requirement: 概要からセッションを開始する

システムは概要の投稿からセッションを1つ開始し、AI の最初の問いを表示する SHALL。投稿の受理・セッションの作成・phase の初期化は `api/overview` が規定し、AI の起動は `api/invoke-agent` が受ける。認証は行わず、単一ユーザーを前提とする。

#### Scenario: 概要を投稿する

- **WHEN** ユーザーが画面1で概要を投稿する
- **THEN** セッションが1つ作られ、phase は `stroking` となり、AI の最初の問いが表示される

#### Scenario: 概要が空のまま投稿する

- **WHEN** 概要が空のまま投稿される
- **THEN** システムはセッションを作成せず、入力が必要である旨を示す

### Requirement: ストロークの往復を進める

システムはユーザーの入力と AI の応答の1往復をストロークとして扱い、同一セッションの継続として進める SHALL。回答の受理は `api/answer` が、AI の起動は `api/invoke-agent` が規定する。

ストロークの応答待ちの待機表示の文言は「AI が次を考えています…」とする。待機表示の文言は場面ごとに規定し、示す側が与える。

#### Scenario: 問いに答える

- **WHEN** ユーザーが回答を送信する
- **THEN** 同一セッションの継続として次の問いが返り、表示される

#### Scenario: 応答を待っている

- **WHEN** AI の応答をまだ受け取っていない
- **THEN** システムは「AI が次を考えています…」で待機中であることを示し、同一セッションへの追加送信を受け付けない。待機中であることを示す文字は点滅し、動作中であることが視覚的に分かる

### Requirement: 回答は選択または自由入力で送る

システムはユーザーが選んだ選択肢、または自由入力の本文を回答として送る SHALL。回答の受理は `api/answer` が規定する。

#### Scenario: 選択肢を選んで送る

- **WHEN** ユーザーが選択肢を1つ選んで送信する
- **THEN** システムはその選択を回答として送る

#### Scenario: 自由入力で送る

- **WHEN** ユーザーが自由入力に書いて送信する
- **THEN** システムはその本文を回答として送る

#### Scenario: 何も選ばず何も書かずに送る

- **WHEN** 選択も自由入力もないまま送信操作が行われる
- **THEN** システムは送信せず、回答が必要である旨を示す
