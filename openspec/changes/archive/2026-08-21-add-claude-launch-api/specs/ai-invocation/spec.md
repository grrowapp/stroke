# ai-invocation Delta

## ADDED Requirements

### Requirement: 初回か継続かはセッション一覧との符合から導く

システムは AI を呼ぶとき、残っているセッションの一覧に符合するセッション id があるかどうかから、初回か継続かを自ら判定する SHALL。判定と渡す定型を呼び出し側から受け取らない。一覧には実体の揃ったセッション——ディレクトリがあり、openspec ルートがあり、ワークフロースキーマが設定済みのもの——だけが載る。符合しなければ初回として、実行環境（openspec ルートとスキーマ設定）を整えた上で新しい会話を開始して初回の定型を渡し、符合すれば継続として実行して続きを促す定型を渡す。

#### Scenario: 作成直後のセッションで呼ぶ

- **WHEN** 概要の受理直後で、まだ一覧に符合しないセッションで AI を呼ぶ
- **THEN** 実行環境が整えられ、新しい会話として開始され、初回の定型が渡る

#### Scenario: 一覧に符合するセッションで呼ぶ

- **WHEN** 一覧に符合するセッションで AI を呼ぶ
- **THEN** 前の往復を踏まえた継続として実行され、続きを促す定型が渡る

#### Scenario: 実行環境を整えられない

- **WHEN** 初回の起動で実行環境を整えられない
- **THEN** AI は起動されず、その呼び出しは失敗として扱われる

#### Scenario: 実行環境を作った後の初回の呼び出しが失敗し、再び起動される

- **WHEN** 実行環境を整えた後の初回の呼び出しが提出に至らず失敗し、再び起動が要求される
- **THEN** 一覧に符合するため継続として実行される。継続先の会話が無ければ、新しい会話を作り直さず、その呼び出しは失敗として扱われる

### Requirement: 定型は設定値として外に出す

システムは AI へ渡す定型（初回の定型・続きを促す定型）を設定値として外に出し、その変更をアプリのコード変更・再ビルドなしに次回の呼び出しから反映する SHALL。

#### Scenario: 定型を変更する

- **WHEN** 運用者が設定値の定型を変更し、その後に AI の呼び出しが起こる
- **THEN** 再ビルドなしに、変更後の定型が渡る

## MODIFIED Requirements

### Requirement: 同一セッションの往復は会話として継続する

システムは、初回か継続かの判定が継続となった呼び出しを、前の往復を踏まえた継続として実行する SHALL。会話履歴をアプリ側で二重に保持しない。判定そのものは「初回か継続かはセッション一覧との符合から導く」が規定する。

#### Scenario: 2往復目を送る

- **WHEN** ユーザーが同じセッションで2回目の入力を送る
- **THEN** AI は前の往復の内容を踏まえて応答する
