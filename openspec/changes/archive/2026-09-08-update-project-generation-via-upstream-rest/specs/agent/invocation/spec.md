# agent/invocation Delta

## ADDED Requirements

### Requirement: 承認の後の実行は、起動の材料を組み立てるたびに生成を依頼する

システムは、承認の後の実行（昇格したプロジェクトでの steering）を起こすとき、**起動の材料を組み立てる中で、AI を起動する前に、生成（`api/project/generate`）を依頼しなければならない（SHALL）**。依頼に渡すのはその実行の作業場所（cwd＝昇格先のプロジェクトのディレクトリ）とする SHALL。初回か継続かを問わず、起動のたびに依頼する SHALL——本家の登録は本家の再起動で消えるため、続きの起動でも依頼し直す。

生成が受理されなければ、**起動の材料を組み立てられなかった**ものとして扱う SHALL。AI は起動されず、その呼び出しは失敗として記録され（`invocation` は `failed`。上限に達していれば `error`）、起動を要求した側には起動に至らなかったことが返る（`api/session/invoke-agent`「起こせなかったときは受理しない」）。巡回が起こし直す。

生成の依頼は、呼び出し側が起動の材料を組み立てる手続きの中で行う SHALL。起動処理が工程から生成の要否を導いてはならない（MUST NOT）——「起動は1系統で、起動定義・定型・作業場所は呼び出し側が渡す」と同じ理由。起動定義・定型・その他の渡す値は変えてはならない（MUST NOT）。

承認の後の実行の起動定義に、本家 spec-workflow の MCP を含めてはならない（MUST NOT）。AI が起動時に本家の登録簿へ自分を書く経路を残すと、生成が AI のプロセスに乗ったままになる（`project/generation`「AI のプロセスにプロジェクトを生成させてはならない」）。

#### Scenario: 昇格したプロジェクトで初めて起こす

- **GIVEN** 昇格したプロジェクトで承認の後の実行がまだ一度も走っていない
- **WHEN** その対象へ起動が要求される
- **THEN** AI が起動する前に、そのプロジェクトのディレクトリで生成が依頼される。受理されてから AI が起動する

#### Scenario: 続きの起動でも依頼する

- **GIVEN** 昇格したプロジェクトで承認の後の実行が一度走り、会話の続き先が覚えられている
- **WHEN** その対象へ起動が要求される
- **THEN** AI が起動する前に生成が依頼され、受理されてから前の会話の続きとして AI が起動する

#### Scenario: 生成が受理されない

- **GIVEN** 本家 dashboard が起動していない
- **WHEN** 昇格したプロジェクトで承認の後の実行が起こされる
- **THEN** 生成の依頼が失敗し、AI は起動されず、`invocation` は `failed` になる。起動を要求した側には起動に至らなかったことが返る。巡回が起こし直し、本家が動いていればそのとき生成が受理されて AI が起動する

#### Scenario: 起動定義に本家の MCP が無い

- **WHEN** 承認の後の実行の起動の材料を組み立てる
- **THEN** AI に渡す MCP の配線は stroke-board 自身のサーバーだけで、本家 spec-workflow の MCP は含まれていない

#### Scenario: ストロークの実行では依頼しない

- **WHEN** ストロークの往復のために AI を呼ぶ
- **THEN** 生成は依頼されない。実行環境を整える手続きは従来どおり openspec ルートとスキーマ設定である
