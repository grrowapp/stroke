# portal/relative-time Delta

## Purpose

一覧に出る「最終更新」などの相対時刻（「19時間前」「8月9日 14:40」）の表示規定を定める。

## ADDED Requirements

### Requirement: 相対時刻はサーバーで描いた結果とブラウザで描き直した結果が一致する

システムは、同じ対象の相対時刻について、サーバーで描いた文言とブラウザで描き直した文言を一致させる SHALL。描画の基準となる「現在時刻」を、両者で別々に決めてはならない（MUST NOT）。

#### Scenario: 刻みの境界をまたいでも表示が入れ替わらない

- **GIVEN** 最終更新が「19時間前」と表示される時点にある対象が一覧にある
- **GIVEN** サーバーが描いてからブラウザが描き直すまでの間に、その対象が「20時間前」に変わる時刻を跨ぐ
- **WHEN** 利用者がその一覧を開く
- **THEN** 表示は片方に定まり、描き直しで文言が入れ替わらない

#### Scenario: 相対と絶対の切り替わりでも一致する

- **GIVEN** 最終更新が7日の境界にある対象が一覧にある（相対表示と絶対日時が切り替わる位置）
- **WHEN** 利用者がその一覧を開く
- **THEN** サーバーが描いた表示とブラウザが描き直した表示が同じ形式（どちらも相対、またはどちらも絶対）になる

#### Scenario: ブラウザの時計がサーバーとずれていても一致する

- **GIVEN** 一覧を開くブラウザが別のマシンにあり、その時計がサーバーより数分以上進んでいる、または遅れている
- **WHEN** 利用者がその一覧を開く
- **THEN** 描き直しの表示はサーバーが描いた表示と一致する。ブラウザの時計は描き直しの基準にならない

### Requirement: 相対時刻の不一致で描画の警告を出さない

システムは、相対時刻の表示を理由に描き直しの不一致を発生させてはならない（MUST NOT）。

不一致は表示のちらつきに留まらない。開発時のログに対象の要素構造がそのまま書き出され、調査に要る記録が埋もれる。

#### Scenario: 一覧を開いても相対時刻を理由とする不一致の警告が出ない

- **GIVEN** 最終更新の列を持つ一覧がある
- **GIVEN** 開くブラウザの時計がサーバーとずれている
- **WHEN** 利用者がその一覧を開く
- **THEN** 相対時刻の列を理由とする描き直しの不一致は報告されず、開発時のログに一覧の要素構造のダンプが出ない
