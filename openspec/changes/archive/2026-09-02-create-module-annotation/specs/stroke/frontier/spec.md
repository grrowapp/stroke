## ADDED Requirements

### Requirement: proposal の見せ方は2つで、どちらでも指摘を付けられる

システムは proposal の見せ方として、整形されたプレビューと素の本文の2つを用意する SHALL。その両方を並べた表示を用意してはならない（MUST NOT）。並べた表示は、読む面と指摘する面が別だったことに由来する。どちらの見せ方でも指摘を付けられる以上、並べる理由が無い。

指摘はどちらの見せ方でも付けられる SHALL。片方を読むだけに限り、指摘を付けられない状態にしてはならない（MUST NOT）。指摘を付けるためだけに見せ方を切り替えさせてはならない（MUST NOT）。

どちらの見せ方で付けた指摘も、もう一方の見せ方にも出る SHALL。どちらで付けたかによって、出る／出ないが変わってはならない（MUST NOT）。一方で取り消した指摘は、もう一方からも消える SHALL。

見せ方が変わっても、指摘が保持する箇所は変わってはならない（MUST NOT）。箇所は素の本文における位置1本で持ち、見せ方ごとに別の持ち方をしない。

#### Scenario: 見せ方を切り替える

- **WHEN** ユーザーが見せ方を切り替える
- **THEN** 同じ proposal が、選んだ見せ方で表示される

#### Scenario: 選べる見せ方は2つ

- **WHEN** ユーザーが見せ方の選択肢を見る
- **THEN** 整形されたプレビューと素の本文の2つがあり、両方を並べた表示は無い

#### Scenario: 整形されたプレビューで指摘を付ける

- **WHEN** 整形されたプレビューを見ている状態で、本文の一部を選んで指摘を書く
- **THEN** 見せ方を切り替えることなく、選んだ箇所に指摘が付く

#### Scenario: 素の本文で指摘を付ける

- **WHEN** 素の本文を見ている状態で、本文の一部を選んで指摘を書く
- **THEN** 選んだ箇所に指摘が付く

#### Scenario: 付けた指摘がもう一方の見せ方にも出る

- **GIVEN** 一方の見せ方で proposal 本文の箇所に指摘を付けた
- **WHEN** もう一方の見せ方へ切り替える
- **THEN** 対応する箇所に同じ指摘が出ており、一覧の中身も変わらない

## REMOVED Requirements

### Requirement: proposal の見せ方を切り替えられる

**Reason**: 見せ方を3つ（整形されたプレビュー / 素の本文 / その両方を並べた表示）とし、指摘を付けられるのは素の本文の側だけとしていた要件である。並べた表示を落として見せ方を2つにし、どちらでも指摘を付けられるようにするため、この要件の前提そのものが無くなる。Scenario「プレビューでは指摘を付けない」は新しい振る舞いと正面から食い違うので、MODIFIED として持ち越さず、要件ごと置き換える。

**Migration**: 「proposal の見せ方は2つで、どちらでも指摘を付けられる」が引き継ぐ。見せ方を切り替えられること（Scenario「見せ方を切り替える」）はそのまま移してあり、失われる操作は無い。並べた表示でできたことは、どちらの見せ方でもできる。
