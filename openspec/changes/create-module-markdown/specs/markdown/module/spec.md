## Purpose

markdown を読める形にする働きを1つの場所に閉じ、外からは決まった口だけで使えるようにする。markdown へ触る作業がどこを触ればよいのかを、参照元を辿らずに置き場だけで判別できる状態にする。

## ADDED Requirements

### Requirement: markdown を扱う実体はモジュールの内側にだけ在る

markdown の解釈・描画・見た目の指定は、markdown モジュールの内側にだけ置かなければならない（SHALL）。モジュールの外に、markdown を解釈する仕組みの設定、フェンスの扱い、本文の見た目の指定を持ってはならない（MUST NOT）。

markdown の扱いを変える作業の影響が、モジュールの外へ及んではならない（MUST NOT）。

#### Scenario: 本文の見た目を変える

- **WHEN** markdown 本文の見た目を変える
- **THEN** 変更はモジュールの中だけで完結し、画面側のファイルは変わらない

#### Scenario: フェンスの扱いを変える

- **WHEN** コードブロックや図の出し方を変える
- **THEN** 変更はモジュールの中だけで完結する

#### Scenario: モジュールの外に markdown の設定が残っている

- **WHEN** モジュールの外に markdown の解釈の設定が置かれている
- **THEN** その配置は本要件に反しており、モジュールへ移す対象になる

### Requirement: 本文を出す口はモジュールが公開する

画面が markdown 本文を出すときは、モジュールが公開する口を通さなければならない（SHALL）。画面が markdown を解釈する仕組みを直接呼んではならない（MUST NOT）。

同じ文書は、どの画面から出しても同じ形で出なければならない（SHALL）。

#### Scenario: 新しい画面で文書を出す

- **WHEN** 新しい画面で markdown 本文を出す
- **THEN** モジュールの口に本文を渡すだけで、markdown の解釈の設定を画面側に書かずに済む

#### Scenario: 複数の画面で同じ文書を出す

- **WHEN** 同じ文書を別々の画面から出す
- **THEN** 見出し・表・コードブロック・図のいずれも同じ形で出る

### Requirement: 文書を直す口もモジュールが公開する

文書を直す面（生テキストの入力と、整形した本文の確認）は、モジュールが公開する口として提供しなければならない（SHALL）。直す面を画面ごとに組み立ててはならない（MUST NOT）。

保存の実行と保存先の決定はモジュールの責務ではなく、口の外側に置かなければならない（SHALL）。

#### Scenario: 文書を直す面を置く

- **WHEN** 画面に文書を直す面を置く
- **THEN** モジュールの口を置くだけで、入力欄と整形した本文の確認が揃う

#### Scenario: 保存先が画面ごとに違う

- **WHEN** 保存先の違う画面が同じ直す面を使う
- **THEN** 直す面は同じもので済み、保存の実行だけが画面ごとに異なる

### Requirement: 描いた本文と生テキストの位置の対応を公開する

モジュールは、整形して描いた本文の範囲と、その元になった生テキストの位置との対応を、外から引ける形で公開しなければならない（SHALL）。

対応は双方向でなければならない（SHALL）。整形された本文の上で選ばれた範囲から生テキストの位置を得られ、生テキストの位置から整形された本文の範囲を得られること。

位置は、**面に渡された**生テキストの先頭から数えた文字数で表さなければならない（SHALL）。ファイルに保存されている元の文字列を基準にしてはならない（MUST NOT） — 改行の表現や front matter の有無で、両者は食い違いうる。基準そのものの規定は `markdown/module` の要件「位置は面に渡された文字列の先頭を基準とする」に置く。

対応を得る側が、markdown の解釈の仕組み・フェンスの扱い・見た目の指定を知る必要があってはならない（MUST NOT）。

#### Scenario: 整形された本文で範囲を選ぶ

- **WHEN** 整形して描かれた本文の上である範囲を選ぶ
- **THEN** その範囲に対応する生テキストの位置（開始と終了の文字数）が得られる

#### Scenario: 生テキストの位置から本文の範囲を得る

- **WHEN** 生テキストの位置を渡す
- **THEN** 整形された本文の上でその位置が指す範囲が得られる

#### Scenario: 記号を伴う箇所を選ぶ

- **GIVEN** 生テキストに `**強調**` のように記号を伴う書き方が含まれる
- **WHEN** 整形された本文の上でその強調部分を選ぶ
- **THEN** 記号を含む生テキストの位置が得られ、記号の分だけずれることはない

#### Scenario: 要素をまたいで選ぶ

- **WHEN** 整形された本文の上で、段落・強調・リンクの境界をまたいで選ぶ
- **THEN** 生テキストの上で連続した1つの範囲が得られる

#### Scenario: 文書の冒頭を選ぶ

- **WHEN** 文書のいちばん先頭から始まる範囲を選ぶ
- **THEN** 生テキストの位置は 0 から始まる範囲として得られ、位置が得られないことにはならない

#### Scenario: 対応が取れない箇所を指す

- **WHEN** 生テキストとの対応が取れない箇所の位置を渡す
- **THEN** 対応が取れないことが呼ぶ側に分かる。誤った範囲を返してはならない

#### Scenario: 対応を使う側の依存

- **WHEN** 対応を使う側のコードを読む
- **THEN** markdown の解釈の仕組みへの参照は現れず、位置の口だけを見ている

### Requirement: 図として描かれる箇所は元の生テキストを添えられる

図として描かれるコードブロックは、描かれた図に元の生テキストを添えられなければならない（SHALL）。図を消して生テキストに置き換えてはならない（MUST NOT） — 図は読むためのものであり、位置を指せるようにするために失わせない。

添えられた生テキストも、本文と同じ位置の対応を提供しなければならない（SHALL）。図の中の文字は画像であって位置を持たないため、対応を保てる場所は添えられた生テキストの上だけである。

生テキストを添えても、本文の他の箇所の位置と見え方が動いてはならない（MUST NOT）。

#### Scenario: 見せたい範囲が図と重なる

- **WHEN** 図として描かれるコードブロックの範囲と、外から渡された「元の生テキストを見せたい範囲」が重なる
- **THEN** 図はそのまま残り、元の生テキストが添えられる

#### Scenario: 見せたい範囲が図と重ならない

- **WHEN** 外から渡された範囲が、その図のコードブロックと重ならない
- **THEN** 生テキストは添えられず、図だけが描かれる

#### Scenario: 添えられた生テキストの上で範囲を選ぶ

- **WHEN** 図に添えられた生テキストの上で範囲を選ぶ
- **THEN** 本文と同じ形で生テキストの位置が得られる

#### Scenario: 生テキストが添えられても本文が動かない

- **WHEN** ある図に生テキストが添えられる
- **THEN** 本文の他の箇所の位置と見え方は変わらない

### Requirement: 元の生テキストを見せたい範囲は外から受け取る

モジュールは「元の生テキストを見せたい範囲」を、本文を出す口を通じて外から受け取らなければならない（SHALL）。

受け取った範囲は、その口の内側で描かれる部品まで届かなければならない（SHALL）。本文の中に何が現れるかは markdown の解釈の結果として決まるため、外から個々の部品へ直接渡す経路は存在しない。

モジュールは、受け取った範囲が何を意味するか（注釈なのか、検索の当たりなのか）を知ってはならない（MUST NOT）。範囲を渡す側が、その意味を持つ。

#### Scenario: 範囲を渡す

- **WHEN** 本文を出す口に「元の生テキストを見せたい範囲」を渡す
- **THEN** その範囲と重なる図に、元の生テキストが添えられる

#### Scenario: 範囲を渡さない

- **WHEN** 範囲を渡さずに本文を出す
- **THEN** 図はすべてそのまま描かれ、生テキストは添えられない

#### Scenario: 範囲の意味に依存しない

- **WHEN** モジュールの実装を読む
- **THEN** 注釈という語や注釈の持つ構造への参照は現れず、範囲の並びだけを見ている
