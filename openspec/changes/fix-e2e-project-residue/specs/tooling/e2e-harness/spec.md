## Purpose

E2E を走らせる土台の振る舞いを定める。テストが何を確かめるかではなく、**その確かめが信用できる条件**を土台の側の約束として持つ。

## ADDED Requirements

### Requirement: 実行は既知の保存先から始まる

土台は、1回の実行を始めるとき、**前の実行が保存先に何を残していても**、それに影響されない状態から始めなければならない（SHALL）。前の実行の残りが、次の実行のテストの結果に現れてはならない（MUST NOT）。

既知の状態に戻すのは**実行の始まり**でなければならない（SHALL）。実行の終わりに片付ける形を既定にしてはならない（MUST NOT）——途中で落ちた・止められた実行は終わりを通らず、その残りが次の実行を壊す。加えて、落ちた実行が残したものは次の実行が始まるまで残り、人が調べられる。

戻す範囲は、土台が使い捨てと定めた保存先の**全体**でなければならない（SHALL）。名前の規約で選んで消す形にしてはならない（MUST NOT）——規約から外れた残りを見逃す。

#### Scenario: 前の実行がプロジェクトを残した

- **GIVEN** 前の実行が、後始末に失敗して承認済みのプロジェクトを保存先に残した
- **WHEN** 次の実行を始める
- **THEN** 一覧に並ぶプロジェクトは、この実行が種をまいたものだけである。前の実行が残したものは一覧に現れない

#### Scenario: 前の実行が途中で止められた

- **GIVEN** 前の実行が途中で強制終了され、後始末を一切通らなかった
- **WHEN** 次の実行を始める
- **THEN** 次の実行の結果は、正常に終わった実行の後に始めた場合と同じである

#### Scenario: 落ちた実行の残りを調べる

- **GIVEN** ある実行が落ち、保存先に残りがある
- **WHEN** 次の実行を始める前にその保存先を見る
- **THEN** 落ちた実行が残したものがそのまま在り、何が残ったかを調べられる

### Requirement: 後始末の失敗は握り潰さない

テストが自分の作ったものを片付ける手順は、片付けが**受理されなかった**とき、その事実を**同じ実行の結果に**出さなければならない（SHALL）。失敗を捨てて緑のまま終えてはならない（MUST NOT）——残りは次の実行で、無関係なテストの失敗としてしか現れず、原因が読めない。

出す内容には、**何を消そうとして、どう断られたか**（応答の状態と本文）が含まれていなければならない（SHALL）。「消せなかった」だけでは、口が弾いたのか届かなかったのかが分からない。

対象が既に無いことは失敗ではない（SHALL NOT）。ただしそれは、消す直前に対象が在ることを確かめた上での「既に無い」に限る。

#### Scenario: 削除が断られる

- **GIVEN** テストが承認でプロジェクトを作った
- **WHEN** 片付けの削除が受理されない（busy・局面の不一致・その他）
- **THEN** そのテストは失敗として報告され、報告には削除の応答の状態と本文が含まれる

#### Scenario: 対象が既に無い

- **GIVEN** 片付けの直前に対象が在ることを確かめた
- **WHEN** 削除が「無い」と応える
- **THEN** 片付けは済んだものとして扱い、テストは通る
