## MODIFIED Requirements

### Requirement: 画面の階層に属さない機能は `modules/` に置く

画面の階層（上層ポータル / 下層ワークスペース）に属さず、それ自体で完結する機能は、リポジトリルートの `modules/` に、機能ごとのディレクトリを作って置かなければならない（SHALL）。

`modules/` に置いてよいのは、次のすべてを満たすものに限る（SHALL）。

- 画面の階層に依存しない。どの階層から参照されても同じように働く
- 外へ公開するものが定まっており、外がその内側の作りを知らずに使える
- 内側の作りを変えても、公開するものが同じであれば外が変わらない

上記を満たさないものを `modules/` に置いてはならない（MUST NOT）。画面の都合や特定のページの事情を持つものは、これまでどおり `app/components/` の階層ディレクトリ、または `app/composables/` の直下に置く。

`modules/` に置いたものの実体を、`app/` の側に重複して持ってはならない（MUST NOT）。

**`modules/` の機能を外部 package として配ることにしたときは、その実体をこのリポジトリから消さなければならない（SHALL）。** `modules/<機能名>/` と外部 package の両方に実体を持ってはならない（MUST NOT）——上の「実体を重複して持たない」と同じ理由で、2つ在れば片方が古くなり、どちらが動いているかを読んで判別できなくなる。

外部 package として配るものは、依存として宣言し、アプリの設定の module の並びへ明示して並べなければならない（SHALL）。

#### Scenario: 階層に依存しない機能を追加する

- **WHEN** どの階層から参照されても同じように働き、公開するものが定まっている機能を追加する
- **THEN** そのファイルは `modules/<機能名>/` に置かれ、`app/components/` にも `app/composables/` にも置かれない

#### Scenario: 画面の都合を持つ部品を追加する

- **WHEN** 特定のページの事情に依存する部品を追加する
- **THEN** そのファイルは `modules/` ではなく、階層ディレクトリに置かれる

#### Scenario: モジュールの内側を変える

- **WHEN** `modules/<機能名>/` の内側の作りを変え、公開するものを変えない
- **THEN** `app/` 配下のファイルは変わらない

#### Scenario: 機能を外部 package として配る

- **WHEN** `modules/<機能名>/` の機能を外部 package として配ることにする
- **THEN** `modules/<機能名>/` はこのリポジトリから消え、その package が依存として宣言され、アプリの設定の module の並びに現れる

#### Scenario: 実体が両方に在る

- **WHEN** 外部 package として配っている機能の実体が `modules/<機能名>/` にも残っている
- **THEN** その配置は本要件に反しており、片方を消す対象になる

### Requirement: モジュールの参照は明示 import で行う

モジュールの参照は `~/components/<階層>/<名前>` および `~/composables/<名前>` の形の明示 import で行わなければならない（SHALL）。Nuxt の auto-import に依存してはならない（MUST NOT）。

`modules/` に置かれたもの、および外部 package として配られるものの参照も、そのモジュールが公開するものを指す明示 import で行わなければならない（SHALL）。モジュールの内側のファイルを直接指す import を書いてはならない（MUST NOT）。

**公開するものを指す import の形は、実体が `modules/` に在るか外部 package に在るかで変えてはならない（MUST NOT）。** 配り方が変わっても参照元のファイルが変わらないようにするためであり、実際に `markdown/module` は `#markdown` の形を切り出しの前後で保つ。

この制約により、ディレクトリの移動が Nuxt の規約による名前解決に影響せず、参照関係が grep で機械的に追跡できる。

#### Scenario: モジュールを参照する

- **WHEN** ページまたはコンポーネントが別のモジュールを使う
- **THEN** そのファイルの先頭に階層を含むパスの import 文があり、どの階層のモジュールに依存しているかがファイル単体で読み取れる

#### Scenario: ディレクトリを移動する

- **WHEN** モジュールを別の階層ディレクトリへ移す
- **THEN** 影響範囲は import パスを書いているファイルに限られ、grep で網羅的に特定できる

#### Scenario: `modules/` の機能を参照する

- **WHEN** ページまたはコンポーネントが `modules/` の機能を使う
- **THEN** そのファイルの先頭に、その機能が公開するものを指す import 文があり、内側のファイルを直接指す import は現れない

#### Scenario: 機能が外部 package へ移る

- **WHEN** `modules/` に在った機能が外部 package として配られるようになる
- **THEN** 参照元のファイルの import 文は変わらない
