## MODIFIED Requirements

### Requirement: markdown を扱う実体はモジュールの内側にだけ在る

markdown の解釈・描画・見た目の指定は、markdown モジュールの内側にだけ置かなければならない（SHALL）。**モジュールの実体は、このリポジトリの外の package として配られる。** アプリのリポジトリに、markdown を解釈する仕組みの設定、フェンスの扱い、本文の見た目の指定を持ってはならない（MUST NOT）。

markdown の扱いを変える作業の影響が、モジュールの外へ及んではならない（MUST NOT）。

見た目の指定は、モジュールが依存する UI ライブラリの theme を通じて持たなければならない（SHALL）。UI ライブラリが提供する見た目を打ち消す指定を、モジュールが自前で持ってはならない（MUST NOT）——打ち消しが入ると、モジュールを使う側が theme で見た目を変える経路が働かなくなる。

#### Scenario: 本文の見た目を変える

- **WHEN** markdown 本文の見た目を変える
- **THEN** 変更はモジュールの中だけで完結し、画面側のファイルは変わらない

#### Scenario: フェンスの扱いを変える

- **WHEN** コードブロックや図の出し方を変える
- **THEN** 変更はモジュールの中だけで完結する

#### Scenario: モジュールの外に markdown の設定が残っている

- **WHEN** モジュールの外に markdown の解釈の設定が置かれている
- **THEN** その配置は本要件に反しており、モジュールへ移す対象になる

#### Scenario: 使う側が本文の見た目を変える

- **WHEN** モジュールを使う側が、UI ライブラリの theme で本文の見た目を上書きする
- **THEN** その上書きが本文に効く。モジュールの自前の指定に打ち消されない

## ADDED Requirements

### Requirement: モジュールは使う側の module の並びに明示して置かれる

モジュールを使う側は、アプリの設定の module の並びへモジュールを明示して並べなければならない（SHALL）。ディレクトリの自動読み込みで入ることを当てにしてはならない（MUST NOT）——モジュールの実体はアプリのリポジトリの外に在り、自動読み込みの対象に現れない。

モジュールは、依存する UI ライブラリより**前**に並べなければならない（SHALL）。UI ライブラリは自分の setup の時点で markdown の解釈の仕組みが入っているかを見て、本文の見た目を担う部品を登録するかどうかを決める。後ろに並べると、その判定が行われた後にモジュールが走ることになり、部品が登録されない。

並びが逆でもアプリは落ちず、本文の見た目だけが失われる。合図が出ないため、並びは規定として持ち、テストで確かめる。

#### Scenario: 並びが正しい

- **WHEN** モジュールを UI ライブラリより前に並べてアプリを起動する
- **THEN** 本文が UI ライブラリの部品で描かれ、見た目が効いている

#### Scenario: 並びが逆になっている

- **WHEN** モジュールを UI ライブラリより後ろに並べてアプリを起動する
- **THEN** 本文を描く部品が登録されず、見た目が失われる。この並びは本要件に反している

#### Scenario: 並びに書かずに置く

- **WHEN** アプリの設定の module の並びにモジュールを書かない
- **THEN** モジュールは入らない。自動読み込みで入ることを当てにした配置は本要件に反している

### Requirement: 見た目の取り込みは1行で済む

モジュールが持つ本文の見た目は、使う側が**1行の取り込み**だけで有効にできなければならない（SHALL）。

使う側に、モジュールの中のファイルを指す path を書かせてはならない（MUST NOT）。モジュールの実体はアプリのリポジトリの外に在り、相対 path は当たらない。

CSS のクラスを生成するための走査の指定は、モジュールが自分の CSS の中に持たなければならない（SHALL）。使う側が走査の範囲にモジュールを足す手続きを持ってはならない（MUST NOT）。

#### Scenario: 見た目を取り込む

- **WHEN** 使う側がモジュールの CSS を1行で取り込む
- **THEN** 本文の見た目が効く。ほかに書く行は無い

#### Scenario: モジュールの中だけが名乗るクラス

- **GIVEN** モジュールの中だけで使われているクラスがある
- **WHEN** アプリをビルドする
- **THEN** そのクラスは生成されている。使う側が走査の指定を足す必要は無い

#### Scenario: 使う側が path を書いている

- **WHEN** 使う側の CSS に、モジュールの中のファイルを指す相対 path が書かれている
- **THEN** その記述は本要件に反しており、取り除く対象になる

### Requirement: 設定は既定値だけで使える

モジュールは、受け取る設定の名前と既定値を公開しなければならない（SHALL）。

使う側は、設定を1つも書かずにモジュールを使えなければならない（SHALL）。既定値のままで、本文の描画・文書の編集・位置の対応のすべてが働くこと。

既定値で働く以上、使う側の設定資料にモジュールの設定を書き写してはならない（MUST NOT）——書く値が無いものを資料に載せると、資料と実態のどちらが正かを突き合わせられなくなる。

#### Scenario: 設定を書かずに使う

- **WHEN** 使う側が設定を1つも書かずにモジュールを入れる
- **THEN** 本文の描画・文書の編集・位置の対応が既定値で働く

#### Scenario: 設定を変える

- **WHEN** 使う側が公開された設定の名前で値を書く
- **THEN** その値が効く。モジュールの中のファイルを書き換える必要は無い
