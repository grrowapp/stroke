## Purpose

文書へ指摘を付ける働きを1つの場所に閉じ、markdown をどう描いているかを知らずに済むようにする。読んでいる面が生テキストでも整形された本文でも、同じ注釈を付けられ、同じ注釈が見える状態にする。

## ADDED Requirements

### Requirement: 注釈は生テキストの位置で1本に持つ

注釈の位置は、対象文書の生テキストの先頭からの文字数（開始と終了）で持たなければならない（SHALL）。

面ごとに別の位置の持ち方をしてはならない（MUST NOT）。整形された本文の上の位置、要素の順番、見出しの番号など、描き方に依存する持ち方をしてはならない（MUST NOT）。

注釈は、位置に加えて、その位置が指す生テキストの引用を持たなければならない（SHALL）。

#### Scenario: 注釈を保存する

- **WHEN** 注釈を付けて差し戻す
- **THEN** 送られる注釈は生テキストの位置と引用を持ち、どちらの面で付けたかは含まれない

#### Scenario: 同じ語が本文に何度も現れる

- **GIVEN** 同じ語が本文の複数箇所に現れる
- **WHEN** そのうち1箇所を選んで注釈を付ける
- **THEN** 選んだ箇所だけに注釈が付き、他の箇所には付かない

### Requirement: 本文には範囲の色だけを出し、コメントは脇の一覧に置く

システムは、注釈の付いた範囲を本文の上で色によって示さなければならない（SHALL）。コメントの本文を本文の中に差し込んではならない（MUST NOT）。

コメントの本文は、本文の脇の一覧に置かなければならない（SHALL）。一覧は、どの面を見ているかにかかわらず出したままでなければならない（SHALL）。

本文の上の色と、一覧の中のコメントは、互いに辿れなければならない（SHALL）。

#### Scenario: 注釈を付ける

- **WHEN** 本文の範囲を選んでコメントを書く
- **THEN** 本文にはその範囲の色が付き、コメントの本文は脇の一覧に現れる

#### Scenario: 面を切り替える

- **WHEN** 見ている面を切り替える
- **THEN** 脇の一覧はそのまま出ており、コメントは消えない

#### Scenario: 一覧から本文の箇所へ辿る

- **WHEN** 脇の一覧のコメントを選ぶ
- **THEN** 本文のどの範囲を指しているかが分かる

#### Scenario: 本文から一覧のコメントへ辿る

- **WHEN** 本文の色の付いた範囲を選ぶ
- **THEN** 脇の一覧のどのコメントに当たるかが分かる

### Requirement: 注釈はどの面でも付けられる

システムは、生テキストの面と、整形された本文の面の双方で注釈を付けられるようにしなければならない（SHALL）。

いずれかの面を「読むだけ」に限り、注釈を付けられない状態にしてはならない（MUST NOT）。注釈を付けるためだけに面を切り替えさせてはならない（MUST NOT）。

#### Scenario: 整形された本文で注釈を付ける

- **WHEN** 整形された本文の面で範囲を選び、コメントを書く
- **THEN** その範囲に注釈が付く

#### Scenario: 生テキストで注釈を付ける

- **WHEN** 生テキストの面で範囲を選び、コメントを書く
- **THEN** その範囲に注釈が付く

#### Scenario: 読んだ面のまま指摘する

- **GIVEN** 整形された本文を読んでいる
- **WHEN** 気になった箇所へ指摘を付ける
- **THEN** 面を切り替えずにその場で付けられる

### Requirement: 面は2つに限る

システムは、対象文書を見せる面を、整形された本文と生テキストの2つに限らなければならない（SHALL）。両方を左右に並べて見せる面を持ってはならない（MUST NOT）。

並べて見せる面は、読む面と指摘する面が別だったことに由来する。どちらの面でも指摘を付けられる以上、並べる理由が無い。面を増やすと、注釈がどの面に出るかの組み合わせも増える。

#### Scenario: 面を選ぶ

- **WHEN** 承認画面で面を切り替える
- **THEN** 選べるのは整形された本文と生テキストの2つで、両方を並べる面は無い

#### Scenario: 並べて見ていた人が開き直す

- **GIVEN** 以前は並べて見せる面が選べた
- **WHEN** 承認画面を開く
- **THEN** 面は2つで、注釈はどちらの面でも付けられ、失われた操作は無い

### Requirement: 付けた注釈はどちらの面にも出る

システムは、付けた注釈を、生テキストの面と整形された本文の面の双方に出さなければならない（SHALL）。

どちらの面で付けたかによって、出る／出ないが変わってはならない（MUST NOT）。

#### Scenario: 整形された本文で付けて生テキストへ移る

- **GIVEN** 整形された本文の上で注釈を付けた
- **WHEN** 生テキストの面へ切り替える
- **THEN** 対応する箇所に同じ注釈が出る

#### Scenario: 生テキストで付けて整形された本文へ移る

- **GIVEN** 生テキストの上で注釈を付けた
- **WHEN** 整形された本文の面へ切り替える
- **THEN** 対応する箇所に同じ注釈が出る

#### Scenario: 注釈を消す

- **WHEN** 一方の面で注釈を消す
- **THEN** もう一方の面からも消える

### Requirement: 範囲が要素をまたいでも注釈を付けられる

システムは、整形された本文の上で強調・リンク・見出しなどの境界をまたいで選ばれた範囲にも、注釈を付けられるようにしなければならない（SHALL）。

注釈を付けることで本文の要素の構造が変わってはならない（MUST NOT）。注釈の有無によって本文の見え方（改行位置・字間・折り返し）が変わってはならない（MUST NOT）。

#### Scenario: 強調をまたいで選ぶ

- **WHEN** 整形された本文で、強調の途中から次の段落の途中までを選んで注釈を付ける
- **THEN** その範囲に注釈が付き、強調や段落の表示は崩れない

#### Scenario: 注釈を付ける前後で本文が動かない

- **WHEN** 本文に注釈を付ける
- **THEN** 本文の改行位置と折り返しは注釈を付ける前と変わらない

### Requirement: フェンスの内側にも注釈を付けられる

システムは、コードブロックの内側の任意の範囲に注釈を付けられるようにしなければならない（SHALL）。フェンス全体を指す注釈しか付けられない状態にしてはならない（MUST NOT）。

コードブロックの内側に付けた注釈は、生テキストの面と整形された本文の面の双方で、その範囲を指して出なければならない（SHALL）。

#### Scenario: コードブロックの一部に注釈を付ける

- **WHEN** 整形された本文のコードブロックの中で、ある行の一部を選んで注釈を付ける
- **THEN** その範囲に注釈が付き、生テキストの面でも同じ範囲を指す

#### Scenario: 言語の指定が無いコードブロック

- **WHEN** 言語を指定していないコードブロックの中の一部を選んで注釈を付ける
- **THEN** その範囲に注釈が付く

#### Scenario: コードブロックをまたいで選ぶ

- **WHEN** コードブロックの手前の段落から、コードブロックの中ほどまでを選んで注釈を付ける
- **THEN** 生テキストの上で連続した1つの範囲に注釈が付く

### Requirement: 図として描かれる箇所にも文字単位で注釈を付けられる

図として描かれる箇所は、整形された本文の面で文字を持たない。システムは、この箇所の注釈を図全体に丸めてはならない（MUST NOT）。付けたときの範囲を、どちらの面でも文字単位で示さなければならない（SHALL）。

そのため、整形された本文の面は、注釈が付いている図について、その図のもとになった生テキストを併せて示さなければならない（SHALL）。併せて示す生テキストは、生テキストの面と同じように範囲を選べ、同じように注釈が出るものでなければならない（SHALL）。

図そのものを消して生テキストに置き換えてはならない（MUST NOT）。注釈が1件も付いていない図に生テキストを添えてはならない（MUST NOT）。

#### Scenario: 図の中の一語に注釈を付ける

- **GIVEN** 生テキストの面で、図として描かれる箇所の中の一語に注釈を付けた
- **WHEN** 整形された本文の面へ切り替える
- **THEN** 図が出たうえで、そのもとになった生テキストが添えられ、付けた一語だけが注釈として示される

#### Scenario: 整形された本文で図に注釈を付ける

- **WHEN** 整形された本文の面で、図に添えられた生テキストの一部を選んで注釈を付ける
- **THEN** 選んだ範囲だけを指す注釈が付き、図全体に広がらない

#### Scenario: 注釈の付いていない図

- **WHEN** 注釈が1件も付いていない図を整形された本文の面で見る
- **THEN** 図だけが出て、生テキストは添えられない

#### Scenario: 図に付けた注釈を差し戻しで送る

- **GIVEN** 図の中の一語に注釈を付けた
- **WHEN** 差し戻しで送る
- **THEN** 送られる位置は付けたときの範囲のままで、図全体に広がってはいない

#### Scenario: 注釈を付けても本文の他の箇所が動かない

- **WHEN** 図に注釈を付ける
- **THEN** 生テキストが添えられても、本文の他の箇所の位置は変わらない

### Requirement: 重なった注釈はすべて本文上に現れる

システムは、範囲が重なった注釈を、すべて本文の上で判別できるように出さなければならない（SHALL）。

範囲が完全に他の注釈へ飲み込まれている注釈、および同一範囲の2件目以降を、本文の上から消してはならない（MUST NOT）。

本文のどの文字も、重なりの数にかかわらず1回だけ描かれなければならない（SHALL）。

#### Scenario: 範囲が重なる注釈を2件付ける

- **WHEN** 一部が重なる範囲に注釈を2件付ける
- **THEN** 重なった部分でも2件あることが本文の上で分かる

#### Scenario: 飲み込まれた注釈

- **GIVEN** ある注釈の範囲が、別の注釈の範囲に完全に含まれている
- **WHEN** 本文を見る
- **THEN** 内側の注釈も本文の上に現れる

#### Scenario: 同一範囲に2件

- **WHEN** まったく同じ範囲に注釈を2件付ける
- **THEN** 2件あることが本文の上で分かる

### Requirement: 注釈は markdown の描き方を知らない

注釈を扱う実体は、markdown の解釈の仕組み・フェンスの扱い・本文の見た目の指定に依存してはならない（MUST NOT）。依存してよいのは、生テキストと、描いた本文と生テキストの位置の対応だけである（SHALL）。

markdown の描き方が変わっても、注釈の実体を変えずに済まなければならない（SHALL）。

#### Scenario: markdown の描き方を変える

- **WHEN** markdown の解釈や見た目の指定を変える
- **THEN** 注釈を扱う実体は変わらない

#### Scenario: 注釈の実体を読む

- **WHEN** 注釈を扱う実体のコードを読む
- **THEN** markdown を解釈する仕組みへの参照は現れない
