## MODIFIED Requirements

### Requirement: 手順は3文書の作り方と終わり方を含む

手順の本文は、次を含む SHALL。

- 対象が product / tech / structure の3文書であることと、作る順序
- 取得（`get-steering`）と提出（`submit-document` の steering 種別）の順序
- 文書がまだ無いとき（`exists: false`）の進め方
- 既に在る文書を上書きしてよいかの判断
- どこまで書けば1文書を終わりとみなすか
- **承認依頼の提出**——1本の提出が受理されるごとに、その文書の承認依頼を本家 spec-workflow の MCP の `approvals` ツール（`action: request`）で出すこと。対象はプロジェクトルートからの相対パス `.spec-workflow/steering/<name>.md`、種別は `document`、category は `steering` とする。承認の結果を待ってはならない（MUST NOT）——承認はユーザーの判断であり、工程の終わりの条件ではない
- **工程の終わりの条件**——3本の提出がすべて受理され、かつその3本それぞれに承認依頼が出ていること。承認依頼の無い文書が1本でも残っていれば工程は終わっていない

承認依頼は文書の提出が受理された後に出す SHALL。受理されていない文書の承認依頼を出してはならない（MUST NOT）——本家は依頼の時点で対象のファイルを読むため、無い文書への依頼は成立しない。

#### Scenario: 3文書を揃えるまで到達できる

- **GIVEN** エージェントが手順を読んでいる
- **WHEN** 文書を1つずつ作って提出し、受理されるごとに承認依頼を出す
- **THEN** エージェントは3文書の受理と3件の承認依頼が揃った時点で工程の終わりと判定できる

#### Scenario: 承認依頼を出さずに終わらない

- **GIVEN** エージェントが手順を読んでいる
- **WHEN** 3本の提出が受理されたが、承認依頼をまだ出していない文書がある
- **THEN** エージェントは工程が終わっていないと判定し、残る文書の承認依頼を出す

#### Scenario: 承認を待たない

- **GIVEN** エージェントが3件の承認依頼を出し終えた
- **WHEN** ユーザーがまだどの依頼にも応答していない
- **THEN** エージェントは承認を待たずに工程を終える。承認の結果は工程の終わりの条件に含まれない
