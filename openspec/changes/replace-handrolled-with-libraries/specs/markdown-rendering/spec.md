## Purpose

本家 spec-workflow の文書表示と同じ形で markdown を描く。文書由来の生 HTML を描かない境界を保ったまま、本家が図として描くもの（mermaid）を図として描き、コードのフェンスを本家と同じ形で見せる。

## ADDED Requirements

### Requirement: 文書由来の生 HTML を要素にしない

システムは、markdown 本文に書かれた生 HTML を要素として描いてはならない（MUST NOT）。stroke-board は本家のファイルを読んで出すだけであり、文書の中身を信用して実行する立場にない。

自前のサニタイズ処理を持ってはならない（MUST NOT）。生 HTML を要素にしないことは、markdown の parse 設定で担保する SHALL。

#### Scenario: 本文に script が書かれている

- **WHEN** 文書の本文に `<script>` が書かれている
- **THEN** それは要素にならず、スクリプトは実行されない

#### Scenario: 本文に img と on 属性が書かれている

- **WHEN** 文書の本文に `<img onerror=…>` が書かれている
- **THEN** それは要素にならない

### Requirement: mermaid のフェンスは図として描く

システムは、`mermaid` を言語に指定したフェンスを図として描く SHALL。本家（`enableMermaid` + `mermaidPlugin`）と同じ見え方にする。

図はサーバーでは描けない SHALL。mermaid はレイアウトの決定に DOM の計測を使うためである。**本文の描画そのものを図の完成まで待たせてはならない（MUST NOT）。** サーバーとクライアントの初期描画では図の枠だけを一致させ、描けた時点で図に差し替える SHALL。

図が描けなかったときは、その旨と元のソースを示す SHALL。

#### Scenario: mermaid のフェンスを含む文書を開く

- **WHEN** `mermaid` のフェンスを含む文書を開く
- **THEN** 本文はすぐ読め、フェンスの位置には図の枠が出て、描けた時点で図に変わる

#### Scenario: mermaid として解釈できないフェンス

- **WHEN** `mermaid` のフェンスの中身が図として解釈できない
- **THEN** 図の代わりに、解釈できなかった旨と元のソースが出る

### Requirement: mermaid 以外のフェンスはコードブロックとして描く

システムは、`mermaid` 以外のフェンスを、本家の文書表示が出す形（枠・言語名の札・行番号・折り返し）で描く SHALL。

言語の指定が無いフェンスでも行番号を出す SHALL。言語の指定が無いとシンタックスハイライトの経路を通らず、行の区切りが出ないためである。

読むだけの画面であるため、本家がエディタとして持つ操作（言語の切り替え・フェンスの削除）は置いてはならない（MUST NOT）。

#### Scenario: 言語を指定したフェンス

- **WHEN** 言語を指定したフェンスを含む文書を開く
- **THEN** 枠の中に色分けされたコードが出て、行番号と言語名の札が付く

#### Scenario: 言語を指定しないフェンス

- **WHEN** 言語を指定しないフェンスを含む文書を開く
- **THEN** 枠の中にコードが出て、行番号が付く
