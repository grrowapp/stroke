## Why

承認まわりの画面を実物で触った結果、5つの引っかかりが出た。いずれも機能は揃っているが、**機能への呼び口が使いにくい**。

とくに却下は、理由を入力して「却下する」を押しても入力欄が閉じるだけに見え、送れたのか分からない。実装を読むと送信は成功しており、**成功したことを示していない**のが原因である。動いているものが動いていないように見える状態は、そのまま使い続けられない。

## What Changes

- **差し戻しボタンを面の切替と同じ並びへ移す。** 本家は決める操作を面の切替と同じ帯に置く。現状は面の切替が本文の上、差し戻しが右サイドバーの最下部にあり、離れている
- **承認一覧の「レビューする」を、その場で開く。** 別画面へ遷移しない。5つのうち最も重い
- **「却下」を「即時却下」に改める。** 差し戻しとの違い（やり直しを求めるのか、その場で終わらせるのか）が名前から読めるようにする
- **レビュー画面に却下を置く。** 現状この画面にあるのは差し戻しだけで、承認・却下は承認一覧のカードにしかない。読んで判断した場で終わらせられない
- **却下の理由入力をモーダルにする。** カードの下に開く欄をやめ、レビュー画面の「全体へのコメント」と同じ形にする。モーダルの中で理由を入力し、却下する／やめる のどちらかを押す

いずれも**機能そのものは変えない**。承認・却下・差し戻しが何をするか、本家へ何を送るかは今のままである。変えるのは置き場・名前・開き方・入力の取り方だけで、利用者にとってできることは増えも減りもしない。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `project/ui`: 「下層で状態を変えられるのは承認への応答だけ」が承認・却下・差し戻しの置き場と、却下の理由の求め方を定めている。却下をレビュー画面にも置くこと、理由をモーダルで求めること、差し戻しを面の切替と同じ並びに置くこと、承認依頼をその場で開くことを加える。送る中身と送り先は変えない

## Impact

**画面**

- `app/components/review/ApprovalAnnotator.vue` — 差し戻しボタンを右サイドバー最下部から面の切替の並びへ。却下を追加
- `app/components/workspace/ApprovalCard.vue` — 却下の理由をカード下の欄からモーダルへ。「却下」→「即時却下」
- `app/components/review/CommentModal.vue` — 全体コメントのモーダル。却下の理由入力が同じ形を採るので、共通化するか写すかを design で決める
- `app/pages/projects/[projectId]/approvals/index.vue` — 「レビューする」をその場で開く形に
- `app/pages/projects/[projectId]/approvals/[approvalId].vue` — 承認依頼の URL は残す（`document-editing` が「編集は文書の URL の上で行う」と定めており、承認依頼の URL もその実体を指す）

**サーバー**

変更なし。`POST /api/projects/:projectId/approvals/:id/:action` の呼び方も送る中身も変わらない。

**テスト**

- `e2e/approval-annotation.spec.ts` — 差し戻しの位置、却下の追加
- `e2e/workspace.spec.ts` — 承認一覧からの遷移がその場で開く形に変わる

**他の change との関係**

`create-module-annotation` が同じ承認画面を触る（どの面でも注釈を付けられるようにし、並列表示を落とす）。面の構成に両方が手を入れるため、**この change を先に通す**。逆順だと面の並びを2度直すことになる。
