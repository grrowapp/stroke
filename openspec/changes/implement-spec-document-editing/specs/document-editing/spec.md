## Purpose

下層で開いている仕様書とステアリングの文書を、その場で直して保存できるようにする。どの文書を直せるのか、直しかけたまま離れようとしたときにどうなるのか、保存できなかったときに何が分かるのかを定める。

## ADDED Requirements

### Requirement: 編集できる文書は6本に限る

システムは、次の6本の文書だけを編集できるようにしなければならない（SHALL）。

- 仕様書 — `requirements` / `design` / `tasks`
- ステアリング — `product` / `tech` / `structure`

上記以外の文書を編集させてはならない（MUST NOT）。

編集できるかどうかは**文書の実体で決まり、どの画面から開いたかによって変わってはならない**（MUST NOT）。承認依頼の対象文書が上記6本のいずれかを指している場合、承認画面からも直せなければならない（SHALL）。

まだ作られていない文書は編集させてはならない（MUST NOT）。

#### Scenario: 仕様書の文書を開く

- **WHEN** 仕様書の `requirements` / `design` / `tasks` のいずれかを開く
- **THEN** その本文を直せる

#### Scenario: ステアリングの文書を開く

- **WHEN** ステアリングの `product` / `tech` / `structure` のいずれかを開く
- **THEN** その本文を直せる

#### Scenario: 未作成の文書を開く

- **WHEN** まだ作られていない文書の URL を開く
- **THEN** 未作成である旨が出て、編集の口は現れない

#### Scenario: 承認依頼から対象文書を開く

- **WHEN** 承認依頼のカードから対象文書を開く
- **THEN** 本文がすぐ直せる状態で出る。編集に入るための操作を挟まない

#### Scenario: 承認依頼が編集できない文書を指している

- **WHEN** 承認依頼の対象が編集を許す6本のいずれでもない
- **THEN** 本文は読めるが、編集の口は現れない

### Requirement: 編集は文書の URL の上で行う

システムは、文書の編集を、その文書を開いている URL の上で行わせなければならない（SHALL）。編集のために別の URL へ移動させてはならない（MUST NOT）。編集の口を、URL で指せない形（一覧の上に重ねる等）で提供してはならない（MUST NOT）。

同じ実体を指す URL は複数あってよい。仕様書やステアリングの文書の URL と、その文書を対象とする承認依頼の URL は、どちらも同じ実体を直す場所になる。

編集の状態は URL に含めない。同じ URL を開いた人が、直しかけの内容を見ることはない。

#### Scenario: 文書を開いて直す

- **WHEN** 文書の URL を開いて本文を直す
- **THEN** URL は変わらず、その URL を共有すれば同じ文書が開く

#### Scenario: 承認依頼の URL から直す

- **WHEN** 承認依頼の URL を開いて対象文書を直し、保存する
- **THEN** その文書の URL を開いても、直した内容が出る

#### Scenario: 直しかけで再読み込みする

- **WHEN** 保存せずに画面を再読み込みする
- **THEN** 保存されている内容が出る。直しかけの内容は残らない

### Requirement: 保存は文書1本の全文を送る

システムは、保存のときに文書1本ぶんの全文を送らなければならない（SHALL）。差分や部分的な更新を送ってはならない（MUST NOT）。

保存の成否が画面で分からなければならない（SHALL）。保存が終わっていないのに終わったように見せてはならない（MUST NOT）。

保存が終わったら、画面が持つ内容を保存した内容に合わせなければならない（SHALL）。

#### Scenario: 保存する

- **WHEN** 直した内容を保存する
- **THEN** 保存されたことが分かり、その文書を開き直すと直した内容が出る

#### Scenario: 保存の最中

- **WHEN** 保存を送ってから応答が返るまでのあいだ
- **THEN** 送信中であることが分かり、同じ内容を二重に送れない

#### Scenario: 保存に失敗する

- **WHEN** 保存が失敗する
- **THEN** 失敗したことと、直しかけの内容が失われていないことが分かる

#### Scenario: 本家に繋がっていない

- **WHEN** 本家に繋がっていない状態で保存しようとする
- **THEN** 保存できないことが分かり、直しかけの内容は残る

### Requirement: 直しかけのまま離れようとしたら引き止める

システムは、保存していない変更がある状態で画面を離れる操作が行われた場合、離れる前に引き止めなければならない（SHALL）。引き止めずに変更を捨ててはならない（MUST NOT）。

引き止めたうえで、そのまま離れることを選べなければならない（SHALL）。

保存していない変更が無い場合は引き止めてはならない（MUST NOT）。

#### Scenario: 直しかけで別の画面へ移ろうとする

- **GIVEN** 保存していない変更がある
- **WHEN** 別の画面へ移ろうとする
- **THEN** 引き止められ、離れるか留まるかを選べる

#### Scenario: 引き止められたうえで離れる

- **GIVEN** 引き止められている
- **WHEN** 離れることを選ぶ
- **THEN** 変更は捨てられ、移動先の画面が開く

#### Scenario: 変更していない状態で離れる

- **GIVEN** 開いてから何も直していない
- **WHEN** 別の画面へ移る
- **THEN** 引き止められず、そのまま移る

#### Scenario: 直した内容を元に戻した

- **GIVEN** 一度直したが、保存されている内容と同じ状態に戻した
- **WHEN** 別の画面へ移る
- **THEN** 引き止められない

### Requirement: 保存の口はサーバーが持つ

システムは、文書の保存を stroke-board のサーバー経由で行わなければならない（SHALL）。ブラウザから本家へ直接保存を送ってはならない（MUST NOT）。

サーバーは、受け取った文書名が編集を許す6本のいずれでもない場合、保存を行わずに退けなければならない（SHALL）。本文が文字列でない場合も同様に退けなければならない（SHALL）。

#### Scenario: 画面から保存する

- **WHEN** 画面が保存を行う
- **THEN** stroke-board のサーバーが受けて本家へ渡す

#### Scenario: 許していない文書名で保存を送る

- **WHEN** 編集を許す6本に含まれない文書名で保存が送られる
- **THEN** 保存は行われず、退けられたことが分かる

### Requirement: 同時に直したときは後から保存したものが残る

システムは、同じ文書を複数の場所から直した場合、後から保存したもので上書きしなければならない（SHALL）。

保存の前に、他所で変更されていないかを確かめてはならない（MUST NOT）。確かめる手段を本家が持たないため、確かめられるかのように見せることはしない。

#### Scenario: 別の場所で先に保存されていた

- **GIVEN** 文書を開いたあとに、別の場所で同じ文書が保存された
- **WHEN** こちらで保存する
- **THEN** こちらの内容で上書きされる

#### Scenario: 画面を開き直す

- **GIVEN** 別の場所で保存されて内容が変わっている
- **WHEN** 画面を開き直す
- **THEN** 保存されている最新の内容が出る
