## MODIFIED Requirements

### Requirement: 有効な token の無い呼び出しを拒否する

有効な token を持たないツール呼び出しは HTTP 401 で拒否する SHALL。有効な token は、現に実行中の起動に対して invoke-agent が発行したもののみとする SHALL——実行の終了（正常・異常とも）と stroke-board の再起動で無効になり、再起動をまたいで有効な token を作ってはならない（MUST NOT）。拒否で接続文脈を既定値で補ってはならない（MUST NOT）（docs/adr/0014 の原則に整合する）。

**失効させるだけで終わりにしてはならない（MUST NOT）。** 再起動の前に起こした claude は、以後どのツール呼び出しも 401 で拒否され、何も提出できないまま走り続ける。システムはその claude を走らせたままにしてはならない（MUST NOT）——起動後の後始末で終了させる SHALL。token を保存して再起動後に復活させる形で解決してはならない（MUST NOT）。

#### Scenario: token を持たない接続は拒否される

- **GIVEN** stroke-board が起動済みである
- **WHEN** token のヘッダを持たない MCP 設定で外部から `claude -p` を起動し、いずれかのツールの実行と呼び出し状況の報告を指示する
- **THEN** 報告に、ツールの呼び出しが認可エラーで失敗したことが示されている

#### Scenario: 発行されていない token は拒否される

- **GIVEN** stroke-board が起動済みである
- **WHEN** 発行されていない token をヘッダに設定した MCP 設定で外部から `claude -p` を起動し、いずれかのツールの実行と呼び出し状況の報告を指示する
- **THEN** 報告に、ツールの呼び出しが認可エラーで失敗したことが示されている

#### Scenario: 再起動で接続を失った claude は残らない

- **GIVEN** ツール呼び出しの途中で stroke-board を再起動する
- **WHEN** 再起動した stroke-board が起動を終える
- **THEN** 再起動の前に起こされた claude はもう走っておらず、失効した token による 401 の呼び出しがそれ以上起こらない

## ADDED Requirements

### Requirement: 自分が起こした claude を再起動の後も見分ける

システムは、**自分が起こした claude** を、再起動の後も他の実行と区別して見分けられる SHALL。見分けの手がかりは、再起動で失われないもの——起動のときに子プロセスへ渡した、そのインスタンスに固有の値——とする SHALL。メモリ上にだけ持つ記録に頼ってはならない（MUST NOT）。

同じ保存先（`projectShareRoot`）を共有する別インスタンスが起こした claude を、自分のものとして扱ってはならない（MUST NOT）。止めてはならない（MUST NOT）し、その対象の実行の記録を書き換えてはならない（MUST NOT）。

見分けがつかないときは、止めない SHALL。判断がつかないものを止める側に倒してはならない（MUST NOT）。

#### Scenario: 自分が起こした実行を見分ける

- **GIVEN** 再起動の前に自分が起こした claude が走っている
- **WHEN** 起動後の後始末が、走っている実行を調べる
- **THEN** その claude は自分のものと判定される

#### Scenario: 別インスタンスの実行は自分のものにしない

- **GIVEN** 同じ保存先を共有する別インスタンス（別の待ち受けで動く stroke-board）が起こした claude が走っている
- **WHEN** 起動後の後始末が、走っている実行を調べる
- **THEN** その claude は自分のものと判定されず、終了させられない

#### Scenario: 見分けがつかない

- **GIVEN** 走っているプロセスを調べられない、または調べた結果から自分のものか判定できない
- **WHEN** 起動後の後始末が走る
- **THEN** 何も終了させられない
