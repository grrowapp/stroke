## Goals / Non-Goals

**Goals:**

- 「同時に走らせられる」を、テストの書き方ではなく土台の側の性質にする
- 走らせた結果が、いま在るソースの結果であることを既定にする
- 前後を比べられる数字を残す。速くなったかどうかを、体感ではなく実測で言う
- 番人（条件10）を、worker ごとに割り直した後も同じ強さで通す

**Non-Goals:**

- テストの中身を作り直すこと。並べ替えも、分割も、統合もしない
- `fullyParallel: true` にすること（Context 3。**足元を外す**）
- flake を消すこと。触る箇所は重なるが、消えたことをこの change の成果にしない
- スタブが返す payload を worker ごとに変えること。分けるのはプロセスであって、返すものではない
- **待ち受けを固定割り当てへ戻すこと。** `playwright.config.ts:25-32` が却下した形である
- 単体テスト（`yarn test`）の土台。共有物を踏んでいない

## Decisions

### 決定1: 並列はファイル単位にする。`fullyParallel` は `false` のまま、`workers` だけを上げる

**`fullyParallel: true` にしない。** Context 3 のとおり、立てると同じファイルのテストが別々の worker へ散る。今 `resetBoard` を払っていない78件は、同じファイルの前のテストが残した状態を前提に書かれている。散らせばその前提が消え、**78件すべてに前提づくりを足すことになる。** 施策 B（絞り込み）と正面から逆を向く。

`fullyParallel: false` のまま `workers` を上げると、14本のファイルが worker へ配られ、ファイルの中の順序は保たれる。`stroke-exit.spec.ts:27` の `mode: 'serial'` もそのまま効く。

**この選び方には天井がある。** 同時に働ける worker は最大でもファイルの本数（14）までで、実行時間は**いちばん長いファイルの時間を下回らない**。`workspace.spec.ts`（43件）と `upstream-style.spec.ts`（33件）がその候補である。ファイルごとの時間はまだ測っていないので、**天井がどこかは 1章 で測る。**

**代替1: `fullyParallel: true` にして、全テストに前提づくりを課す。** 却下。221件が毎回 `resetBoard` を払う形になり、いま 78件が払っていないぶんが増える。B と真逆で、並列で稼いだぶんを前提づくりで返す。

**代替2: ファイルを分割して天井を下げる。** 本 change ではやらない。テストの中身に手を入れないという線を越える（`proposal.md` の対象外）。測った結果ひとつのファイルが天井を作っているなら、**別 change として起こす**。

### 決定2: worker ごとの値は `TEST_PARALLEL_INDEX` から引き、モジュールのトップレベルの定数のまま置く

Context 2 と 7 から出る。`test/e2e/support.ts:11` の `STUB_URL` も `stroke-exit.spec.ts:12` も**モジュールのトップレベルで確定する**ので、fixture の値を渡す形にするとどちらも書き換えが要る。`stub` を fixture にすると呼び出しは64箇所、テストの引数も33以上のシグネチャに及ぶ。

`TEST_PARALLEL_INDEX` はモジュールが読み込まれるより前に立っているので（条件2）、**トップレベルの定数のままで worker ごとの値にできる。** `STUB_URL` の形も `stub.*` の64箇所も、`stroke-exit.spec.ts:12` も、`degraded.spec.ts` の `REGISTRY_PATH` 7箇所も、`stroke-exit.spec.ts` の `PROJECTS_PARENT` 11箇所も、`proposal-persistence.spec.ts` の3箇所も、`ws-disconnect.spec.ts:70` も、**書き換えずに済む。**

- **A-1（値の導出）で触るのは、値を作っている1箇所だけである。** ポートと根のパスの導出（`playwright.config.ts:78-105`）
- **A-2（fixture）では、テストの `test` の出所だけが変わる。** 14本の spec が `@playwright/test` から `test` を import している（実測。全14本）。worker scope の fixture を効かせるには、拡張した `test` を配る先が要る。`support.ts` が `test` を再輸出し、14本の import 行をそこへ向ける。**変わるのは import 行だけで、テストの本体も引数も1つも変わらない**（受け入れ条件は tasks 4.3）

**代替1: worker scope の fixture で値まで持ち回る。** 却下。Playwright の作法としては正しいが、書き換えが 64＋α 箇所に及ぶ。**得るものが「作法に合う」だけで、テストの読みやすさも安全性も上がらない。** テストが自分のポートを知る必要は無く、知らないまま正しい所へ当たればよい。

**代替2: worker ごとに Playwright の project を分ける。** 却下。project ごとに `use` を変えれば宛先は分けられるが、テストファイルが project の数だけ重複して実行される。並列化ではなく多重実行になる。

### 決定3: ポートは worker ごとに空きを取る。番号を算術で振らない

**rebase で全面的に差し替えた決定である。** 以前の版は「`slot × 100 + parallelIndex`。作業ツリーの表を埋め、表に無いものは止める」と書いていたが、**その表は develop で廃止されている。** `playwright.config.ts:25-32` が固定表を却下した理由は、本 change が書こうとしていた理由とほぼ同じである（ツリーを増やすたびに人が表を足す必要があり、足し忘れは「他人のスタブを掴む」方向へ倒れる）。**戻さない。**

直すのは条件9 の1点、**持ち回りの鍵が worker で変わらないこと**だけである。

- **鍵に worker の名札を混ぜる。** `E2E_STUB_PORT` → `E2E_STUB_PORT_<名札>`。名札は `TEST_PARALLEL_INDEX` があれば `w<番号>`、無ければ `main`（決定5）
- 本体プロセスが控えるのは `…_main` なので、worker はそれを読まない。**worker は自分のプロセスで空きを取り、自分の env へ控える。** 控えの仕組み（`:89-96`）はそのまま生きるので、`:84` の 207件の事故は再発しない
- **番号を算術で決めない。** 空きを OS から探す形は衝突を原理的に起こさない。`slot × 100 + parallelIndex` のような算術は、`:25-32` が却下した「人が表を保つ」形へ半分戻ることになる
- **探し始めだけ worker ごとにずらす。** 全 worker が `PORT_SEARCH_START`（`:41` の 50000）から同時に探すと、同じ番号を同時に「空き」と見て取り合う。`PORT_SEARCH_START + parallelIndex × 10` から探す（1 worker が使うのはスタブとアプリの2つなので 10 は余裕。`PORT_SEARCH_END` は `:44` の 60000 のまま）
- **ずらしても隙は残る。** 取ってから待ち受けるまでの間に別のプロセスが割り込みうることは `:64-70` が既に書いている。worker が同時に立ち上がるぶん、いまより当たりやすい。**起動待ちが失敗したら次の空きで取り直す**（回数の上限つき。R10）

**代替1: 固定表を復活させて worker 番号を足す。** 却下。`:25-32` が却下済みの形である。ツリーを増やすたびに人が表を足す必要が戻り、足し忘れが「他人のスタブを掴む」方向へ倒れる。

**代替2: 本体プロセスで `workers` の数だけ先に取り、env へ並べる。** 却下ではないが採らない。`globalSetup` からは `config.workers` が読めるので書ける。ただし (a) 実際に使われない worker のぶんまで取る、(b) 取ってから worker がサーバーを立てるまでの隙が本体〜worker 起動ぶん伸びる、(c) worker が作り直されたとき（条件2）に取り直す口が無い。

### 決定4: スタブとアプリは worker scope の fixture が起こす。`webServer` は畳む

Context 1 のとおり `webServer` では書けない。`test.extend` の worker scope・`auto: true` の fixture で、その worker のスタブとアプリを起こし、応答するまで待ち、worker の終わりに落とす。

- **待ち方は `webServer` と同じにする。** 今の `webServer` が待っている url（`playwright.config.ts:231` の `/api/projects/list`、`:238` の `/api/projects`）へ、応答するまで叩く。今の待ち方を捨てない
- **`baseURL` も同じ fixture の値にする。** `playwright.config.ts:225` の `use.baseURL` は本体プロセスで決まるので worker の値を持てない。`test.extend` で `baseURL` を上書きし、**その fixture がサーバーの fixture に依存する**ようにして、`page` と `request` が立ち上がった後のアプリへ向くようにする
- **拡張した `test` を `support.ts` から配る。** 14本の spec の import 行だけが変わる（決定2）
- **種まきは fixture の中で行う。** Context 6 のとおり、いまは config のモジュールを読み込むだけで走る。worker が複数になるとここが真っ先にぶつかる。`playwright.config.ts:188-216` をモジュール本体から出し、worker の起動時に**その worker の根に対して**まく
- **worker が作り直されたときは、根を消してからまき直す。** `parallelIndex` は作り直しでも同じ値なので、前のプロセスが落とした残骸が根に残っている
- **起動ログにポートを出す。** `CLAUDE.md:34` が「どのポートを使ったかは Playwright の起動ログに出る」と書いている。`webServer` を畳むとその出所が消えるので、fixture が同じ情報を出す。**手引きを書き換えるのではなく、手引きが書いていることを壊さない**

**代替1: `globalSetup` で `workers` の数だけ先に立てる。** 却下ではないが採らない。(a) 実際に使われない worker のぶんまで立てる、(b) 起動待ちを自前で書くことになる（fixture なら worker の起動と同じ流れに乗る）、(c) 落とし損ねが `globalTeardown` の一点に集まる、(d) worker が作り直されたときに立て直す口が無い。**fixture の方が、立てるものと使うものが同じ寿命になる。**

**代替2: `webServer` は残し、1台のアプリを worker で共有する。** 却下。Context 5 のとおり、走査先と registry の在り処が起動時の環境変数で固まる。1台では registry を分けた意味が無い。

### 決定5: worker の外では「使えない値」に落とす。モジュールの読み込みでは投げない

**rebase 後の実測（条件8）で差し替えた決定である。** 以前の版は「`TEST_PARALLEL_INDEX` が無い場で呼ばれたら例外を投げる」と書いていたが、**テストのモジュールは本体プロセスでも評価される**（`runner/index.js:6665` → `:2044-2056` → `common/index.js:2897`）。トップレベルで投げると収集の段で落ち、1件も走らない。

代わりに、**worker の外では誰も使えない値を返し、使おうとした所で止める。**

- **名札**: `TEST_PARALLEL_INDEX` があれば `w<番号>`、無ければ `main`
- **根**: `E2E_ROOT`（`playwright.config.ts:102` の `.e2e-tmp`）は動かさず、その下に `WORKER_ROOT = join(E2E_ROOT, 名札)` を掘る。`PROJECTS_PARENT` / `SPEC_WORKFLOW_HOME` / `REGISTRY_PATH`（`:103-105`）はその下へ移す。**`E2E_ROOT` を動かさないのは、番人の `:134-139` が `${E2E_ROOT}/` を基準に「外を指していないか」を見ているためである。** 掘るのは下なので、この検査は1文字も変えずに通り続ける
- **ポート**: worker の外では空きを探さず `0` を返す。`0` は「どこでもよい」の意味であって宛先にならないので、うっかり本物へ当たらない
- **止める場所は使う所**: fixture がサーバーを起こす直前に、名札が `main` でないこと・ポートが `0` でないことを確かめて、違えば投げる（決定9 の番人と同じ場で行う）
- **`export default defineConfig({…})` の中に worker ごとの値を1つも書かない。** `baseURL` は決定4 で fixture へ移り、`webServer` は畳まれるので、残るのは `testDir` / `testMatch` / `fullyParallel` / `workers` / `timeout` / `use.trace` だけになる

**判定基準**（tasks 3.6 の終了条件）。「置いていないこと」は目視では確かめられないので、次の4つで見る。

1. `defineConfig` に渡すオブジェクトのどのプロパティも、名札やポートを参照していない（`grep` で `STUB_PORT` / `APP_PORT` / `WORKER_ROOT` / `PROJECTS_PARENT` / `SPEC_WORKFLOW_HOME` / `REGISTRY_PATH` を探し、`:218` 以降に1件も出ないこと）
2. `playwright.config.ts` のモジュール本体に、ファイルを作る・書く副作用が1つも残っていない（決定4。`mkdirSync` / `writeFileSync` の呼び出しが `defineConfig` の外に無いこと）
3. 本体プロセスで名札が `main` になることを確かめる小さな検査を1本足し、`yarn test` の側で回す（E2E を回さずに見られる）
4. 実行後に `.e2e-tmp/main/` が**作られていない**こと。作られていたら、本体プロセスのどこかが worker の値を使って書いている

**この決めが無いと、決定2 の「トップレベルの定数のままでよい」が安全でなくなる。** import しただけで動くモジュールから worker ごとの値が出ていく形は、Context 6 と同じ事故の形である。

### 決定6: 入れる順は C → A → B。各段で測る

- **C（build の前置）を最初に入れる。** 入れないと、A と B の効果を測っているつもりで古いビルドを測る。**測定の前提である**
- **次に A（割り直し）。** 効果が最大で、B の測り方（1ファイルを単独で速く回せること）もここで手に入る
- **最後に B（絞り込み）。** A が入った後なら、1つの `beforeEach` を外して該当ファイルだけを回すのが速い。33箇所を1つずつ試せる

**各段の前後で総実行時間を測る。** 起票時の 18.4分は渡された値で、本 change の作成者が測ったものではない。**着手時に自分で測り直したものを基準にする。**

測る場所を段ごとに決めておく。8.3 が要求する「C / A / B の内訳」は、この3点の差分である。

| --- | --- | --- |
| 基準 | 1.1 | 起票時の 18.4分 |
| C の後 | 2.5 | 1.1。build のぶんだけ増える（`test:e2e`）／変わらない（省く口） |
| A の後 | 5.8 | 2.5 の「省く口」の値。並列で縮んだぶん |

### 決定7: `test:e2e` の既定は build 込み。省く口は別名で立て、承認の要らない場所にも書く

`package.json:23` を build 込みにし、省く口を1本足す。**既定が省く側であってはならない**（`specs/tooling/e2e-harness/spec.md`「実行はいま在るソースに対して行われる」）。

**「どちらを選べばよいかが読める」を、承認待ちに依存させない。** 同 spec の3つ目の Scenario は「走らせる者が、用意された口の一覧を読む」→「既定がどちらで、省く口がどちらかが分かる」を求めている。`README.md:201-206` のテスト表への追記は上位資料への整合反映なのでユーザー承認が要る（`docs/agents/issue-tracker.md`「更新対応」）が、**承認が下りない間もこの SHALL が満たされている**状態にする。承認の要らない経路を2本用意する。

1. **script の名前そのもの。** `package.json` の scripts は `yarn run` で一覧が出る。名前が「省く口である」と言っていれば、表を読まなくても分かる（`test:e2e:no-build` のように、省くものを名前に書く。`fast` や `only` のような速さ・範囲を連想させる名前を採らない）
2. **省く口が走り出しに1行出す。** 「古いビルドに当たる。ソースを直したなら `yarn test:e2e`」を先頭に出してから `playwright test` を叩く。**選んだ瞬間に読める場所である**

`README.md` の表への追記は、この2本の上に**重ねて**提案する（承認が下りれば読める場所が3つになる）。

**代替: 既定を省く側にして、CI だけ build 込みにする。** 却下。`adr0017-sub-fix-normalization-offset` の `tasks.md:86`・`:115` に記録が残っている事故は、CI ではなく**手元の毒見**で起きている。手元で嘘を返す形が残るなら直したことにならない。

### 決定8: `resetBoard` の要否は測って決める。読んで決めない

施策 B の対象は 33箇所の `beforeEach`（143件のテスト）。どれが要るかを読み取りで判断しない。**1箇所ずつ外して、そのファイルを回して落ちるかを見る。**

- 落ちなければ外す。落ちれば戻し、**要る側として記録する**
- **判定が変わってはならない**（`specs/tooling/e2e-harness/spec.md`「絞り込みが判定を変えない」）。外して落ちたということは、そのテストは前提を要る側である
- 一律の `beforeEach` から外したものは、**必要なテストの中で払う**形にする。宣言しないテストが「何も無い」状態に落ちてはならない（同 spec）

外した数と、そこで消えた往復の回数を記録する。**「速くなった」の内訳がこの数字である。**

### 決定9: 番人（`refuseRealTargets`）は畳まず、worker の側へ移して同じ検査を通す

条件10 の番人は `playwright.config.ts:152` でモジュール本体から1回呼ばれ、`PROJECTS_PARENT` / `SPEC_WORKFLOW_HOME` / `STUB_PORT` という**モジュールの定数**と付き合わせている。施策 A はこの3つを worker ごとに動かすので、**番人は必ずここを通る。**

- **二段にする。** (a) 本体プロセスでも走る段 — 外から差し込まれた `NUXT_*` が在ること自体を拒む（ポートに依らない `:119-132` の照合のうち、値の一致ではなく「そもそも差し込まれている」を見る側）。(b) fixture がスタブとアプリを起こす直前に走る段 — その worker の根とポートに対して、いまの `:119-149` と同じ3つを確かめる
- **`${E2E_ROOT}/` の検査（`:134-139`）は1文字も変えない。** 決定5 のとおり `E2E_ROOT` は動かさず、worker の根はその下に掘る。`startsWith` はそのまま通る
- **緩めない。** 「worker ごとで比べる相手が変わるから外す」は採らない。比べる相手が worker ごとに変わるだけで、比べること自体は変わらない
- **番人が仕事をすることを確かめる。** `NUXT_UPSTREAM_BASE_URL` を本家（`localhost:5000`）に向けて1回走らせ、**起動時に落ちる**ことを目で見る（tasks 4.10）

**代替: `webServer` を畳むときに番人も畳む。** 却下。番人が守っているのは ADR-0001 の線で、`webServer` の都合とは無関係である。畳めば、環境変数を1つ間違えた実行が本物の `.spec-workflow/` へ承認を書き込む。

## Migration Plan

段階は決定6 のとおり C → A → B。データの移行は無い。`.e2e-tmp` の中身は毎回まき直すもので、`yarn clean`（`package.json:12`）が根ごと消す（`rm -rf … .e2e-tmp …`。worker ごとの根はその下なので、この行は変えなくてよい）。

ロールバックは段ごとに独立している。

- C を戻す — `package.json` の `test:e2e` を元に戻すだけ
- A-1 を戻す — `playwright.config.ts` の導出（名札・鍵・根）を戻す。テストのコードには A-1 で触っていない（決定2）
