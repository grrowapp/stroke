# mcp/tools/question Delta

## Purpose

ストロークの問いを提出するツールの契約を定める。問いは文章ではなく構造化データであり、専用の引数スキーマを持つ。

## ADDED Requirements

### Requirement: 問いを構造化引数で提出する

ツールの引数は問いの構造——header（話題タグ）・detail（詳細説明）・question（問い本文）・options（選択肢の一覧。各選択肢は label・description・任意の recommended を持つ）——とする SHALL。ツールは問いを自セッションのストロークの問いとして提出する SHALL。結果は次のいずれか1つを返す SHALL。

- **受理**: 提出が受け付けられたこと
- **エラー**: ステータスとエラー内容

#### Scenario: 問いを提出する

- **GIVEN** 対象のセッションがストローク中である
- **WHEN** header・detail・question・options を渡してツールを実行する
- **THEN** 問いがそのセッションに提出され、受理が返る

### Requirement: 検証エラーは同じ口で出し直せる

ツール側で引数の値の検証を行って提出を止めてはならない（MUST NOT）——検証の正は提出先（`api/stroke/question`）にある。提出先の検証に通らなかった場合はエラーを返し、その内容を読んで同じツールの呼び直しで出し直せる SHALL。

#### Scenario: 提出先の検証に通らない

- **GIVEN** 対象のセッションがストローク中である
- **WHEN** 提出先の検証に通らない問いを提出する
- **THEN** エラーが返り、ステータスとエラー内容を持つ

#### Scenario: 検証エラーの後に出し直す

- **GIVEN** 対象のセッションがストローク中であり、直前の提出が検証エラーで受理されていない
- **WHEN** 内容を直した問いを同じツールで提出する
- **THEN** 受理が返る
