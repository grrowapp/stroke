## ADDED Requirements

### Requirement: 起動の材料を組み立てられなかった要求は受理しない

システムは、起動の材料を組み立てられなかった起動要求（U13）を受理しない SHALL。要求元には、受理しなかったことと、組み立てられなかった理由が返る。

受理を表す応答を返してはならない（MUST NOT）。返すと、要求元——画面・巡回・承認処理——は起動が始まったものとして扱い、失敗に気付く手立てを持たない。

組み立ての成否は AI を起こす前に決まる。応答が待つのはその成否までとし、AI の応答の完了を待ってはならない（MUST NOT）。受理したときの応答が即完結する性質は変わらない。

受理しなかった後は、同じ対象に再び起動を要求できる SHALL。多重起動を止める仕掛けが、受理しなかった要求のために残ってはならない（MUST NOT）。

#### Scenario: 材料を組み立てられない状態で起動を要求する

- **WHEN** 起動の材料を組み立てられない状態で U13 が要求される
- **THEN** システムは受理せず、組み立てられなかった理由を伝える。AI は起動されない

#### Scenario: 起こし直しを要求した側が失敗を知る

- **WHEN** 巡回または承認処理が起こし直しを要求し、その要求で材料を組み立てられない
- **THEN** 要求元は応答から受理されなかったことを知り、失敗として扱える

#### Scenario: 受理しなかった応答も AI を待たない

- **WHEN** 起動の材料を組み立てられずに要求が終わる
- **THEN** 応答は AI の応答の完了を待たずに返る

#### Scenario: 受理しなかった後に再び起動を要求する

- **WHEN** 受理されなかった対象に、原因が直った後で再び起動が要求される
- **THEN** システムは受理し、AI の呼び出しを開始する
