## ADDED Requirements

### Requirement: 問いの配信先が切れてもシステムは動き続ける

問いを受け取る接続は、ユーザーの通常の操作（リロード・画面遷移・タブを閉じる）でいつでも切れる。システムはこれを異常ではなく通常の事象として扱う SHALL。

配信先が切れたとき、システムは応答を続ける。他の配信先・他のセッション・そのセッションの状態のいずれも、切断によって変わってはならない。切れた配信先が以後の配信の妨げになってもならない。

正常な切断と異常の通知は、どちらも同じ結果とする。

#### Scenario: 接続した直後に切れる

- **WHEN** 問いを受け取る接続が繋がり、接続の瞬間の配信が届くより前にその接続が切れる
- **THEN** システムは応答を続け、他のセッションも引き続き開ける

#### Scenario: 繋いでは切るを繰り返す

- **WHEN** ユーザーが問いを受ける画面のリロードを繰り返す
- **THEN** 回数によらずシステムは応答を続ける

#### Scenario: 配信先の1つが切れている

- **WHEN** 同じセッションに複数の配信先があり、そのうち1つが既に切れている状態で新しい問いが配信される
- **THEN** 残りの配信先には問いが届く

#### Scenario: 異常が通知されて切れる

- **WHEN** 問いの配信先について、正常な切断ではなく異常が通知される
- **THEN** 結果は正常な切断のときと同じで、システムも他の配信先も影響を受けない

#### Scenario: 切断がセッションの状態を変えない

- **WHEN** 問いの配信先が切れる
- **THEN** そのセッションの phase も、現在の1問も、回答を待っていることも変わらない。繋ぎ直せば今の1問が届く
