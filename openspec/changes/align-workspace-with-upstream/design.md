## Context

動機と実測値は proposal.md - Why / Findings を参照。設計上の制約は次の3つ。

- stroke-board は本家 spec-workflow-mcp の画面を写す。本家に対応する画面がある限り、文言も見えも本家が正である。
- 本家は日本語ロケール（`src/dashboard_frontend/src/locales/ja.json`）を持つ。ただし**全ての文字列が i18n を通っているわけではない**。ステアリングの表示名（`Product` / `Technical` / `Structure`）は `SteeringPage.tsx` に直接書かれており、日本語表示でも英語のまま出る。
- 本家 CSS には、定義だけ残って**どの画面からも使われていない** class がある（`.status-badge`）。定義を読んで写すと、実物と違うものができる。

## Goals / Non-Goals

**Goals:**

- 下層の文言を本家の日本語ロケールに一致させる。
- 一覧の見えを、稼働中の本家の実測値に一致させる。
- 「なぜトークンではなく生の値なのか」がコードから読めるようにする。

**Non-Goals:**

- design token の値を動かすこと。トークンは本家の定義どおりに保つ。
- 本家に無い操作を足すこと。
- 上層（ポータル）の文言。

## Decisions

### 文言は自前で訳さず、本家 `ja.json` の値をそのまま使う

実装時は stroke-board 側で説明文を書き下ろしていた（「本家が持つ仕様書を読む。編集と承認の操作は置かない」など）。これは本家に存在しない文である。本家と並べて見たときに言葉がずれ、「どちらが正か」が判断できなくなる。

写す相手が文言を持っているなら、それが正である。訳し直さない。

- 却下: 本家の英語原文から訳し直す。本家の日本語と語彙が揃わない。
- 却下: stroke-board 独自の説明文を残す。「操作は置かない」のような**実装都合の説明**が画面に出続ける。読む人が知りたいのは画面の役割であって、stroke-board の制約ではない。

### ステアリングの表示名は訳さず `Product` / `Technical` / `Structure` のまま出す

本家は行の1列目を2段で出し、上段に表示名、下段にファイル名を置く（`SteeringPage.tsx` の `SteeringDocumentRow`）。この表示名は `displayName` に直接書かれていて i18n を通っていない。**本家を日本語表示にしても英語のまま出る。**

ロケールに合わせるという方針を貫くなら、ここも本家に合わせて訳さない。訳すと本家より「親切」になるが、写しではなくなる。

- 却下: 「プロダクト」「技術」「構造」と訳す。本家の日本語表示と食い違う。

### 見えのずれは本家 CSS の定義ではなく、稼働中の本家の実測値に合わせる

本家 CSS の `.status-badge` は `padding: 2px var(--space-2)` を持つが、この class はどの画面からも使われていない。実際に出ているバッジは `px-2 py-1` の直書きで、実測 4px 8px。有無バッジの色も同様に Tailwind 直書き（`dark:text-green-400`）で、`--status-success`（green-500）とは別の色になる。

目的は**見えを揃えること**なので、生きていない定義ではなく実物に合わせる。

E2E ではこの二重性をそのまま残している。`rule.padding`（本家 CSS の定義値）と `style.paddingTop`（実際に出る値）の両方を assert しており、片方だけ見て「揃っている」と誤認しないようにしてある。

- 却下: 定義どおり 2px にする。本家の実画面と 2px ずれる。
- 却下: `--status-success` トークンの値を green-400 に変える。トークンは接続 dot などでも使われており、そちらまで色が変わる。ずれているのはバッジだけなので、バッジ側で持つ。

### 一覧の列見出しは本家の 11px ではなく 13px にする

本家の列見出しは 11px + `uppercase` + `letter-spacing`。これは**英語の大文字を前提にした組み方**で、日本語（「ドキュメント」「ステータス」）を入れると詰まって読めない。ここは本家から意図的に外れ、13px に上げる。

`uppercase` と `letter-spacing` は残す。日本語には効かず、英語が入ったときだけ本家と同じに出る。

トークンに 13px は無いため生の値で持つ（`.sb-table td` と同じ扱い）。

- 却下: 11px のまま。本家と同じだが、日本語で読めない。
- 却下: `--text-sm`（14px）。読めるが、本文（14px）と同じ大きさになり見出しとして立たない。

### 操作列の見出しには幅を指定しない

見出しを入れる前は `w-12`（48px）で固定していた。中身が `sr-only` の空列だったため、幅を与えないと潰れるからである。

見出しの文字が入ると事情が変わる。48px に固定したまま「アクション」を入れると、文字が最小幅を押し広げて他の列を圧迫する。本家もこの列に幅指定を持たない。固定をやめる。

## Risks / Trade-offs

- [本家がロケールを変えると stroke-board とずれる] → ずれたときに追随する。文言を stroke-board 側で持つ限り、ずれは必ず起きる。出どころを本家に一本化しておけば、追随先が1箇所で済む。
- [実測値をハードコードするため、本家の変更に追随しにくい] → E2E が実測値を固定しているので、ずれればテストが落ちて気づける。落ちたときに実測し直す。
- [列見出し 13px が本家から外れる] → 外れる箇所を `.sb-datatable th` の1点に閉じ、理由を様式のコメントに書いた。

## Decided

- 文言は自前で訳さず、本家 `ja.json` をそのまま使う（2026-08-24）
- ステアリングの表示名は本家に合わせて訳さない（2026-08-24）
- ずれの判断は本家 CSS の定義ではなく、稼働中の本家の実測値による（2026-08-24）
