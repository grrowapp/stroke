# api/invoke-agent Specification

## Purpose

AI（claude）の起動を受け付ける endpoint を規定する。起動の唯一の入口であり、入力を受理する endpoint 群から起動の責務を分離した先である。

## Requirements

### Requirement: AI の起動を受け付ける endpoint を1つ公開する

システムは AI の起動要求を受け付ける endpoint を1つ公開し、起動要求を受理したときは AI の呼び出しを開始して、応答の完了を待たずに受理を返して完結する SHALL。要求はメソッド GET・セッション id のパス指定のみで行い、body・パラメータを持たない。初回か継続かの判定・渡す定型は要求側から受け取らない（ai-invocation が規定する）。

#### Scenario: 起動を要求する

- **WHEN** 存在するセッションに対して起動が要求される
- **THEN** システムは AI の呼び出しを開始し、応答の完了を待たずに受理を返す

#### Scenario: 存在しないセッションに起動を要求する

- **WHEN** 存在しないセッション id で起動が要求される
- **THEN** システムは起動せず、存在しないことを伝える

### Requirement: 同一セッションの多重起動を受け付けない

システムは、実行中の呼び出しを持つセッションへの起動要求を受理しない SHALL。呼び出しが終わった後は、同じセッションに再び起動を要求できる。

#### Scenario: 実行中に起動を要求する

- **WHEN** 実行中の呼び出しを持つセッションに起動が要求される
- **THEN** システムは受理せず busy であることを伝え、AI は二重に起動されない

#### Scenario: 呼び出しが終わった後に再び起動を要求する

- **WHEN** 実行中だった呼び出しが終わったセッションに、再び起動が要求される
- **THEN** システムは受理し、AI の呼び出しを開始する

### Requirement: 承認後のセッションへの起動は受け付けない

システムは phase が `approved` のセッションへの起動要求を受理しない SHALL。承認後のセッションは提出を受け付けない（agent-api）ため、起動だけが通って提出が捨てられる実行を作らない。

#### Scenario: 承認後に起動を要求する

- **WHEN** phase が `approved` のセッションに起動が要求される
- **THEN** システムは受理せず、AI は起動されない

### Requirement: 前提が欠けている間は起動を受け付けない

システムは、AI の起動に必要な前提（startup-readiness）が揃っていないセッションへの起動要求を受理しない SHALL。要求元には受理しなかったことと、欠けている前提の内容が返る。前提が満たされた後は、同じセッションに再び起動を要求できる。

#### Scenario: 前提が欠けた状態で起動を要求する

- **WHEN** AI の起動設定が成立しない状態で起動が要求される
- **THEN** システムは受理せず欠けている前提を伝え、AI は起動されない

#### Scenario: 前提が満たされた後に起動を要求する

- **WHEN** 欠けていた前提が満たされた後で、同じセッションに起動が要求される
- **THEN** システムは受理し、AI の呼び出しを開始する
