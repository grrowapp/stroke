# api/send-back Specification

## Purpose

差し戻しを受理する endpoint を規定する。指摘の記録と、AI へ渡る内容を整えるところまでを担い、AI の起動を含まない。

## Requirements

### Requirement: 差し戻しを受理して記録する

システムは積まれた指摘を1回の差し戻しとして受け付ける endpoint を1つ公開し、差し戻しを受理したときは AI を起動せず、指摘を記録し、AI へ渡る内容を整えて完結する SHALL。

#### Scenario: 差し戻しが届く

- **WHEN** 1件以上の指摘を伴う差し戻しが届く
- **THEN** 指摘が記録され、受理が返る。AI の起動はこの endpoint では行われない

#### Scenario: 指摘が1件も無い差し戻しが届く

- **WHEN** 指摘が1件も無い差し戻しが届く
- **THEN** システムは受理せず、指摘が必要である旨を返す

#### Scenario: 存在しないセッション id で差し戻しが届く

- **WHEN** 存在しないセッション id に対する差し戻しが届く
- **THEN** システムは受理せず、存在しないことを伝え、何も記録しない

#### Scenario: 実行中のセッションに差し戻しが届く

- **WHEN** 実行中の呼び出しを持つセッションに差し戻しが届く
- **THEN** 差し戻しは受理され記録される。AI の起動はこの endpoint では行われない

#### Scenario: proposal がまだ無いセッションに差し戻しが届く

- **WHEN** phase が `stroking` で proposal がまだ無いセッションに差し戻しが届く
- **THEN** システムは受理せず、差し戻す対象の proposal が無いことを伝え、何も記録しない

#### Scenario: 承認後のセッションに差し戻しが届く

- **WHEN** phase が `approved` のセッションに差し戻しが届く
- **THEN** システムは受理せず、何も記録しない

### Requirement: 差し戻しは同じ内容を複数の形で AI へ渡るよう整える

システムは差し戻しを1つの形に畳まず、受理したとき次の4つを AI へ渡る形で用意する SHALL。

- **要約** — 全体への指摘と本文への指摘を並べた、人間可読のテキスト
- **構造化された指摘の一覧** — 指摘ごとに、種別（全体 / 本文）・引用・指摘本文を持つ
- **決定の記録** — 差し戻したという決定・指摘一覧・要約・時刻を1つにまとめたもの
- **手続き** — 差し戻されたこと、プロジェクトが作られていないこと、proposal を出し直すこと、および各指摘の列挙

手続きに書いてよいのは、差し戻し後に何が起きたか・何を出し直すかまでとする。

#### Scenario: 差し戻しを渡す

- **WHEN** 差し戻しが受理され、AI へ渡る内容が用意される
- **THEN** 要約・構造化された指摘の一覧・決定の記録・手続きの4つが揃って用意される

#### Scenario: 本文への指摘を渡す

- **WHEN** 本文の一部に紐づく指摘が含まれる
- **THEN** どの箇所を指しているかが分かる引用が、指摘本文と組で用意される

### Requirement: 差し戻しに対応方法を指示しない

システムは、AI へ渡るよう用意する内容に「全文を書き直す」「一部だけ直す」といった対応方法の指示を含めてはならない SHALL。対応方法は AI が指摘内容を読んで判断する。

#### Scenario: 対応方法を渡さない

- **WHEN** 差し戻しの内容が用意される
- **THEN** 用意される内容に、proposal をどう直すかの指示は含まれない
