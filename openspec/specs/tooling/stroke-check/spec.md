# tooling/stroke-check Specification

## Purpose
ストロークを実機で流し、着地するかを見る道具の振る舞いを定める。対向の枠組み（スキル・MCP ツール・ワークフロースキーマ）を差し替えたときに、人が意図して叩いて確かめるためのもの。

## Requirements

### Requirement: どこまで進めるかを選べる

道具は、proposal の着地で止めるか、承認して steering 工程まで進めるかを、実行のたびに選べる SHALL。

既定は proposal で止める SHALL。承認はプロジェクトを生成する不可逆な操作であり、意図せず走らせてはならない（MUST NOT）。

#### Scenario: 既定では proposal で止まる

- **GIVEN** 進め方を指定せずに道具を走らせる
- **WHEN** ストロークが proposal に着地する
- **THEN** そこで終わり、承認は行われず、プロジェクトは作られていない

#### Scenario: 指定すれば steering 工程まで進む

- **GIVEN** steering 工程まで進める指定をして道具を走らせる
- **WHEN** ストロークが proposal に着地する
- **THEN** 承認まで進み、steering 工程の実行も追われ、その結果が着地の判定に含まれる

### Requirement: 後始末をするかを選べる

道具は、その実行で作ったセッションを最後に片付けるかどうかを選べる SHALL。片付けの対象は、その実行で作ったものに限る（MUST NOT: 他の実行や利用者が作ったものに触れる）。

#### Scenario: 片付けを指定すると残らない

- **GIVEN** 後始末をする指定をして道具を走らせる
- **WHEN** 実行が終わる
- **THEN** その実行で作ったセッションは残っておらず、それ以外のセッションやプロジェクトは触られていない

#### Scenario: 承認まで進めた場合も片付く

- **GIVEN** steering 工程まで進め、かつ後始末をする指定で道具を走らせる
- **WHEN** 実行が終わる
- **THEN** 承認で作られたプロジェクトも片付いている（承認によって対象の名前が変わっても取り違えない）

### Requirement: 操作はブラウザから行う

道具は、アプリへの操作をブラウザの画面から行う SHALL。画面を介さずサーバーの endpoint を直接叩いて状態を進めてはならない（MUST NOT）。

画面の状態とサーバーの状態が食い違うと、着地しているのに画面が進まないなど、実際の利用では起きない失敗を作り込む。

**この規定は操作に掛かる。着地の判定に使う材料を画面に限る規定ではない。** 画面に出ない成果物は、成果物そのものを見て判定してよい SHALL。判定のために状態を進めてはならない（MUST NOT）という制限だけが残る。

#### Scenario: 直接叩いて回復しない

- **GIVEN** 起動の要求が拒否され、道具が回復を試みる
- **WHEN** 道具が回復の操作を行う
- **THEN** 操作は画面から行われ、画面が持つ状態と食い違わない

#### Scenario: 画面に出ない成果物を判定する

- **GIVEN** 承認後の工程が作る成果物が、その工程の実行中しか画面に出ない
- **WHEN** 道具が着地を判定する
- **THEN** 判定は書かれた成果物そのものから行われ、そのために状態は1つも進んでいない
