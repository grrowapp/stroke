# notification-toast Specification

## Purpose
通知が発生した瞬間に、利用者が別の画面を見ていても気づけるようにする。形は本家 spec-workflow-mcp のトーストと同じにして、知らせること以上の役割を持たせない。

## Requirements

### Requirement: 通知の発生時に画面内トーストを出す

システムは、通知が発生したときに、ブラウザの画面内にトーストを出さなければならない（SHALL）。トーストは画面の右上に固定し、複数同時に発生した場合は縦に積まなければならない（SHALL）。

システムは、OS の通知機構を使ってはならない（MUST NOT）。

#### Scenario: 通知が1件発生する

- **WHEN** 通知が1件発生する
- **THEN** 画面の右上にトーストが1つ出る

#### Scenario: 通知が複数同時に発生する

- **WHEN** 通知が同時に3件発生する
- **THEN** 3つのトーストが右上に縦に積まれる

#### Scenario: 通知画面以外を見ている

- **WHEN** 利用者がプロジェクト一覧や下層の画面を見ている状態で通知が発生する
- **THEN** その画面のままトーストが出る

### Requirement: トーストは5秒で自動的に消える

システムは、トーストを表示から5秒後に自動的に取り除かなければならない（SHALL）。利用者が閉じるボタンを押した場合は、5秒を待たずに取り除かなければならない（SHALL）。

#### Scenario: 何もしないで待つ

- **WHEN** トーストが出てから5秒が経過する
- **THEN** そのトーストは消えている

#### Scenario: 閉じるボタンを押す

- **WHEN** トーストの閉じるボタンを押す
- **THEN** そのトーストは即座に消える

### Requirement: トーストは1行のテキストだけを載せる

システムは、トーストの中身を1行のテキストに限らなければならない（SHALL）。件名と本文の区別、リンク、その他の操作を載せてはならない（MUST NOT）。

#### Scenario: トーストの中身を見る

- **WHEN** トーストが出る
- **THEN** 表示されているのは1行のテキストと閉じるボタンだけである

### Requirement: トーストは押しても何も起きない

システムは、トーストのテキスト部分を押しても何も起こしてはならない（MUST NOT）。対象を開く導線は通知の一覧に一本化する。

#### Scenario: トーストのテキストを押す

- **WHEN** トーストのテキスト部分を押す
- **THEN** 画面は遷移せず、対象も開かない

### Requirement: トーストは種別で色を分ける

システムは、トーストを info / success / warning / error の4種別に分け、種別ごとに色とアイコンを変えなければならない（SHALL）。通知4種の対応は次のとおりとする。

- タスク完了 → success
- タスク着手 → info
- 全件完了 → success
- 承認依頼の発生 → info

#### Scenario: タスク完了の通知が発生する

- **WHEN** 「タスク完了」の通知が発生する
- **THEN** success の色とアイコンのトーストが出る

#### Scenario: 承認依頼の通知が発生する

- **WHEN** 「承認依頼の発生」の通知が発生する
- **THEN** info の色とアイコンのトーストが出る

### Requirement: トーストはフォーカスを奪わない

システムは、トーストが出たときに、利用者の操作中のフォーカスを移してはならない（MUST NOT）。閉じるボタンにはキーボードで到達できなければならない（SHALL）。

#### Scenario: 入力中にトーストが出る

- **WHEN** 利用者が何かを操作している最中にトーストが出る
- **THEN** フォーカスは移動せず、操作が中断されない

#### Scenario: キーボードでトーストを閉じる

- **WHEN** キーボードでフォーカスを送る
- **THEN** トーストの閉じるボタンに到達でき、そこで閉じられる

### Requirement: 初回ロードで過去分をトーストにしない

システムは、画面を開いた時点で既に一覧に載っている通知を、トーストとして出し直してはならない（MUST NOT）。トーストは新たに発生した通知にのみ対応する。

#### Scenario: 通知がある状態で画面を開き直す

- **WHEN** 通知が5件ある状態でブラウザの画面を再読み込みする
- **THEN** トーストは1つも出ない
