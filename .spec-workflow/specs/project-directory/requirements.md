# specs/project-directory — delta

## ADDED Requirements

### Requirement: 作成と登録の入口を置き、可否判定は持たない

システムは、プロジェクト一覧画面に「作成」と「登録」の入口を置く SHALL。独立したメニュー項目として持ってはならない（MUST NOT）——一覧画面の操作として持つ。

「作成」は常に押せる。押したときの挙動（オーバーレイ上のモーダルでストロークを開く）は `stroke/frontier` が規定する。「登録」は非活性で置き、押せないことが見て分かる表示にする。

システムは、作成・登録の可否をサーバーに問い合わせる仕組みを持ってはならない（MUST NOT）。可否判定は行わない。

#### Scenario: 一覧を開く

- **WHEN** プロジェクト一覧画面を開く
- **THEN** 「作成」は活性、「登録」は非活性で表示され、可否のためのサーバー問い合わせは発生しない

#### Scenario: 作成を押す

- **WHEN** 「作成」を押す
- **THEN** ストロークがオーバーレイ上のモーダルとして開く（`stroke/frontier`）

## REMOVED Requirements

### Requirement: プロジェクトの登録と作成は非活性の入口として持つ

**Reason**: 作成の非活性の根拠だった「接続先の別プロジェクトに繋がっていない」が、統合で接続先が同一アプリ内のストロークになり成立しなくなった（ADR-0009 / ADR-0010）。
**Migration**: 「作成と登録の入口を置き、可否判定は持たない」が引き継ぐ。作成は常に活性、登録は非活性のまま。

### Requirement: 作成は接続先が無ければ行えず、その状態を画面に出す

**Reason**: 「接続先の別プロジェクト」という前提が統合で消滅し、可否判定は登録の分も含め仕組みごと廃止する決定になった（承認済み requirements 2026-08-25）。
**Migration**: 可否判定と理由コードは撤去する。作成の前提の欠けは、モーダル内で概要を投稿したときのエラーとして現れる（`stroke/frontier`）。
