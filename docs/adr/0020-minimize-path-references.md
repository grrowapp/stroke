# ADR 0020: 参照先へのパス参照は絶対に必要な最小限度にする

- **状態**: 採用（2026-09-04）

## 決定

**ファイルのパスで他の文書やコードを指す参照は、絶対に必要な最小限度に留める。** 正の所在を示す参照は 1 箇所に集約し、他の場所からは概念の名前（「構造の規範」「契約」）で指す。

1. **CLAUDE.md は docs の一覧を持たない。** ディレクトリの役割だけを書き、中のファイル名・分類の表を置かない。一覧は各ディレクトリを直接見れば得られる
2. **運用の文書（`docs/agents/`）は、正の所在を 1 箇所だけパスで示す。** 同じ文書の他の箇所や例文は、その 1 箇所を指す
3. **コードのコメントに docs のパスを書かない。** コメントはコードの事情だけを書く。docs との対応は docs の側が持つ
4. **docs の中の相互参照は、同じディレクトリのファイル名か、正の所在の 1 箇所に留める。** 同じ内容を複数の箇所からパスで指さない

## 理由

docs のファイルを動かすたびに、それを指すパスが散らばった先を全て直す作業が生じる。2026-09-04 に `docs/specs/core/` の構造系 4 本を `docs/specs/structure/` へ移した際、旧パスを指す箇所が CLAUDE.md・`docs/agents/`・`nuxt.config.ts` のコメント・`docs/specs/plan/` と `architecture/` の 7 本・ADR 2 本・`openspec/specs/` 2 本・active な change 8 件の artifact に残った。

参照が多いほど文書は動かしにくくなり、動かせない文書は現状に追随できなくなる。参照の数を減らせば、動かすときに直す場所は正の所在の 1 箇所で済む。

## 参照の方向との関係

参照の方向（`docs/agents/issue-tracker.md`「参照の方向」）は**どこからどこへ張ってよいか**を定める。この決定は**張ってよい範囲の中で、どれだけ張るか**を定める。両方を満たすこと。
