# ADR 0024: 根拠薄弱な独断の限定制約を設置してはならない

- **状態**: 採用（2026-09-09）

## 決定

**エージェントは、根拠を示さずに自分の判断で限定の制約（「〜だけ」「〜には置かない」「〜のみが正」）を規定に書き込んではならない。絶対厳守。**

1. **理由の無い限定を無駄に入れない。** 限定は自由度を削る。削る理由を言えない限定は、規定の側に負債として残る
2. **限定にメリットがあると判断したときは、先にユーザーへ理由を提示し、承認を得てから書く。** 根拠がはっきりしていて、限定した方がより効果的または安全であるなど、限定性そのものに利点がある場合に限る
3. **提示するのは、何を限定するか・なぜ限定が要るか・限定しないと何が起きるか。** この3つを言えないなら限定しない
4. **既に書かれた根拠の無い限定を見つけた者は、外すか、ユーザーに諮る。** 黙って残さない
5. **適用範囲は規定を書くすべての場面。** docs・ADR・`CLAUDE.md`・`docs/agents/`・openspec の artifact と specs・steering・コードのコメント

## 理由

2026-09-09、当て字の禁止例の一覧について、エージェントが「一覧の正は ADR だけ。`CLAUDE.md` には一覧を置かない」という限定を、ユーザーの指示に無いまま ADR と運用資料に書き込んだ。ユーザーからの指摘は「一覧の正を限定する理由はない」であった。

限定は一見きれいに見えるが、根拠が無ければ後から読む者はその限定を守るべきか外すべきか判断できない。守れば不要な不便が残り、外せば規定を破った形になる。どちらに転んでも損失であり、限定を書いた時点でユーザーに諮っていれば生じなかった。

## 判定の仕方

限定を書こうとしたら、次を自問する。

1. この限定を外すと、具体的に何が壊れるか。言えなければ書かない
2. 言えるなら、それをユーザーへ提示し、承認を待つ
3. 承認を得たら、限定と一緒にその理由を規定に書く
