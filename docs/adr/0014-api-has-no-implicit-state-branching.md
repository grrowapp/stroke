# ADR-0014: API は暗黙の状態分岐を持たない

- **状態**: 採用
- **日付**: 2026-08-26

## 決定

steering の `tech.md`（`## Technical Requirements & Constraints` の `### API Design Principles`）に
次の1項目を置いた。これが規約の本体である。規約は1つで、下の2つはその範囲と例外を示す補足である。

> - **API は暗黙の状態分岐を持たない**: 呼び出し側が渡していない内部状態を見て振る舞いを変えない。契約（path と引数）から読み取れない挙動を持たせない
>   - 責務の不成立（存在しない id・スキーマ違反）と、引数で制御される分岐は契約に現れるので対象外
>   - 例外はユーザーの指示か事前の承認が要る。判断は proposal か grilling の段階で行う

以下は本文と補足2つの解説である。短縮された文面から元の意図を復元するために置く。

### 「呼び出し側が渡していない内部状態を見て振る舞いを変えない」

**暗黙**とは、契約——path と引数——に現れないという意味である。呼び出し側が渡していない値を
API が内部で読み、それによって結果を変えると、同じ呼び出しが状況によって通ったり弾かれたりする。
呼び出し側から見ると理由が見えない。説明されないと分からない挙動は持たせない。

判定そのものを禁じているのではない。**判定の材料が外から見えるかどうか**が分かれ目である。

### 「責務の不成立と、引数で制御される分岐は契約に現れるので対象外」

反しない形が2つある。

1. **責務を果たせない場合の判定** — 受け取った引数に対してその責務が成立しないケース。
   「存在しないセッション id は受理しない」「本文が空なら受理しない」はこれにあたる。
   id も本文も引数として受け取っており、それに応えられないという話なので暗黙ではない
2. **引数で制御される判定** — 判定の受け口が endpoint の引数として外に出ているなら、
   その判定は API の責務である。起動要求が `cwd` を引数で受け取るような形

どちらも、呼び出し側が渡したものに対する応答として説明が閉じる。

### 「例外はユーザーの指示か事前の承認が要る（判断は proposal か grilling の段階）」

エッジケースで暗黙にせざるを得ない場面はありうる。ただし採ってよいのは、**ユーザーの指示があるか、
事前に協議して承認を得た場合だけ**である。判断は proposal か grilling の段階で行う。
実装や spec を書く段になってから理由を添えて押し通す形にしない——spec に書けば通る、
という抜け道を作らないためである。

## 背景

`agent-api` の「承認後のセッションは提出を受け付けない」がこの原則に反していた。
エージェントは `phase` を渡していないのに、API が `state.json` の `phase` を見て、
同じ提出を通したり弾いたりしていた。呼び出し側から見ると、契約に現れない理由で結果が変わる。

同じ口を画面・エージェント・サーバー内部の複数が使う構成になっており
（steering 起動を含む。承認後の steering 自動起動は
[`docs/specs/plan/portal-stroke-exit.md`](../specs/plan/portal-stroke-exit.md) の
「承認ボタン → 一覧へ戻る」節が確定を持つ）、
暗黙の分岐はそのうちのどれか1つの都合が他へ漏れる形になっていた。

## 根拠

- 契約から挙動が読めることが、**複数の呼び出し側が同じ口を使う**ための前提である。
  暗黙の分岐があると、呼び出し側ごとに「この状況では通る/通らない」を個別に覚える必要が出る
- 暗黙挙動は spec にもテストにも現れにくい。引数として外に出ていれば、
  その引数の Scenario として自然に書ける
- 状態の判定を API から追い出すことで、状態を持つ側（画面・呼び出し元）に判断が集まる。
  どこで何が決まるかが1箇所になる

## 影響

- `api/stroke/question` と `api/stroke/proposal` の「承認後のセッションは提出を受け付けない」を削除する
  （change `connect-portal-and-strokes`）
- 今後 API の spec を書くとき、状態による分岐を入れるなら、引数として外に出すか、
  責務の不成立として説明できる形にする
- 規約の本体は steering の `tech.md` にあり、この ADR はその解説として従属する。
  文面を変えるときは両方を揃える
