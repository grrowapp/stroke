# ADR 0023: instruction・template で規定されていない短縮形の使用を絶対に禁じる

- **状態**: 採用（2026-09-09）

## 決定

**instruction（`CLAUDE.md`・`docs/agents/`・`CONTEXT.md`・スキルやエージェントのプロンプト定義）または template（openspec のスキーマ・artifact の雛形・docs の書式）で規定されていない短縮形は、いかなる場所でも使わない。絶対厳守。**

1. **短縮してよいのは、規定がその短縮形を定めているものだけ。** 規定が定めた記法（契約の `U15`・`W1`、change-id、ラベルの値、`tasks.md` の番号）はその記法どおりに書く
2. **自分で短縮形を作らない。** 語の一部を切る（「用語の表記」→「用語表記」）、頭字語を作る、change-id・ファイル名・節名・コマンド名・識別子を省略する、いずれも禁じる
3. **規定の名前は規定の形で書く。** ファイルはパスまたはファイル名、節は節名そのまま、change は change-id そのまま、ブランチ・worktree はその名前そのまま
4. **短縮形を見つけた者は、触った箇所から規定の形へ戻す。** 新しく書くものには一切持ち込まない
5. **適用範囲は書くものすべて。** docs・ADR・`openspec/` の artifact と ticket・steering・コードのコメント・コミットメッセージ・PR の本文・ユーザーへの応答・他セッションへの指示

## 理由

規定に無い短縮形は、書いた本人にしか元の形へ戻せない。読み手は推測で補うことになり、推測が外れれば別のものを指す。同じ対象に正式な形と短縮形が並ぶと grep で追えず、docs・specs・コード・ticket の対応が取れなくなる。

規定が短縮形を定めているとき、その短縮形は辞書に載った語である。辞書に無い短縮形を作る利益は無く、損失だけがある。

## 判定の仕方

1. その短縮形を定めている instruction または template を指せるか。指せればその形で書く
2. 指せなければ、規定の正式な形で書く
3. 正式な形が長くて不便でも、短縮形を作らない。不便なら規定の側に短縮形を提案する

## 参照

- ドメイン用語の定義は `CONTEXT.md`
