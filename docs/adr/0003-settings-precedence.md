# 設定値はコードの既定値に優先する

> **この ADR は [0004](0004-settings-reference-is-authoritative.md) に取って代わられた。**
> `NUXT_*` の環境変数は、置き場の2件（`NUXT_SESSIONS_ROOT` / `NUXT_PROJECTS_ROOT`）を除いて全廃した。「既定値をモジュールに置き、環境変数があればそれを優先する」という形は、もう設定の一般則ではない。以下は、そう決めていた時期の記録である。**判断の根拠に使わない。**

実行時に与えられた設定値が、コードに書かれた既定値に**優先する**。コードの既定値は「何も与えられなかったときに使う値」であって、正しい値ではない。

形は1つに固める。**既定値をその値を使うモジュールに `DEFAULT_*` として置き、`NUXT_*` の環境変数があればそれを優先する `resolve*()` を並べる。**

```ts
export const DEFAULT_SESSIONS_ROOT = '/var/lib/stroke-board/sessions'

export function resolveSessionsRoot(): string {
  return process.env.NUXT_SESSIONS_ROOT?.trim() || DEFAULT_SESSIONS_ROOT
}
```

値を読む側は、使う場所で `resolve*()` を呼ぶ。解決は呼び出しのたびに行い、**値を持ち回るために関数の引数を増やさない。**

一覧は `docs/settings-reference.md`、差し替えのテンプレートは `.env.example` が持つ。

## Considered Options

### 設定だけを集めた層を新設する

`server/utils/config.ts` のような1モジュールに全ての設定を集める案。読み口が1箇所に閉じる。

退けたのは、**既定値がその値を使うコードから離れる**ためである。閾値の意味も、なぜその値なのかも、使う場所にしか無い。集めると、値を変えるときに2つのファイルを行き来することになり、検証だけが値から離れる。

### 全て `runtimeConfig` に載せる

Nuxt の機構に一本化する案。

退けたのは、**読み手が Nitro の外にもいる**ためである。`yarn session`（CLI）は tsx で走り、`useRuntimeConfig()` を使えない。加えて `nuxt.config.ts` は Nuxt のエイリアス（`#shared/*`）が存在しない時点で評価されるため、エイリアスを import するモジュールから既定値を読めない（`error TS2307` で実測）。

`runtimeConfig` に載せるのは、**Nitro の中からしか読まれない値だけ**とする。現状では `claude -p` の起動設定（ADR 0001）がこれに当たる。その既定値も、単独モジュールに置けるものは `nuxt.config.ts` がそこから import する（同じ値を2箇所から決めない）。

### 引数で持ち回る

解決した値を呼び出し側から引数で渡す案。

退けたのは、**設定の話が呼び出し規約の話に化ける**ためである。値の出どころを変えるだけの変更が、誰が誰を呼ぶかの変更になる。

## Consequences

- **不正な値は既定へ倒れる。`resolve*()` は投げない。** 倒れたことは起動時チェック（`server/plugins/00.startup-checks.ts`）が示す。検査する関数は値の定義と同じモジュールに置き、起動時チェックはそれを集めるだけにする
- **形をなしていない値のまま走り出さない。** 環境変数は文字列で来るため、数値・絶対パス・正規表現・シグナル名は起動の時点で検査し、不正なら全件を並べて止める
- **実行経路が違っても同じ値に解決される。** endpoint も CLI も同じ `resolve*()` を通るため、サーバが作ったセッションを CLI が同じ置き場で見つけられる
- **ビルド時に決まる設定はこの規定の外にある。** ビルドが消費して出力を作るもの（`modules` / `css` / `devtools` / `ignore` / `nitro.experimental.websocket`）には優先しようがない。環境変数を与えても動作は変わらず、変えるにはアプリを作り直す。どちらなのかは `nuxt.config.ts` の見出しで分かれている
- **設定にしてはならないものがある。** 置き場の外へ出られる形を許すもの（`..` を含む名前を弾く判定、セッション uuid の正規表現）と、画面とサーバの契約（`shared/stroke.ts` の語彙）は外に出さない。**優先の対象にしない**という判断であり、未対応ではない
- 子プロセスへ渡す環境変数の名前（既定 `STROKE_BASEURL`）は `NUXT_` の規則の外にある。`NUXT_` は「こちらが読む環境変数」に対する規則であって、渡す名前はその外である
