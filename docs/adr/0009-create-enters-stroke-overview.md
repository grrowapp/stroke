# ADR-0009: プロジェクト一覧の「作成」はストロークの開始である

- **状態**: 採用（2026-08-25 改訂: 入場の形をモーダルに変更）
- **日付**: 2026-08-25

## 決定

プロジェクト一覧の「作成」を押すと、**全面オーバーレイのモーダル**が開き、その中でストローク全体
（概要入力 → AI との往復 → 承認）を行う。モーダルは画面全体を覆い、一覧は見えない。閉じる操作は設けない。
**URL は変わってよい**（実装はページ遷移でよく、リロードで同じ途中画面に復帰できる形を採る）。
作成の実処理は同一アプリ内のストローク機能が担い、「作成」のための処理を新設しない。

> 改訂の経緯（2026-08-25）: 当初は「概要入力画面へのページ遷移」だったが、仕様書レビューの
> 差し戻しで全面オーバーレイのモーダルに変更。その実体は「見た目が全面モーダル」であり、
> URL が `/projects` から進むこと（ページ遷移での実装）はユーザー確認済み。

## 背景

統合前の `project-directory` spec は「作成の実処理は**接続先の別プロジェクト**が担い、stroke-board が持つのは
入口だけ」という前提で書かれ、入口は非活性が SHALL だった。統合（merge `9cef630`）でその「別プロジェクト」は
同一プロセス内の `/strokes` として実在するようになり、「接続が無い」という非活性の理由は成立しなくなった。

## 根拠

- `stroke-session` が「概要の投稿からセッションを1つ開始する」を規定し、その画面（`/strokes`）と
  API（`POST /api/strokes`）が実装済みで動く。作成の意味を新しく発明せず、既存の入口へ接ぐだけで流れが繋がる
- `/strokes` は現状どのナビゲーションからも辿れない。作成ボタンが、ポータルからストロークへ渡る計画上唯一の橋である

## 影響

- `project-directory` の2要件の改定が要る:
  「プロジェクトの登録と作成は非活性の入口として持つ」（作成側の非活性の解除）と
  「作成は接続先が無ければ行えず、その状態を画面に出す」（「接続先」概念の書き直し）。
  差分は change `connect-portal-and-strokes` の specs として書く
- 「登録」はこの決定の対象外。非活性のまま（理由 `meaning-undecided` は変わらない）
- 作成が押せる条件（`actions.create.available` の導出元）は未決。別の ADR で決める
