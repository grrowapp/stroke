# ADR 0025: 画面遷移と操作アクションを自己判断で変更してはならない

- **状態**: 採用（2026-09-10）

## 決定

**エージェントは、画面遷移と操作アクションを、ユーザーの指示なしに自分の判断で足す・変える・消すことをしてはならない。絶対厳守。**

対象は、人が見る場所と、人が押した結果が変わるものすべてである。

1. **URL の入場先。** ある URL を開いたときに何が出るか。リダイレクト・自動遷移・既定の着地先の追加と変更を含む
2. **遷移そのもの。** `navigateTo` / `router.push` / `router.replace` / `redirect` / route rule / middleware / route 定義の追加・変更・削除
3. **操作アクションの結果。** ボタン・リンク・行・タブを押したときに何が起きるか。飛び先、開くもの、閉じるもの、実行されるもの
4. **操作の可否。** 活性・非活性、押せる条件、フォーカスを受けるかどうか
5. **画面の責務範囲。** どの画面が何を担うか、どこからどこへ渡すか

### 変更したいときの手順

1. **先にユーザーへ提示する。** 今どうなっているか、どう変えたいか、なぜ変えるか、変えないと何が起きるか
2. **承認を待つ。** 承認の前に実装へ入らない
3. **承認を得たら、遷移の設計を docs へ書き出してから実装する。** 正は [`docs/specs/architecture/screen-flow.md`](../specs/architecture/screen-flow.md)
4. **リファクタリング・バグ修正・「ついでに」の範囲でも同じ。** 別の作業の副産物として遷移を動かさない

### 既に入っているものを見つけたとき

黙って残さず、黙って直さない。**ユーザーへ報告し、指示を仰ぐ。**

## 理由

2026-09-10、`/` を開くと `/projects` へ自動で遷移する実装が、ユーザーの指示も承認も無いまま入っていた。ユーザーからの指摘は「画面遷移や操作アクションを勝手な自己判断で変更するのは絶対禁止」であった。

画面遷移はプロダクトの外形そのものである。コードの内部構造と違い、変えれば使う人の手が直接空を切る。しかも遷移は1行で足せてしまうため、「動線を良くしたつもり」で入り込みやすく、入った後は仕様と実装のどちらが正なのか誰にも分からなくなる。

`/` が何を出すかは、この製品が何から始まるかの宣言であり、エージェントが良かれと判断してよい範囲に無い。

## 判定の仕方

書こうとしている差分が次のどれかに触るなら、手を止めてユーザーに諮る。

1. URL を開いたときの着地先が変わるか
2. 押した結果の飛び先・起きることが変わるか
3. 押せる／押せないが変わるか
4. 画面の担当範囲が動くか

1つでも当てはまり、かつユーザーの指示にその変更が含まれていないなら、書かない。
