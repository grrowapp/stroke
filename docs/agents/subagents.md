# サブエージェントの使い分け

コンテキストを節約したいときに使うのは **fresh なエージェント**。`fork` は親の文脈を丸ごと継承するので節約にならない。

節約したいのは探索や作業履歴といった中間コンテキストであって、結論ではない。fresh なエージェントなら過程が向こうに残り、こちらは結論だけ受け取れる。

## 投げてよいもの

- リポジトリ横断の全数洗い出し（多数のファイルを読む調査）
- 結論だけあればよい探索

## 投げる前に済ませること

実装を渡すなら、文脈を artifact（`proposal` / `design` / `tasks`）に書き切ってから渡す。artifact が完結していれば、別セッションでも fresh なエージェントでも同じように進む。書き切れていない文脈は渡した瞬間に失われる。

## 並列に走らせないもの

同じファイルに触れる change どうし。worktree で分離しても、戻すときにコンフリクトするだけで得がない。依存の順に直列で進める。

## 進め方の原則

締めで見えている状態を失わないことを最優先にする。作業を進める前に、失われて困る知見を先に永続化する。置き場は `docs/` — セッションが変わっても辿れる場所に置く。
