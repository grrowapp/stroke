# 承認 — `POST /api/sessions/:id/approve`

**承認**（`CONTEXT.md`）を受理し、セッションを**プロジェクト**へ昇格させる。共通の約束は [contract.md](../contract.md)。

- input: `{ projectName: string }`
- output: 本文なし（204）

## 振る舞い

- 承認は**セッションディレクトリを `<projectName>` へ改名するだけ**である。新しいディレクトリを作らず、ファイルも動かさない
- 前提: `docs/proposal.md` が在ること。書くのは A7 で、残せたときだけ受理を成立させるので、`proposed` まで進んだセッションでは通常在る。外から消された場合は 409（proposal が見つからない）で止まる。**承認は proposal を書かず、既にあるものに触れない**
- 順序は「衝突確認 → 改名 → phase 書き換え」で、phase の書き込みが失敗したら改名を戻す。`approved` かつ未改名の宙吊りは作らない
- 改名の成功直後に steering の claude を起こす（cwd＝生成先。完了は待たない・[ADR 0011](../../../adr/0011-steering-stage-follows-approval.md)）。昇格に失敗したときは起こさない

## 実行中は受理しない

**対象で AI が走っている間は 409 busy を返し、何も変えない。** 確認から改名の完了までの間、その対象への新しい起動も受け付けない。

改名は inode を保つので、走っている claude の作業場所は改名先へ追随して生き続ける。その状態で放置すると、その claude 以後の操作は宛先を失う。**待たずに断るのは、承認が人の操作で、数分待たせられないためである。** 呼び手は AI の応答が終わってから押し直す。

## エラー

| status | 状況 |
|---|---|
| 400 | 形式不正 |
| 404 | セッションが無い |
| 409 | name-conflict |
| 409 | phase（`proposed` のみ受理） |
| 409 | proposal が無い |
| 409 | busy（対象で AI が走っている） |
| 500 | 改名失敗 |
