# 昇格 — `POST /api/sessions/:id/promote`

判断のあるセッションを**プロジェクト**へ昇格させる。共通の約束は [contract.md](../contract.md)。

- input: 本文なし（**名前は判断が持つ。** 引数で受けると判断と違う名前で昇格できてしまう）
- output: 本文なし（204）

## 振る舞い

- 判断を下すことも、起動を要求することも受け持たない。記録された判断が無ければ 409 phase —— **承認が昇格の唯一の引き金である**関係はここで守られる
- 昇格は**セッションディレクトリを判断の名前へ改名するだけ**である。順序は「衝突確認 → 改名 → `phase` を書く」で、書き込みが失敗したら改名を戻す。どの時点で失敗しても、セッションは元の名前・`proposed`・判断そのままで残り、同じ判断のまま昇格だけをやり直せる
- name-conflict のときは判断を取り下げて 409 name-conflict を返す（画面は衝突として出し、別名で判断からやり直す）
- 昇格の完了時点で対象の `invocation` は `failed` になる（「起こし直す対象」の印）。画面の起動要求が届けばすぐ実行に変わり、届かなければ巡回が拾って steering を起こす

## 実行中は受理しない

**対象で AI が走っている間は 409 busy を返し、何も変えない。** 確認から改名の完了までの間、その対象への新しい起動も受け付けない。

改名は inode を保つので、走っている claude の作業場所は改名先へ追随して生き続ける。一方その claude が名乗る id は改名前のままなので、以後の操作（問いの送信・文書の提出・実行の記録）はすべて対象を見つけられずに落ち、成果はどこにも残らない。

**占有は改名と `phase` の書き込みが終わった直後に解く。** 昇格の成功を見た側は続けて起動を要求し、それは同じ作業場所を取りに来る——解放を後にすると、自分の占有で 409 になる。

## エラー

| status | 状況 |
|---|---|
| 404 | セッションが無い |
| 409 | phase（判断なし・昇格済み） |
| 409 | name-conflict |
| 409 | busy（対象で AI が走っている） |
| 500 | 改名失敗 |
