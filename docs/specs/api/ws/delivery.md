# WS 配信

サーバ → 画面の一方向。**画面からは何も送らない。** 共通の約束は [contract.md](../contract.md)。

| # | パス | 相手 | 内容 |
|---|---|---|---|
| W1 | `/api/sessions/:id/ws/question` | セッション1件を見ている画面 | 問いを配信する |
| W2 | `/api/sessions/:id/ws/proposal` | セッション1件を見ている画面 | proposal を配信する |
| WB | `/ws` | 上層を開いているブラウザ | 上層へのサーバー発イベントを配信する |

## 規約

- **サーバ → 画面の一方向**
- **接続した瞬間に現在分を流す**
- **出来事の種類が増えても endpoint を増やさない。** 増やしてよいのは運ぶ相手が違うときだけで、同じ相手へ届く出来事が2種類あることを理由に2本にしない

## WB が運ぶ種別（`BoardMessage`）

| 種別 | いつ | 内容 |
|---|---|---|
| `snapshot` | 接続の瞬間 | 通知の一覧・本家との接続状態 |
| `notification` | 本家由来の通知が起きたとき | 通知1件 |
| `upstream-connection` | 本家との接続が変わったとき | 繋がっているか |
| `project-creation` | 昇格・生成の完了・生成の失敗 | プロジェクト名と `done` / `in-progress` / `failed` |

WB は行の中身を運ばない。プロジェクト一覧の正は `GET /api/projects` の1つのままで、WB は「取り直せ」の合図と、完了を祝う引き金である。

`snapshot` は現在分であって、出来事ではない。受けた画面は一覧を取り直す（切れていた間の変化がそこで揃う）が、トーストも祝いも出さない。
