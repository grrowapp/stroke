# 5.4 検証報告: 既存経路の無変更確認（ロールバック比較）

## 目的

`--mcp-config` の追加が既存のストローク往復（curl スキル経由）を壊していないか。
ロールバック手段は「mcp-config の追加分を外すだけ」（proposal/design）であるため、
mcp-config の有無で挙動が変わらないことを確認する。

## 方法

同一セッション（`f3646be3-7aef-421e-9287-9373ccbffa46`、検証セッションK）に対し、
本番 invoke.ts と同一の `--allowedTools` / `cwd` / prompt を用い、
**`--mcp-config` だけを外した**状態（= ロールバック後相当）で `claude -p --resume` を
外部実行した。

```
claude --setting-sources project --model sonnet \
  --add-dir .../base4 --add-dir .../base4/assets \
  --allowedTools "Skill" "Bash(openspec *)" "Bash(curl -X POST *)" "Bash(jq -n *)" "Bash(printenv *)" "Read" "Edit" \
  --disallowedTools "Bash(cd *)" \
  -p --resume f3646be3-7aef-421e-9287-9373ccbffa46 -- "続きを進めろ。状況は取得スキルで確認してから判断しろ。"
```

（`--mcp-config` を渡していない点だけが、本番の実行コマンドとの差分）

## 結果（エージェントの報告そのまま）

> `get-overview`スキルの実行が `.claude/settings.json` の permission 設定でブロックされている。
>
> **状況**: deny に `Bash(curl *)` があり、allow には POST `/api/strokes` 専用のパターンのみ許可されている。get-overview は GET `.../overview` を叩くため、この許可パターンにマッチせず拒否される。おそらく get-strokes / get-send-back など他の「取得」スキルも同様に拒否される可能性が高い。

## 結論

- `--mcp-config` の**有無に関わらず**、既存スキル（get-overview 等）は同一の理由
  （`.claude/settings.json` の `Bash(curl *)` deny）で同一に失敗する。
- したがって、現在観測されている「プロセスは成功したが提出が届かない」障害は
  **provide-operations-via-mcp の変更（`--mcp-config` の追加）に起因しない**。
  変更前の状態（mcp-config 無し）でも同じ障害が再現するため、本 change による
  既存経路への回帰は無いと判断する。
- 障害の実体は `.claude/settings.json`（本 change の対象外・別途ユーザー対応が必要）。
