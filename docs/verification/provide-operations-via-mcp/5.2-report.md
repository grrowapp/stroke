# 5.2 検証報告: 未認可 token でのツール呼び出し拒否

## 検証方法

稼働中の dev サーバー（`http://127.0.0.1:3399`）に対し、`claude` を外部プロセスとして
2パターンで起動し、`get-overview` ツールを1回呼び出させ、結果をエージェント自身に
報告させた。

### パターンA: 未発行（無効）token

```
claude --mcp-config /tmp/mcp-test-invalid-token.json --strict-mcp-config \
  --allowedTools "mcp__stroke-board__get-overview" \
  -p "stroke-board の MCP サーバーの get-overview ツールを1回呼び出してください。
      成功したかエラーだったか、エラーならそのメッセージ・ステータスコードを
      正確に日本語で報告してください。それ以外は何もしないでください。"
```

mcp-config の該当箇所:
```json
{
  "mcpServers": {
    "stroke-board": {
      "type": "http",
      "url": "http://127.0.0.1:3399/mcp",
      "headers": { "x-stroke-token": "invalid-test-token-not-registered" }
    }
  }
}
```

**エージェントの報告（そのまま）:**
```
エラーでした。

- ステータスコード: 401
- メッセージ: 無効な token。
```

### パターンB: token ヘッダそのものが無い

mcp-config の headers を省略した状態で同様に実行。

**エージェントの報告（そのまま）:**
```
get-overview を1回呼び出した結果、エラーでした。

- ステータスコード: 401
- メッセージ: `x-stroke-token ヘッダが無い。`
```

## 結論

- 未発行 token・token ヘッダ欠落のいずれも `401` で拒否され、接続表の実装
  （`server/utils/mcp/connection-table.ts` の `resolveConnection`）が
  specs `server/session-management`「有効な token の無い呼び出しを拒否する」の
  Scenario 2件（token を持たない接続の拒否／発行されていない token の拒否）を
  満たすことを実機で確認した。
- 既定値で補う・エラーを握りつぶす等の挙動は見られなかった。
